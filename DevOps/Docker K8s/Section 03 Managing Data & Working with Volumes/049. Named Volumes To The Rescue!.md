# Named Volumes Giải Cứu: Lưu Trữ Dữ Liệu Vĩnh Viễn Trong Docker

## Giới thiệu

Anonymous volumes trong Dockerfile không đủ để giải quyết vấn đề dữ liệu. Đó là lý do Docker cung cấp **Named Volumes** — một cơ chế mạnh mẽ hơn nhiều.

## Anonymous Volume vs Named Volume

| Đặc điểm | Anonymous Volume | Named Volume |
|-----------|-----------------|--------------|
| Tên | Tự động ngẫu nhiên | Bạn đặt tên |
| Tồn tại sau khi container xóa | Không (nếu dùng --rm) | Có |
| Chia sẻ giữa nhiều container | Không | Có |
| Quản lý | Rất khó | Dễ dàng |

## Sử dụng Named Volume

Không thể tạo named volume trong Dockerfile. Bạn phải tạo khi chạy container:

```bash
docker run -d -p 3000:80 --rm \
  -v feedback:/app/feedback \
  --name feedback-app \
  feedback-node:volumes
```

Trong đó:
- `-v feedback:/app/feedback`: Tạo volume tên "feedback" và mount vào `/app/feedback`
- Phần trước dấu `:` là tên volume (bạn tự đặt)
- Phần sau dấu `:` là đường dẫn trong container

## Kết quả

Bây giờ, khi submit feedback và sau đó xóa container:

```bash
docker stop feedback-app
docker volume ls  # Vẫn thấy volume "feedback"
```

Volume vẫn tồn tại! Và khi chạy container mới với cùng tên volume:

```bash
docker run -d -p 3000:80 --rm \
  -v feedback:/app/feedback \
  --name feedback-app \
  feedback-node:volumes
```

Dữ liệu feedback **vẫn nguyên vẹn**. Đây là sức mạnh của Named Volumes.

## Khi nào nên dùng Named Volume?

Named Volume lý tưởng cho:
- **Dữ liệu cơ sở数据库**: PostgreSQL, MongoDB, MySQL
- **File uploads**: Ảnh, tài liệu người dùng upload
- **Dữ liệu ứng dụng cần tồn tại vĩnh viễn**: Bất kỳ thứ gì không được phép mất

## Tóm tắt

Named Volume là giải pháp hoàn hảo cho dữ liệu cần persist. Bạn không cần biết Docker lưu file ở đâu trên host — Docker tự quản lý. Bạn chỉ cần đặt tên và mount vào đường dẫn trong container.
