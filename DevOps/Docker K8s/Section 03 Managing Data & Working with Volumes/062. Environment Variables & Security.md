# Bảo Mật Biến Môi Trường: Những Điều Cần Biết

## Giới thiệu

Environment variables rất tiện lợi, nhưng cũng tiềm ẩn rủi ro bảo mật nếu sử dụng sai cách. Bài viết này giải thích cách bảo vệ secrets trong Docker.

## Vấn đề bảo mật với ENV trong Dockerfile

```dockerfile
# NGUY HIỂM: Secrets bị "bake" vào image!
ENV DATABASE_URL=postgres://user:password@localhost/db
ENV API_KEY=sk-1234567890
```

Khi đặt secrets trực tiếp trong Dockerfile:
- Secrets **vẫn tồn tại** trong image history
- Bất kỳ ai có quyền pull image đều có thể xem secrets
- Dùng `docker history <image>` để lộ secrets

## Giải pháp an toàn

**1. Sử dụng file .env riêng biệt:**

```bash
# File .env (KHÔNG commit vào git)
DATABASE_URL=postgres://user:password@localhost/db
API_KEY=sk-1234567890
```

```bash
docker run --env-file .env my-app
```

**2. Truyền biến khi chạy container:**

```bash
docker run -e DATABASE_URL="postgres://..." my-app
```

**3. Docker secrets (cho Docker Swarm):**

```bash
docker secret create db_password password.txt
```

## Quy tắc vàng

1. **KHÔNG BAO GIỜ** đặt secrets trong Dockerfile
2. **Luôn thêm .env vào .dockerignore** để tránh copy nhầm vào image
3. **Không commit file .env** vào version control
4. **Sử dụng Docker secrets** trong production environments
5. **Quay轮 secrets định kỳ** để giảm thiểu rủi ro

## Checklist bảo mật

```
# Trong .dockerignore
.env
.env.*
*.pem
*.key
secrets/
```

```bash
# Kiểm tra image có chứa secrets không
docker run --rm <image> find / -name '.env*' -o -name '*.pem' 2>/dev/null
```

Bảo mật là trách nhiệm của mỗi developer. Hãy luôn cảnh giác với secrets trong Docker!
