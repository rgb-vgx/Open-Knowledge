# Vấn Đề Cốt Lõi: Tại Sao Dữ Liệu Bị Mất Khi Container Xóa?

## Giới thiệu

Chúng ta đã có ứng dụng chạy tốt trong Docker. Nhưng có một vấn đề lớn: **dữ liệu trong container sẽ biến mất khi container bị xóa**. Bài viết này sẽ phân tích sâu vào nguyên nhân và giải thích tại sao đây lại là vấn đề nghiêm trọng.

## Mô tả vấn đề

Hãy thử tình huống sau:
1. Chạy container và submit feedback "awesome"
2. Truy cập `/feedback/awesome.txt` — file tồn tại
3. Dừng container (`docker stop feedback-app`)
4. Khởi động lại container mới

**Kết quả**: File `awesome.txt` đã biến mất!

## Nguyên nhân gốc rễ

Docker sử dụng cơ chế **layered filesystem** (hệ thống file lớp):

- **Image layer**: Read-only, chứa source code và dependencies
- **Container layer**: Read-write layer được thêm khi container chạy

Khi container bị xóa, **toàn bộ container layer bị xóa theo**. Vì file `awesome.txt` nằm trong container layer (không phải trong image), nên nó sẽ biến mất.

Đây là **cốt lõi của thiết kế Docker**: nhiều container chạy từ cùng một image phải **hoàn toàn cô lập** với nhau. Mỗi container có "bản sao" riêng của file system mà không ảnh hưởng đến image gốc.

## Tại sao đây là vấn đề?

Trong thực tế, chúng ta **thường xuyên xóa và tạo container mới** — đặc biệt khi triển khai phiên bản mới của ứng dụng. Nếu dữ liệu mất theo mỗi lần xóa container, mọi tài khoản người dùng, dữ liệu kinh doanh sẽ biến mất. Đây là điều không thể chấp nhận được.

Giải pháp? **Docker Volumes** — chủ đề của bài tiếp theo.
