# Phân Loại Dữ Liệu Trong Docker: 3 Loại Dữ Liệu Bạn Cần Biết

## Giới thiệu

Trước khi giải quyết vấn đề quản lý dữ liệu trong Docker, chúng ta cần hiểu rõ **có những loại dữ liệu nào** và mỗi loại có đặc điểm gì. Việc phân loại đúng giúp bạn chọn được phương pháp lưu trữ phù hợp cho từng trường hợp.

## 1. Dữ liệu ứng dụng (Application Code)

Đây là **source code** và **môi trường thực thi** của ứng dụng — thứ mà chúng ta viết và cấu hình. Dữ liệu này được **COPY vào image** trong quá trình build và trở thành **read-only** (chỉ đọc) khi image đã được tạo xong.

```dockerfile
# Code được copy vào image và không thể thay đổi
COPY . .
```

Điều này hoàn toàn hợp lý vì ứng dụng đang chạy không nên tự ý chỉnh sửa source code. Image chỉ đọc đảm bảo tính nhất quán và bảo mật.

## 2. Dữ liệu tạm thời (Temporary Data)

Là dữ liệu được tạo ra **trong quá trình ứng dụng chạy**, ví dụ: biến trong bộ nhớ, file cache, session data. Dữ liệu này được lưu trong **read-write layer** của container (tầng đọc-ghi mà Docker thêm lên trên image).

Đặc điểm:
- **Đọc-ghi**: Ứng dụng cần đọc và ghi dữ liệu này
- **Tạm thời**: Hoàn toàn OK nếu mất đi khi container tắt
- **Không cần lưu trữ**: Vì tính chất tạm thời của nó

Ví dụ: Khi người dùng nhập dữ liệu vào form, dữ liệu đó được xử lý tạm thời trên server — bạn không cần lưu nó vĩnh viễn.

## 3. Dữ liệu vĩnh viễn (Persistent Data)

Đây là loại dữ liệu **bắt buộc phải tồn tại** ngay cả khi container bị xóa — مثل tài khoản người dùng, dữ liệu cơ sở dữ liệu, file uploads. Vấn đề là nếu chỉ dùng container, dữ liệu này sẽ mất khi container bị xóa.

**Volumes** chính là giải pháp cho loại dữ liệu này. Volumes cho phép dữ liệu được lưu ra ngoài container, trên máy host, đảm bảo dữ liệu luôn an toàn.

## Tóm tắt

| Loại dữ liệu | Đặc điểm | Lưu ở đâu | Cần persist? |
|---|---|---|---|
| Source code | Read-only | Image | Không cần |
| Dữ liệu tạm thời | Read-write | Container layer | Không cần |
| Dữ liệu vĩnh viễn | Read-write | Volume | Có |

Hiểu rõ 3 loại dữ liệu này sẽ giúp bạn đưa ra quyết định đúng đắn khi quản lý dữ liệu trong Docker. Ở bài tiếp theo, chúng ta sẽ áp dụng kiến thức này vào một ứng dụng thực tế.
