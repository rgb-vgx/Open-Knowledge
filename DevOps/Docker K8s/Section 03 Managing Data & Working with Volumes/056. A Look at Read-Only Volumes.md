# ReadOnly Volumes: Bảo Vệ Dữ Liệu Container Khỏi Ghi Lại

## Giới heroine

Khi dùng bind mount, bạn có thể muốn container **chỉ đọc** dữ liệu từ host mà không được phép ghi lại. Đây là best practice để bảo vệ source code và cấu hình.

## Tại sao dùng ReadOnly Volume?

Với bind mount mặc định, container có quyền **read-write** trên thư mục mount. Điều này có thể nguy hiểm vì:
- Container có thể vô tình xóa hoặc sửa đổi file quan trọng
- Code trong container có thể ghi đè cấu hình host
- Khó debug khi có sự cố không mong muốn

## Cách sử dụng

Thêm `:ro` (read-only) sau đường dẫn container:

```bash
docker run -d -p 3000:80 --rm \
  -v feedback:/app/feedback \
  -v "$(pwd)":/app:ro \
  -v /app/node_modules \
  -v /app/temp \
  --name feedback-app \
  feedback-node:nodemon
```

## Kết hợp với writable sub-volumes

Vấn đề: Nếu mount toàn bộ `/app` ở chế độ read-only, container **không thể ghi** vào `feedback/` và `temp/`.

Giải pháp: Thêm volume riêng cho các thư mục cần ghi:

```bash
-v "$(pwd)":/app:ro \           # Toàn bộ app: read-only
-v /app/temp \                  # temp: writable (anonymous)
-v feedback:/app/feedback \     # feedback: writable (named)
```

Quy tắc: **Sub-volume cụ thể hơn ghi đè parent volume**.

## Lợi ích

1. **Bảo mật**: Container không thể sửa đổi source code
2. **Rõ ràng**: Mọi người hiểu rõ ý định thiết kế
3. **An toàn**: Tránh lỗi vô ý trong production
4. **Best practice**: Luôn nên mount code ở chế độ read-only trong production

## Kiểm tra

Sau khi chạy container, thử ghi file vào thư mục mount:

```bash
docker exec feedback-app touch /app/test.txt
# Kết quả: Read-only file system
```

ReadOnly volume là một phần quan trọng của chiến lược bảo mật Docker.
