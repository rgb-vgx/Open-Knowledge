# Tổng Kết: So Sánh Anonymous Volume, Named Volume & Bind Mounts

## Giới thiệu

Đây là lúc tổng hợp lại tất cả kiến thức về volumes và bind mounts. Có quá nhiều khái niệm dễ gây nhầm lẫn — bài viết này sẽ giúp bạn phân biệt rõ ràng.

## Ba cách sử dụng `-v` trong `docker run`

```bash
# 1. Anonymous Volume (không tên)
-v /app/feedback

# 2. Named Volume (có tên)
-v feedback:/app/feedback

# 3. Bind Mount (đường dẫn host)
-v /path/to/host/folder:/app
```

Đơn giản vậy thôi! Phần trước dấu `:` quyết định loại volume:
- **Không có gì** → Anonymous volume
- **Tên** → Named volume
- **Đường dẫn tuyệt đối** → Bind mount

## Bảng so sánh chi tiết

| Đặc điểm | Anonymous Volume | Named Volume | Bind Mount |
|-----------|-----------------|--------------|------------|
| Tạo trong Dockerfile | Có | Không | Không |
| Tạo khi `docker run` | Có | Có | Có |
| Tên | Tự động | Bạn đặt tên | Đường dẫn host |
| Tồn tại sau khi container xóa | Không (với --rm) | Có | Có |
| Quản lý bởi Docker | Có | Có | Không |
| Chia sẻ giữa containers | Không | Có | Có |
| Truy cập từ host | Khó | Khó | Dễ |
| Dùng trong production | Ít | Nhiều | Ít |

## Khi nào dùng loại nào?

**Anonymous Volume:**
- Bảo vệ thư mục cụ thể không bị ghi đè bởi bind mount
- Lưu dữ liệu tạm thời (cache, temp files)
- Tối ưu hiệu năng bằng cách "outsourced" dữ liệu ra host

**Named Volume:**
- Lưu dữ liệu vĩnh viễn (database, user uploads)
- Chia sẻ dữ liệu giữa nhiều containers
- Dùng trong production environments

**Bind Mount:**
- Phát triển locally với live code updates
- Chia sẻ cấu hình từ host vào container
- Khi bạn cần truy cập trực tiếp vào files

## Mẹo thực tế

Trong thực tế, bạn sẽ thường kết hợp cả ba loại trong một container:

```bash
docker run -d \
  -v app-data:/app/data \           # Named volume: dữ liệu vĩnh viễn
  -v "$(pwd)":/app \                # Bind mount: live code
  -v /app/node_modules \            # Anonymous volume: bảo vệ dependencies
  my-app
```
