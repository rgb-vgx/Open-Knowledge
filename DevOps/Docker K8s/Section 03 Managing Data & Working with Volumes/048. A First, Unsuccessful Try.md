# Lần Thử Đầu Tiên: Thêm Volume Vào Dockerfile

## Giới thiệu

Chúng ta đã hiểu Volumes là gì. Giờ hãy thử áp dụng vào thực tế bằng cách thêm volume trực tiếp trong Dockerfile.

## Thêm instruction VOLUME trong Dockerfile

```dockerfile
FROM node:14
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .

# Thêm anonymous volume cho thư mục feedback
VOLUME ["/app/feedback"]

EXPOSE 80
CMD ["node", "server.js"]
```

Instruction `VOLUME ["/app/feedback"]` nói với Docker: hãy tạo một volume cho đường dẫn `/app/feedback` bên trong container.

## Build và chạy

```bash
docker build -t feedback-node:volumes .
docker run -d -p 3000:80 --rm --name feedback-app feedback-node:volumes
```

## Vấn đề phát sinh

Sau khi thêm volume và chạy container, ứng dụng **bị crash** khi submit feedback! Kiểm tra logs:

```bash
docker logs feedback-app
```

Lỗi: `EXDEV: cross-device link, rename`

## Nguyên nhân lỗi

Phương thức `fs.rename()` trong Node.js không hoạt động khi file bị di chuyển giữa các thiết bị khác nhau. Vì volume được mounted ra ngoài container (ra host), thao tác rename bị coi là "cross-device" và thất bại.

## Giải pháp

Thay thế `rename` bằng `copyFile` + `unlink`:

```javascript
// Thay vì fs.rename
await fs.copyFile(tempFilePath, finalFilePath);
await fs.unlink(tempFilePath);
```

Sau khi sửa code, rebuild image và chạy lại — mọi thứ hoạt động bình thường. Nhưng vấn đề lớn hơn vẫn còn: **dữ liệu có thực sự tồn tại khi container xóa không?**
