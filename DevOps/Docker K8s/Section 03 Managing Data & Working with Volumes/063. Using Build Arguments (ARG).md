# Build Arguments (ARG): Tạo Images Linh Hoạt Khi Build

## Giới thiệu

Environment variables (ENV) giúp cấu hình runtime, nhưng bạn cũng cần sự linh hoạt **trong quá trình build image**. Docker cung cấp **Build Arguments (ARG)** để giải quyết vấn đề này.

## ARG vs ENV: Sự khác biệt quan trọng

| Đặc điểm | ARG | ENV |
|-----------|-----|-----|
| Thời điểm sử dụng | Chỉ khi build | Khi build VÀ khi chạy |
| Có trong container | Không | Có |
| Ghi đè khi build | Có | Không |
| Lưu trong image | Không (metadata) | Có |

## Cách sử dụng ARG

```dockerfile
# Khai báo argument với giá trị mặc định
ARG DEFAULT_PORT=80

# Sử dụng trong ENV instruction
ENV PORT=$DEFAULT_PORT

# Sử dụng trong RUN instruction
RUN echo "Building with port $DEFAULT_PORT"

EXPOSE $PORT
CMD ["node", "server.js"]
```

## Truyền argument khi build

```bash
# Dùng giá trị mặc định (port 80)
docker build -t feedback-node:production .

# Ghi đè port thành 8000
docker build -t feedback-node:dev --build-arg DEFAULT_PORT=8000 .
```

## Pattern phổ biến: ARG + ENV

```dockerfile
# ARG chỉ tồn tại khi build
ARG DEFAULT_PORT=80

# ENV kế thừa giá trị từ ARG
ENV PORT=$DEFAULT_PORT

EXPOSE $PORT
```

Cách này cho phép:
- Đặt giá trị mặc định linh hoạt khi build
- Ghi đè bằng `--build-arg` mà không sửa Dockerfile
- Giá trị vẫn có sẵn trong container qua ENV

## Ví dụ thực tế

```bash
# Production image với port 80
docker build -t my-app:prod .

# Development image với port 8000
docker build -t my-app:dev --build-arg DEFAULT_PORT=8000 .

# Mỗi image có port mặc định khác nhau
```

## Lưu ý quan trọng

1. **ARG không có trong container**: Chỉ dùng được trong Dockerfile
2. **ARG có thể bị lộ trong image history**: Không dùng cho secrets
3. **ARG bị giới hạn scope**: ARG trước FROM chỉ dùng được cho FROM
4. **Nên đặt ở cuối Dockerfile**: Để tránh rebuild layers không cần thiết
