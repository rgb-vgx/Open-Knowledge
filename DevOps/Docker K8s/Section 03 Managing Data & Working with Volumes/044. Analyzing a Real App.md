# Phân Tích Ứng Dụng Thật: Feedback App Trong Docker

## Giới thiệu

Để minh họa rõ ràng cho 3 loại dữ liệu đã nói ở bài trước, chúng ta sẽ cùng phân tích một ứng dụng Node.js thực tế — một **Feedback App** cho phép người dùng nhập phản hồi và lưu thành file.

## Cấu trúc ứng dụng

Ứng dụng bao gồm:

- **`server.js`**: File chính chứa mã nguồn server Node.js với các route xử lý request
- **`pages/`**: Thư mục chứa các file HTML (trang form, trang hiển thị feedback)
- **`public/`**: Thư mục chứa file CSS styles
- **`temp/`**: Thư mục lưu file tạm thời (ban đầu trống)
- **`feedback/`**: Thư mục lưu file feedback vĩnh viễn (ban đầu trống)

## Cách ứng dụng hoạt động

1. Người dùng truy cập form nhập feedback
2. Khi submit, feedback được lưu vào thư mục `temp/` dưới dạng file tạm
3. Ứng dụng kiểm tra file đã tồn tại chưa tại `feedback/`
4. Nếu chưa có, file sẽ được copy từ `temp/` sang `feedback/`

## 3 loại dữ liệu trong ứng dụng này

- **Source code**: `server.js`, các file HTML, CSS — được copy vào image, read-only
- **Dữ liệu tạm thời**: File trong thư mục `temp/` — OK nếu mất khi container xóa
- **Dữ liệu vĩnh viễn**: File trong thư mục `feedback/` — **bắt buộc phải lưu trữ**

Đây chính là kịch bản hoàn hảo để chúng ta thấy rõ vấn đề: khi container bị xóa, tất cả file trong `feedback/` sẽ biến mất. Giải pháp sẽ được giới thiệu ở bài tiếp theo — **Docker Volumes**.
