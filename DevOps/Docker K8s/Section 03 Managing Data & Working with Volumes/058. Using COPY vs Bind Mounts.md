# COPY Trong Dockerfile: Tại Sao Vẫn Cần Dù Đã Dùng Bind Mount?

## Giới thiệu

Nếu dùng bind mount cho toàn bộ source code trong quá trình phát triển, tại sao Dockerfile vẫn cần instruction `COPY`? Có vẻ như bước này bị trùng lặp?

## COPY trong Dockerfile vs Bind Mount

| | COPY trong Dockerfile | Bind Mount |
|---|---|---|
| **Thời điểm** | Lúc build image | Lúc chạy container |
| **Mục đích** | Tạo snapshot code cho image | Live code updates |
| **Sử dụng trong** | Production | Development |
| **Tính permanently** | Code được "đóng băng" trong image | Code thay đổi real-time |

## Tại sao vẫn cần COPY?

```dockerfile
COPY . .  # Vẫn cần giữ bước này
```

Lý do:

1. **Production không dùng bind mount**: Khi triển khai production, bạn không mount source code từ host vào container. Container phải tự chứa tất cả code.

2. **Tạo image snapshot**: COPY tạo ra image hoàn chỉnh, độc lập — có thể chạy ở bất kỳ đâu mà không cần source code trên host.

3. **Docker image phải self-contained**: Image phải chứa tất cả cần thiết để chạy ứng dụng. Không được phụ thuộc vào host.

## Workflow hoàn chỉnh

**Development:**
```bash
docker run -v "$(pwd)":/app ...  # Bind mount: live updates
```

**Production:**
```dockerfile
COPY . .  # Code được đóng băng trong image
CMD ["node", "server.js"]
```

```bash
docker run my-app:latest  # Không có bind mount
```

## Kết luận

Giữ COPY trong Dockerfile — đây là **bước cần thiết** để tạo image production-ready. Bind mount chỉ là công cụ development, không thay thế được COPY.
