# Thách Thức: Triển Khai Tasks API Lên Cluster EKS

Bạn đã triển khai thành công Users API và Auth API lên EKS cluster. Bây giờ là lúc thực hành thêm một API mới vào cluster.

## Tổng quan thách thức

Bạn sẽ cần triển khai **Tasks API** - một API mới quản lý công việc cá nhân. Tasks API sẽ:
- Kết nối đến MongoDB để lưu trữ tasks
- Giao tiếp với Auth API để xác thực
- Truy cập được từ bên ngoài (LoadBalancer)

## Yêu cầu

### 1. Tasks API phải accessible từ bên ngoài
- Sử dụng Service type **LoadBalancer**
- Listen trên port 3000

### 2. Tasks API phải giao tiếp được với Auth API
- Sử dụng environment variable `AUTH_API_ADDRESS`
- Giá trị: `http://auth-service.default.svc.cluster.local:3000`

### 3. Tasks API cần kết nối MongoDB
- Sử dụng environment variable `MONGODB_CONNECTION_URI`
- Connection string tương tự Users API

## Bước chuẩn bị

### Download code mới

Trong file đính kèm, bạn sẽ tìm thấy:
- `auth-api` - Đã cập nhật code
- `users-api` - Đã cập nhật code
- `tasks-api` - API mới
- `docker-compose.yaml` - Tham khảo cấu hình

### Build và Push images

```bash
# Auth API (đã có code mới)
cd auth-api
docker build -t [tên-tài-kho]/kub-dep-auth .
docker push [tên-tài-kho]/kub-dep-auth

# Users API (đã có code mới)
cd ../users-api
docker build -t [tên-tài-kho]/kub-dep-users .
docker push [tên-tài-kho]/kub-dep-users

# Tasks API (API mới)
cd ../tasks-api
docker build -t [tên-tài-kho]/kub-dep-tasks .
docker push [tên-tài-kho]/kub-dep-tasks
```

### Sửa lỗi typo trong Users API

Trong file `users.yaml`, sửa environment variable:

```yaml
# Sai (trước đây)
- name: AUTH_SERVICE_ADDRESS
  value: "http://auth-service.default.svc.cluster.local:3000"
  
# Đúng (bây giờ) - có 2 s ở cuối
- name: AUTH_API_ADDRESS
  value: "http://auth-service.default.svc.cluster.local:3000"
```

Tương tự trong `docker-compose.yaml`.

## Tạo file Tasks YAML

Tạo file `tasks.yaml` trong thư mục `kubernetes/`:

### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: tasks-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: task
  template:
    metadata:
      labels:
        app: task
    spec:
      containers:
        - name: tasks-api
          image: [tên-tài-kho]/kub-dep-tasks
          ports:
            - containerPort: 3000
          env:
            - name: MONGODB_CONNECTION_URI
              value: "[connection-string-cua-ban]"
            - name: AUTH_API_ADDRESS
              value: "http://auth-service.default.svc.cluster.local:3000"
```

### Service

```yaml
---
apiVersion: v1
kind: Service
metadata:
  name: tasks-service
spec:
  selector:
    app: task
  type: LoadBalancer
  ports:
    - protocol: TCP
      port: 80
      targetPort: 3000
```

## Checklist

Trước khi deploy, kiểm tra:

- [ ] Code auth-api, users-api, tasks-api đã được cập nhật
- [ ] Tất cả images đã build và push lên Docker Hub
- [ ] Connection string MongoDB đã đúng
- [ ] AUTH_API_ADDRESS đã sửa typo (2 s ở cuối)
- [ ] File `tasks.yaml` đã tạo đúng

## Deploy

```bash
cd kubernetes

# Deploy Tasks API
kubectl apply -f tasks.yaml

# Cập nhật Auth và Users API (vì code đã thay đổi)
kubectl delete deployment auth-deployment
kubectl delete deployment users-deployment
kubectl apply -f auth.yaml
kubectl apply -f users.yaml
```

## Kiểm tra

```bash
# Kiểm tra tất cả deployments
kubectl get deployments

# Kiểm tra pods
kubectl get pods

# Kiểm tra services (lấy EXTERNAL-IP)
kubectl get services
```

## Test Tasks API

Sử dụng Postman để test:

### 1. Login để lấy token

```http
POST http://[USERS-SERVICE-URL]/login
Content-Type: application/json

{
  "email": "test@test.com",
  "password": "testers"
}
```

Copy token từ response.

### 2. Lấy danh sách tasks

```http
GET http://[TASKS-SERVICE-URL]/tasks
Authorization: Bearer [token-cua-ban]
```

### 3. Tạo task mới

```http
POST http://[TASKS-SERVICE-URL]/tasks
Authorization: Bearer [token-cua-ban]
Content-Type: application/json

{
  "title": "Learn Docker",
  "text": "Learn it in depth"
}
```

### 4. Xóa task

```http
DELETE http://[TASKS-SERVICE-URL]/tasks/[task-id]
Authorization: Bearer [token-cua-ban]
```

## Điều cần lưu ý

- Tasks Service sẽ tạo **Load Balancer mới** trên AWS
- Bạn sẽ có **2 Load Balancers**: Users Service và Tasks Service
- Auth Service vẫn là ClusterIP (không có external IP)
- Mỗi user chỉ thấy tasks của riêng mình (cùng token)
