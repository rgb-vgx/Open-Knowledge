# Áp Dụng Cấu Hình Kubernetes Lên Cluster EKS

Đây là lúc tuyệt vời nhất - áp dụng những gì chúng ta đã học để triển khai ứng dụng lên cluster EKS thực tế. Điểm mạnh lớn nhất của Kubernetes là: **cấu hình YAML chúng ta đã dùng với minikobe sẽ hoạt động y hệt trên EKS**.

## Triển khai ứng dụng

Mở terminal và thực hiện:

```bash
# Vào thư mục chứa các file YAML
cd kubernetes

# Áp dụng cấu hình
kubectl apply -f auth.yaml
kubectl apply -f users.yaml
```

Lệnh này sẽ tạo các deployments và services trên cluster EKS.

## Kiểm tra triển khai

```bash
# Kiểm tra deployments
kubectl get deployments

# Kiểm tra pods
kubectl get pods

# Kiểm tra services
kubectl get services
```

### Kết quả mong đợi

```

users-deployment   2/2     2            2           1m

```

### Điểm khác biệt với minikube

Với minikube, trường `EXTERNAL-IP` của service type LoadBalancer luôn hiển thị `<pending>`. Nhưng với EKS, bạn sẽ nhận được một **URL thực tế** có thể truy cập từ Internet!

## Kiểm tra ứng dụng

### Lấy URL của Users Service

```bash
kubectl get services users-service
```

Copy giá trị trong cột `EXTERNAL-IP`.

### Test với Postman

1. Mở **Postman**
2. Tạo **POST request** đến: `http://[EXTERNAL-IP]/signup`
3. Body → Raw → JSON:
```json
{
  "email": "test@test.com",
  "password": "testers"
}
```
4. Click **Send** - Nhận về response "User created"

### Test Login

1. Tạo **POST request** đến: `http://[EXTERNAL-IP]/login`
2. Body → Raw → JSON:
```json
{
  "email": "test@test.com",
  "password": "testers"
}
```
3. Click **Send** - Nhận về response với token

### Kiểm tra lỗi

- Thử tạo user trùng email → Nhận lỗi "User already exists"
- Thử đăng nhập sai password → Nhận lỗi authentication
- Omit ký tự `@` trong email → Nhận lỗi validation

## Kiểm tra trên AWS Console

1. Mở **EC2 Console** → Tab **Load Balancers**
2. Bạn sẽ thấy **một Load Balancer mới** đã được tự động tạo
3. Đây là Load Balancer cho Users Service

## Communication nội bộ cluster

Communication giữa Users API và Auth API hoạt động bình thường thông qua tên service tự động:

```yaml
# Trong users.yaml
env:
  - name: AUTH_SERVICE_ADDRESS
    value: "http://auth-service.default.svc.cluster.local:3000"
```

Kiểm tra namespaces:

```bash
kubectl get namespaces
```

Bạn sẽ thấy namespace `default` mà chúng ta đang sử dụng.

## Cập nhật deployment

Thay đổi replicas trong `users.yaml` từ 2 lên 3:

```yaml
spec:
  replicas: 3
```

Áp dụng lại:

```bash
kubectl apply -f users.yaml
kubectl get pods
```

Bạn sẽ thấy thêm pods mới được tạo và distribute tự động across các nodes.

## Tóm tắt

- Cấu hình Kubernetes hoạt động y hệt trên EKS như trên minikube
- Service type LoadBalancer tự động tạo ALB trên AWS
- Communication nội bộ cluster hoạt động qua DNS tự động
- Pods được distribute tự động across worker nodes
- Cập nhật deployment đơn giản với `kubectl apply`

Đây chính là sức mạnh của Kubernetes - một cấu hình chuẩn hóa có thể áp dụng cho bất kỳ cluster nào!
