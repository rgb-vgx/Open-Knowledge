# Tạo và Cấu Hình Cluster Kubernetes Với AWS EKS

Bây giờ chúng ta đã có tài khoản AWS và AWS CLI được cấu hình, hãy bắt đầu tạo cluster EKS. Nhớ rằng cluster là thứ chúng ta cần tự tạo, còn các pods và containers sẽ được Kubernetes quản lý.

## Bước 1: Tạo IAM Role cho EKS Cluster

EKS cần quyền hạn để tạo và quản lý các tài nguyên khác (như EC2 instances). Chúng ta sử dụng IAM (Identity and Access Management) để cấp quyền này.

### Tạo Role mới

1. Mở IAM Console trong tab mới
2. Click **Roles** → **Create role**
3. Chọn **AWS service** làm trusted entity
4. Scroll xuống và chọn **EKS**
5. Chọn **EKS Cluster** làm use case
6. Click **Next**
7. Trang Permissions hiển thị các policy đã có sẵn cho EKS - **không cần thay đổi gì**
8. Click **Next**
9. Đặt tên cho role (ví dụ: `eksClusterRole`)
10. Click **Create role**

## Bước 2: Tạo VPC Network

Cluster EKS cần một mạng VPC (Virtual Private Cloud) để hoạt động. Sử dụng CloudFormation để tạo nhanh VPC.

### Tạo VPC bằng CloudFormation

1. Mở **CloudFormation Console** trong tab mới
2. Click **Create stack** → giữ nguyên default
3. Chọn **Template is ready** và nhập URL template VPC từ tài liệu đính kèm
4. Click **Next**
5. Đặt tên cho stack (ví dụ: `eksVpc`)
6. Click **Next** → **Create stack**
7. Đợi quá trình tạo hoàn tất (có thể mất vài phút)

## Bước 3: Tạo EKS Cluster

1. Quay lại trang **EKS Console**
2. Click **Create cluster**
3. Nhập tên cluster (ví dụ: `kub-dep-demo`)
4. Chọn phiên bản Kubernetes (nên chọn phiên bản mới nhất)
5. Chọn **Cluster Service Role** vừa tạo ở Bước 1
6. Click **Next**

### Cấu hình Network

7. Chọn **VPC** vừa tạo ở Bước 2
8. Chọn **Subnets** (để default)
9. **Cluster endpoint access**: Chọn **Public and private**
   - Public: Cho phép truy cập từ Internet
   - Private: Cho phép communication nội bộ cluster
10. Click **Next**

### Cấu hình Logging

11. Có thể bật logging nếu cần (không bắt buộc)
12. Click **Next**

### Review và tạo

13. Kiểm tra lại tất cả settings
14. Click **Create**
15. Đợi cluster được tạo (có thể mất 10-15 phút)

## Bước 4: Cấu hình kubectl cho EKS

Trong khi chờ cluster được tạo, hãy cấu hình kubectl:

### Sao lưu cấu hình minikube

```bash
cp ~/.kube/config ~/.kube/config.minikube
```

### Chạy lệnh cập nhật cấu hình

Sau khi cluster Active:

```bash
aws eks update-kubeconfig \
  --region us-east-2 \
  --name kub-dep-demo
```

### Kiểm tra kết nối

```bash
kubectl get nodes
kubectl get pods
```

Lúc này, `kubectl` đã kết nối đến cluster EKS thay vì minikube.

## Xác minh cluster

Kiểm tra cluster đã hoạt động:

```bash
# Danh sách nodes (sẽ trống vì chưa thêm worker nodes)
kubectl get nodes

# Kiểm tra namespaces
kubectl get namespaces
```

Cluster đã được tạo nhưng chưa có worker nodes. Section tiếp theo sẽ hướng dẫn thêm worker nodes vào cluster.

## Lưu ý quan trọng

- **Chờ cluster hoàn tất tạo** trước khi chạy lệnh `update-kubeconfig`
- **Region phải khớp** với region nơi bạn tạo cluster
- **Lưu file config.minikube** để có thể quay lại minikube nếu cần
- Kiểm tra trạng thái cluster trong AWS Console để đảm bảo đã Active
