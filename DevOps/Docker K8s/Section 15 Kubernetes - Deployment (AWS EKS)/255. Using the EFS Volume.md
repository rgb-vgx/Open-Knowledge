# Sử Dụng EFS Volume Trong Ứng Dụng

Bây giờ mọi thứ đã được cấu hình, chúng ta sẽ test việc sử dụng EFS volume thực tế. Ứng dụng sẽ ghi log vào file và đọc log từ file được lưu trữ trên EFS.

## Bước 1: Cập nhật Code

Thay thế các file sau trong thư mục `users-api`:
- `user-actions.js` - Thêm hàm ghi log vào file
- `user-routes.js` - Thêm route GET `/logs`

### Thay đổi chính:

**Ghi log khi tạo user mới:**
```javascript
// Khi user được tạo, ghi log vào file
const logEntry = `${new Date().toISOString()} - UserID: ${user._id} - Email: ${user.email}\n`;
fs.appendFileSync('/app/users/users-log.txt', logEntry);
```

**Đọc log:**
```javascript
// Route GET /logs - Đọc file log
const logs = fs.readFileSync('/app/users/users-log.txt', 'utf-8');
```

## Bước 2: Build và Push Image Mới

```bash
cd users-api

# Build image mới
docker build -t [tên-tài-kho]/kub-dep-users .

# Push lên Docker Hub
docker push [tên-tài-kho]/kub-dep-users
```

## Bước 3: Cập nhật Deployment

Có hai cách:

### Cách 1: Apply lại (khuyến khích)
```bash
cd kubernetes
kubectl apply -f users.yaml
```

### Cách 2: Xóa và tạo lại
```bash
kubectl delete deployment users-deployment
kubectl apply -f users.yaml
```

Kiểm tra pods mới:
```bash
kubectl get pods
```

Đợi pods ở trạng thái `Running`.

## Bước 5: Xác minh dữ liệu trên EFS

### Kiểm tra trên EFS Console

1. Mở **EFS Console**
2. Click vào file system `eks-efs`
3. Tab **Monitoring**
4. Kiểm tra các metrics:
   - **Data writes** - Có dữ liệu được ghi
   - **Client connections** - Số connections hiện tại (bằng số replicas)
   - **Metered size** - Kích thước dữ liệu

### Test tính persistent của dữ liệu

**Giảm replicas xuống 0:**
```yaml
# Trong users.yaml
spec:
  replicas: 0
```

```bash
kubectl apply -f users.yaml
kubectl get pods  # Tất cả pods đang terminating
```

**Tăng replicas lên 2:**
```yaml
spec:
  replicas: 2
```

```bash
kubectl apply -f users.yaml
kubectl get pods  # Pods mới đang starting
```

**Kiểm tra log vẫn còn:**
```http
GET http://[LOAD-BALANCER-URL]/logs
```

Dữ liệu log **vẫn được giữ nguyên** vì được lưu trên EFS, không phụ thuộc pods cụ thể.

## Giải thích: Tại sao dữ liệu vẫn còn?

1. **Persistent Volume** không bị ảnh hưởng khi pods restart
2. **EFS** lưu trữ dữ liệu bên ngoài cluster
3. **ReadWriteMany** cho phép nhiều pods/pods mới truy cập cùng dữ liệu
4. Dữ liệu được lưu trên EFS, không trên local container

## Các loại volume khác có thể sử dụng

Ngoài EFS, bạn có thể sử dụng:

- **awsElasticBlockStore** - EBS (block storage, chỉ ReadWriteOnce)
- **gcePersistentDisk** - Google Persistent Disk
- **azureDisk** - Azure Managed Disk
- **any CSI driver** của bên thứ ba

EFS chỉ là một ví dụ vì chúng ta đang sử dụng AWS. Bạn có thể dùng bất kỳ CSI driver nào phù hợp với cloud provider của mình.

## Tóm tắt

- EFS volume hoạt động chính xác như kỳ vọng
- Dữ liệu được persistent xuyên suốt vòng đời pods
- Hỗ trợ ReadWriteMany - nhiều pods có thể truy cập cùng lúc
- Dễ dàng tích hợp với Kubernetes thông qua CSI driver
- Tương thích với các công cụ monitoring của AWS

Bạn đã triển khai thành công ứng dụng Kubernetes với persistent storage trên AWS EKS!
