# Các cách chạy lệnh trong Container: docker run, docker exec, và Command Override

## Giới thiệu

Trước khi xây dựng Utility Container đầu tiên, chúng ta cần hiểu rõ **ba cách khác nhau** để chạy lệnh trong container. Mỗi cách đều có mục đích sử dụng riêng và hiểu rõ sự khác biệt sẽ giúp bạn làm việc hiệu quả hơn với Docker.

## Cách 1: Chạy container với chế độ tương tác (Interactive Mode)

Cách cơ bản nhất là chạy image trực tiếp với `docker run` ở chế độ tương tác:

```bash
docker run -it node:14-alpine
```

Khi chạy lệnh này, container khởi động và bạn nhận được một shell tương tác bên trong Node.js. Bạn có thể gõ các lệnh Node.js trực tiếp:

```javascript
> 2 + 2
4
> console.log('Hello from container')
Hello from container
```

Để thoát, nhấn `Ctrl+C` hai lần. Container sẽ dừng lại và xuất hiện trong danh sách stopped containers. Bạn có thể dọn dẹp bằng:

```bash
docker container prune
```

## Cách 2: docker exec — Chạy lệnh trong container đang chạy

**Docker exec** cho phép bạn thực thi một lệnh mới trong một container **đang chạy**, mà **không ảnh hưởng** đến tiến trình chính (PID 1) của container.

```bash
# Bước 1: Chạy container ở chế độ background với pseudo-TTY
docker run -d -it --name mynode node:14-alpine

# Bước 2: Chạy lệnh npm init bên trong container đang chạy
docker exec -it mynode npm init
```

Cú pháp đầy đủ:

```
docker exec [OPTIONS] CONTAINER COMMAND [ARG...]
```

### Các option quan trọng

| Option | Mô tả |
|--------|-------|
| `-i, --interactive` | Giữ STDIN mở ngay cả khi không attach |
| `-t, --tty` | Cấp phát pseudo-TTY |
| `-d, --detach` | Chạy lệnh ở chế độ background |
| `-w, --workdir` | Thư mục làm việc bên trong container |
| `-e, --env` | Đặt biến môi trường cho tiến trình exec |

### Ví dụ thực tế

```bash
# Đọc file log từ container đang chạy mà không làm gián đoạn ứng dụng
docker exec -it mycontainer cat /var/log/app.log

# Chạy lệnh trong thư mục cụ thể
docker exec -w /app mycontainer ls -la

# Chạy với biến môi trường tùy chỉnh
docker exec -e NODE_ENV=production mycontainer node script.js
```

Điểm quan trọng cần nhớ: lệnh exec chỉ chạy **trong khi container chính đang hoạt động**. Nếu container dừng, exec sẽ thất bại.

## Cách 3: Override Command — Thay thế lệnh mặc định

Mỗi image Docker đều có một lệnh mặc định được định nghĩa qua `CMD` trong Dockerfile. Bạn có thể **ghi đè** lệnh này bằng cách truyền một lệnh mới sau tên image khi chạy `docker run`:

```bash
# Lệnh mặc định của node image là chạy REPL (interactive mode)
# Bạn có thể override bằng:
docker run -it node:14-alpine npm init
```

Trong trường hợp này:
- Lệnh mặc định (`node`) bị thay thế bởi `npm init`
- Container chạy `npm init`, tạo file `package.json`, rồi dừng lại
- Container **không còn chạy REPL** nữa

### Khác biệt giữa exec và override

```bash
# docker exec: Chạy thêm một lệnh MỚI trong container đang chạy
docker exec -it mycontainer npm install

# Override command: THAY THẾ lệnh mặc định khi chạy container mới
docker run -it node:14-alpine npm init
```

- **exec** → container vẫn chạy tiến trình gốc, bạn chạy thêm lệnh khác
- **override** → container chạy lệnh mới thay vì lệnh gốc

## Tóm tắt

| Phương thức | Khi nào dùng | Container gốc |
|-------------|---------------|----------------|
| `docker run -it` | Chạy shell tương tác | Là tiến trình chính |
| `docker exec -it` | Thêm lệnh vào container đang chạy | Vẫn chạy bình thường |
| `docker run ... [CMD]` | Chạy container với lệnh khác mặc định | Bị thay thế |

Hiểu rõ ba cách này là nền tảng để xây dựng Utility Containers hiệu quả. Trong bài tiếp theo, chúng ta sẽ bắt tay vào xây dựng Utility Container đầu tiên.
