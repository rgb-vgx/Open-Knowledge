# Tại sao bạn cần Utility Containers? Bài toán cài đặt công cụ trên máy host

## Giới thiệu

Bạn có bao giờ gặp tình huống này: muốn tạo một dự án Node.js mới nhưng lại cần cài đặt Node.js trên máy trước? Hay muốn bắt đầu với Laravel nhưng phải cài đặt hàng tá công cụ trên máy host? Đây chính là lúc Utility Containers phát huy tác dụng.

## Bài toán thực tế

Hãy xem xét một tình huống đơn giản: bạn có một thư mục trống và muốn tạo dự án Node.js mới trong đó.

### Cách truyền thống — Cài đặt Node.js trên máy host

Để tạo dự án Node.js mới, bạn thường chạy:

```bash
npm init
```

Lệnh này sẽ hướng dẫn bạn trả lời một số câu hỏi và tạo file `package.json` với thông tin cấu hình dự án.

Vấn đề là gì? Lệnh `npm` **chỉ khả dụng** khi bạn đã cài đặt Node.js trên máy. Và để cài Node.js, bạn phải:

1. Truy cập nodejs.org
2. Tải về installer
3. Cài đặt trên máy host
4. Khởi động lại terminal

Điều này **trái ngược hoàn toàn** với triết lý cốt lõi của Docker — chúng ta muốn tránh cài đặt các công cụ toàn cục trên máy host.

### Không chỉ là Node.js

Vấn đề này không chỉ riêng Node.js. Nếu bạn làm việc với:

- **PHP/Laravel:** Cần cài PHP, Composer, và nhiều extension khác
- **Ruby on Rails:** Cần cài Ruby, Bundler, và các dependencies hệ thống
- **Java/Spring:** Cần cài JDK, Maven hoặc Gradle
- **Go:** Cần cài Go toolchain

Mỗi framework đều yêu cầu một bộ công cụ riêng trên máy host chỉ để **khởi tạo** dự án, dù sau đó bạn vẫn sẽ chạy ứng dụng trong Docker.

## Utility Containers giải quyết vấn đề này

Với Utility Containers, bạn **không cần cài đặt bất kỳ công cụ nào** trên máy host. Thay vào đó:

```bash
# Tạo dự án Node.js mới mà không cần cài Node.js
docker run -v $(pwd):/app node:14-alpine init

# Cài đặt dependencies mà không cần npm trên máy
docker run -v $(pwd):/app node:14-alpine install
```

Container sẽ:
1. Tải image Node.js (nếu chưa có)
2. Chạy lệnh `npm init` hoặc `npm install` bên trong container
3. Kết quả được ghi trực tiếp vào thư mục máy host thông qua bind mount
4. Container dừng lại sau khi hoàn thành

## So sánh

| | Truyền thống | Utility Container |
|---|---|---|
| Cài đặt công cụ | Cài trên máy host | Không cần |
| Khởi tạo dự án | `npm init` trực tiếp | `docker run ... npm init` |
| Ảnh hưởng hệ thống | Cài global packages | Hoàn toàn cách ly |
| Bảo mật | Phụ thuộc vào versions trên máy | Mỗi dự án dùng version riêng |
| Cleanup | Gỡ cài đặt thủ công | Xóa container khi xong |

## Kết luận

Utility Containers không chỉ là một trick hay — chúng là giải pháp cho một vấn đề thực tế mà mọi developer đều gặp phải. Bạn có thể bắt đầu dự án với bất kỳ ngôn ngữ nào mà **không cần cài đặt bất kỳ thứ gì** trên máy host.

Trong bài tiếp theo, chúng ta sẽ tìm hiểu các **cách khác nhau** để chạy lệnh trong container.
