# Tổng kết Module: Utility Containers và cách thực thi lệnh trong Container

## Giới thiệu

Chúng ta đã đi qua một hành trình khá dài với Utility Containers. Bài viết này tổng hợp lại toàn bộ kiến thức quan trọng, giúp bạn hệ thống hóa những gì đã học và sẵn sàng áp dụng vào thực tế.

## Utility Containers — Định nghĩa lại

**Utility Containers** là những container chỉ chứa một môi trường cụ thể (Node.js, PHP, Python...) nhưng **không chạy ứng dụng**. Thay vào đó, chúng được sử dụng để thực thi các lệnh cụ thể và dừng lại sau khi hoàn thành.

Đây **không phải** thuật ngữ chính thức của Docker, nhưng nó mô tả chính xác pattern mà chúng ta sử dụng.

## Kiến thức cốt lõi đã học

### 1. Các cách chạy lệnh trong container

| Lệnh | Mục đích | Container gốc |
|-------|----------|----------------|
| `docker run -it IMAGE` | Shell tương tác | Là tiến trình chính |
| `docker exec -it CONTAINER CMD` | Thêm lệnh vào container đang chạy | Vẫn chạy bình thường |
| `docker run IMAGE CMD` | Thay thế lệnh mặc định | Bị thay thế |

### 2. ENTRYPOINT vs CMD

```dockerfile
# CMD — Bị override hoàn toàn
CMD ["npm", "init"]
# docker run image install → chạy "install", KHÔNG chạy "npm init"

# ENTRYPOINT — Lệnh mới được APPEND sau
ENTRYPOINT ["npm"]
# docker run image install → chạy "npm install"
```

**Quy tắc:** ENTRYPOINT giữ nguyên, lệnh truyền vào `docker run` được nối thêm phía sau.

### 3. Docker Compose cho Utility Containers

```yaml
version: "3.8"
services:
  npm:
    build: .
    stdin_open: true
    tty: true
    volumes:
      - .:/app
```

- `docker compose run --rm npm init` — Chạy utility container rồi tự động xóa
- `docker compose up/down` — Dành cho application containers, **không phải** utility
- Luôn dùng `--rm` để giữ hệ thống sạch

### 4. Bind Mount — Kết nối container với host

```bash
docker run -it -v $(pwd):/app node-util init
```

- `-v $(pwd):/app` gắn thư mục hiện tại vào `/app` trong container
- Mọi thay đổi trong container → ghi trực tiếp trên host
- Utility container không có bind mount = kết quả bị mất khi container dừng

### 5. Quyền hạn trên Linux

- Container mặc định chạy với **root (UID 0)** → file tạo ra thuộc root
- Sử dụng **USER instruction** trong Dockerfile hoặc **--user** khi chạy
- **Không** dùng `--privileged` trừ khi thực sự cần

## Pattern thực tế

### Tạo dự án Node.js mới

```bash
# docker-compose.yml
version: "3.8"
services:
  npm:
    build: .
    stdin_open: true
    tty: true
    volumes:
      - .:/app

# Lệnh thực thi
docker compose run --rm npm init
docker compose run --rm npm install express --save
```

### Dockerfile tối giản

```dockerfile
FROM node:14-alpine
WORKDIR /app
USER node
ENTRYPOINT ["npm"]
```

## Tại sao Utility Containers quan trọng?

1. **Không cần cài tool trên host** — Node.js, npm, Composer... đều chạy trong container
2. **Mỗi dự án dùng version riêng** — Tránh conflict giữa các project
3. **Bảo mật** — Container cách ly, không ảnh hưởng hệ thống
4. **Tái sử dụng** — Image utility có thể dùng cho nhiều dự án
5. **Dọn dẹp dễ dàng** — Xóa container = xóa sạch môi trường
