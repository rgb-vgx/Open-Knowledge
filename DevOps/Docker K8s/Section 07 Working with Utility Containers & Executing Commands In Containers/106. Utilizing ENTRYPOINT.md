# Sử dụng ENTRYPOINT để tạo Utility Container chuyên dụng

## Giới thiệu

Utility Container ở bài trước cho phép chạy **bất kỳ lệnh nào**. Điều này linh hoạt nhưng cũng tiềm ẩn rủi ro — nếu bạn vô tình chạy `rm -rf /` trong container có bind mount, dữ liệu trên máy host cũng sẽ bị xóa. **ENTRYPOINT** giúp giải quyết vấn đề này bằng cách giới hạn container chỉ chạy một loại lệnh cụ thể.

## Vấn đề với Utility Container tự do

Với Dockerfile hiện tại:

```dockerfile
FROM node:14-alpine
WORKDIR /app
```

Bạn có thể chạy bất kỳ lệnh nào:

```bash
docker run -it -v $(pwd):/app node-util npm init
docker run -it -v $(pwd):/app node-util npm install
docker run -it -v $(pwd):/app node-util任意_lệnh_nào_đây
```

Điều này **nguy hiểm** vì:
- Không có sự kiểm soát nào về lệnh được chạy
- Rủi ro chạy các lệnh phá hủy dữ liệu
- Không rõ container này được thiết kế cho mục đích gì

## ENTRYPOINT là gì?

**ENTRYPOINT** là một instruction trong Dockerfile chỉ định **executable mặc định** của container. Điểm khác biệt quan trọng giữa ENTRYPOINT và CMD:

```dockerfile
# CMD — Bị GHI ĐỀ khi bạn truyền lệnh mới
CMD ["npm", "init"]
# docker run image something  → chạy "something", KHÔNG chạy "npm init"

# ENTRYPOINT — KHÔNG bị ghi đề, lệnh mới được THÊM VÀO sau
ENTRYPOINT ["npm"]
# docker run image init  → chạy "npm init"
# docker run image install  → chạy "npm install"
```

**Quy tắc:** Khi bạn truyền lệnh sau tên image trong `docker run`, lệnh đó sẽ được **nối thêm (append)** vào ENTRYPOINT, không thay thế nó.

## Practical: Chuyển đổi Utility Container

### Dockerfile cũ (không có ENTRYPOINT)

```dockerfile
FROM node:14-alpine
WORKDIR /app
```

```bash
# Phải gõ đầy đủ mỗi lần
docker run -it -v $(pwd):/app node-util npm init
docker run -it -v $(pwd):/app node-util npm install express
```

### Dockerfile mới (có ENTRYPOINT)

```dockerfile
FROM node:14-alpine
WORKDIR /app
ENTRYPOINT ["npm"]
```

```bash
# Chỉ cần gõ tham số — "npm" đã có sẵn
docker run -it -v $(pwd):/app mynpm init
docker run -it -v $(pwd):/app mynpm install
docker run -it -v $(pwd):/app mynpm install express --save
```

### Build và chạy

```bash
# Build image mới
docker build -t mynpm .

# Tạo dự án mới
docker run -it -v $(pwd):/app mynpm init

# Cài express
docker run -it -v $(pwd):/app mynpm install express --save
```

Kết quả: File `package.json` và thư mục `node_modules` xuất hiện trên máy host thông qua bind mount.

## Kết hợp CMD và ENTRYPOINT

Bạn cũng có thể sử dụng `CMD` để cung cấp **tham số mặc định** cho `ENTRYPOINT`:

```dockerfile
FROM node:14-alpine
WORKDIR /app
ENTRYPOINT ["npm"]
CMD ["init"]
```

Với Dockerfile này:
- `docker run -it -v $(pwd):/app mynpm` → chạy `npm init` (sử dụng CMD mặc định)
- `docker run -it -v $(pwd):/app mynpm install` → chạy `npm install` (override CMD)

### Quy tắc kết hợp

| Dockerfile | `docker run image` | `docker run image install` |
|------------|---------------------|----------------------------|
| `ENTRYPOINT ["npm"]` + `CMD ["init"]` | `npm init` | `npm install` |
| `ENTRYPOINT ["npm"]` (không có CMD) | `npm` (lỗi hoặc等待input) | `npm install` |
| `CMD ["npm", "init"]` (không có ENTRYPOINT) | `npm init` | `install` (lỗi — vì CMD bị override hoàn toàn) |

## Shell form vs Exec form

ENTRYPOINT hỗ trợ hai dạng cú pháp:

```dockerfile
# Exec form (KHUYẾN NGHỊ)
ENTRYPOINT ["npm"]

# Shell form
ENTRYPOINT npm
```

**Exec form** được khuyến nghị vì:
- Lệnh chạy trực tiếp làm PID 1 trong container
- Xử lý tín hiệu (SIGTERM, SIGKILL) đúng cách
- Không qua shell trung gian → an toàn hơn

**Shell form** chạy qua `/bin/sh -c`, dẫn đến:
- Lệnh chạy là child process của shell
- Tín hiệu không được forward đúng cách
- Có thể gặp vấn đề với graceful shutdown

## Tóm tắt

- **ENTRYPOINT** định nghĩa executable chính — lệnh truyền vào `docker run` sẽ được **append** sau đó
- **CMD** cung cấp tham số mặc định — bị **override** khi truyền lệnh mới
- Kết hợp ENTRYPOINT + CMD tạo ra utility container **linh hoạt và an toàn**
- Luôn sử dụng **exec form** (`["executable"]`) thay vì shell form

Trong bài tiếp theo, chúng ta sẽ tìm hiểu cách sử dụng **Docker Compose** để quản lý utility containers một cách tiện lợi hơn.
