# Sử dụng Docker Compose với Utility Containers

## Giới thiệu

Chạy utility containers bằng `docker run` với bind mount dài dòng có thể **phiền phức**. Docker Compose — dù thường được dùng cho multi-container applications — cũng rất hữu ích cho utility containers. Bài viết này hướng dẫn cách sử dụng `docker compose run` để quản lý utility containers một cách sạch sẽ và tiện lợi.

## Vấn đề: Lệnh dài và khó nhớ

Với `docker run`, mỗi lần chạy utility container bạn cần nhớ:

```bash
docker run -it -v $(pwd):/app mynpm install express --save
```

Lệnh này gồm nhiều phần và dễ bị gõ sai, đặc biệt khi bind mount path dài.

## Giải pháp: docker-compose.yml

Tạo file `docker-compose.yml`:

```yaml
version: "3.8"

services:
  npm:
    build: .
    stdin_open: true
    tty: true
    volumes:
      - .:/app
```

### Giải thích từng phần

| Directive | Ý nghĩa |
|-----------|---------|
| `version: "3.8"` | Phiên bản Docker Compose file format |
| `services.npm` | Định nghĩa service tên `npm` |
| `build: .` | Build image từ Dockerfile trong thư mục hiện tại |
| `stdin_open: true` | Tương ứng `-i` (giữ STDIN mở) |
| `tty: true` | Tương ứng `-t` (cấp phát pseudo-TTY) |
| `volumes: - .:/app` | Bind mount thư mục hiện tại vào `/app` |

## docker compose run — Command cho Utility Containers

**Điều quan trọng:** `docker compose up` **không phù hợp** cho utility containers. `up` được thiết kế để khởi động các service chạy liên tục (application containers).

Thay vào đó, sử dụng **`docker compose run`**:

```bash
# Tạo dự án mới
docker compose run npm init

# Cài dependencies
docker compose run npm install

# Cài package cụ thể
docker compose run npm install express --save
```

Lệnh ngắn gọn hơn nhiều so với `docker run` đầy đủ!

### Khác biệt giữa `docker compose up` và `docker compose run`

| | `docker compose up` | `docker compose run` |
|---|---|---|
| Mục đích | Khởi động service chạy liên tục | Chạy một lệnh rồi dừng |
| Container | Luôn chạy cho đến khi stop | Tự động dừng khi lệnh hoàn thành |
| Port mapping | Có (nếu định nghĩa) | Không (mặc định) |
| Phù hợp cho | Web server, database | npm init, build script, test |

## Xóa container sau khi chạy với --rm

Một vấn đề: sau khi `docker compose run` hoàn thành, container **không tự động xóa**. Dần dần bạn sẽ có nhiều stopped containers:

```bash
docker container ls -a  # Rất nhiều container cũ
```

Giải pháp: thêm flag `--rm`:

```bash
docker compose run --rm npm init
docker compose run --rm npm install
```

Container sẽ bị xóa ngay sau khi lệnh hoàn thành — giữ hệ thống sạch sẽ.

### So sánh清理

```bash
# Cách 1: Không dùng --rm → phải dọn thủ công
docker container prune

# Cách 2: Dùng --rm → tự động dọn sau mỗi lệnh
docker compose run --rm npm init
```

## docker compose exec — Chạy lệnh trong container đang chạy

Ngoài `run`, còn có `docker compose exec` — tương tự `docker exec`:

```bash
# Khởi động container trước
docker compose up -d npm

# Chạy lệnh bên trong container đang chạy
docker compose exec npm install

# Dừng container
docker compose down
```

**Khác biệt chính:**
- `docker compose run` → Tạo container mới, chạy lệnh, dừng lại
- `docker compose exec` → Chạy lệnh trong container **đã tồn tại**

## Ví dụ thực tế: Cài đặt Express

```bash
# 1. Tạo docker-compose.yml (xem ở trên)

# 2. Khởi tạo dự án
docker compose run --rm npm init

# 3. Cài Express và lưu vào dependencies
docker compose run --rm npm install express --save

# 4. Kiểm tra kết quả
cat package.json
# → File package.json có dependencies: { "express": "^4.18.0" }

ls node_modules/
# → Thư mục node_modules đã được tạo
```

Tất cả đều chạy **trong container** nhưng kết quả ghi trực tiếp vào máy host.

## Tóm tắt

- **`docker compose run`** là command lý tưởng cho utility containers
- **`docker compose.yml`** giúp bạn không phải gõ lệnh dài mỗi lần
- Luôn dùng **`--rm`** để tự động xóa container sau khi chạy
- **`docker compose up/down`** dành cho application containers, không phải utility
- Kết quả từ bind mount ghi trực tiếp vào máy host

Trong bài tiếp theo, chúng ta sẽ tìm hiểu về **quyền hạn (permissions)** khi làm việc với utility containers trên Linux.
