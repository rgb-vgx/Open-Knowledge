# Utility Containers và Quyền hạn trên Linux

## Giới thiệu

Khi làm việc với Utility Containers trên Linux, bạn có thể gặp phải các vấn đề liên quan đến **quyền hạn file**. Đây là chủ đề quan trọng mà nhiều developer bỏ qua, dẫn đến các lỗi khó hiểu. Bài viết này giúp bạn hiểu và xử lý vấn đề này.

## Vấn đề: Quyền hạn file giữa Container và Host

Khi sử dụng bind mount, các file được tạo bên trong container sẽ thuộc về **user UID/GID của container**, không phải user trên máy host. Điều này có thể gây ra:

- File tạo trong container **không thể sửa đổi** trên host
- Lỗi "Permission denied" khi truy cập file
- File sở hữu bởi root (UID 0) thay vì user thông thường

### Ví dụ minh họa

```bash
# Tạo utility container và chạy npm init
docker compose run --rm npm init

# Kiểm tra quyền file trên host
ls -la package.json
# -rw-r--r-- 1 root root ... package.json  ← Thuộc root!
```

File thuộc về `root` vì container chạy với user root mặc định.

## Giải pháp: USER instruction trong Dockerfile

Cách giải quyết phổ biến nhất là sử dụng **USER instruction** trong Dockerfile để chạy container với user cụ thể:

```dockerfile
FROM node:14-alpine
WORKDIR /app
USER node
ENTRYPOINT ["npm"]
```

Hoặc tạo user tùy chỉnh:

```dockerfile
FROM node:14-alpine
WORKDIR /app

# Tạo user với UID cụ thể
RUN addgroup -g 1000 appgroup && \
    adduser -u 1000 -G appgroup -s /bin/sh -D appuser

USER appuser
ENTRYPOINT ["npm"]
```

## Các cách xử lý quyền hạn

### Cách 1: Sử dụng USER instruction (Khuyến nghị)

```dockerfile
FROM node:14-alpine
WORKDIR /app
USER node  # Chạy với user "node" mặc định của image
ENTRYPOINT ["npm"]
```

`node:14-alpine` đã có sẵn user `node` với UID 1000. Đây là cách đơn giản nhất.

### Cách 2: Chạy container với user host

```bash
# Chạy với user hiện tại trên host
docker run -it --user $(id -u):$(id -g) -v $(pwd):/app node-util init
```

Flag `--user` ghi đè user trong Dockerfile, chạy lệnh với UID/GID của user host.

### Cách 3: Sử dụng --privileged (Không khuyến nghị)

```bash
# Cho phép container chạy với quyền root đầy đủ
docker run -it --privileged -v $(pwd):/app node-util init
```

**Cảnh báo:** `--privileged` cấp toàn quyền cho container — **rủi ro bảo mật cao**. Chỉ sử dụng trong môi trường development.

## Best Practices cho quyền hạn Utility Containers

### 1. Luôn định nghĩa user trong Dockerfile

```dockerfile
FROM node:14-alpine
WORKDIR /app
USER node
ENTRYPOINT ["npm"]
```

### 2. Sử dụng --user khi chạy

```bash
docker compose run --rm --user $(id -u):$(id -g) npm init
```

### 3. Kiểm tra quyền trước khi sử dụng

```bash
# Kiểm tra UID/GID hiện tại trên host
id  # uid=1000(maith) gid=1000(maith) groups=...

# Đảm bảo container chạy với cùng UID/GID
```

### 4. Chỉnh sửa quyền sau khi tạo file (nếu cần)

```bash
# Sửa quyền file thủ công
sudo chown $(id -u):$(id -g) package.json
```

## Tóm tắt

- Utility Containers trên Linux có thể tạo file với **quyền root** do container mặc định chạy với UID 0
- Sử dụng **USER instruction** trong Dockerfile hoặc flag **--user** khi chạy để tránh vấn đề này
- **KHÔNG** sử dụng `--privileged` trong môi trường production
- Luôn kiểm tra `id` trên host để đảm bảo UID/GID phù hợp
