# Xây dựng Utility Container đầu tiên với Node.js và Bind Mount

## Giới thiệu

Sau khi hiểu lý thuyết, giờ chúng ta sẽ **thực hành xây dựng** một Utility Container từ đầu. Bài viết này hướng dẫn bạn tạo image Node.js tối giản và sử dụng nó để chạy `npm init` mà không cần cài Node.js trên máy host.

## Bước 1: Viết Dockerfile

Tạo file `Dockerfile` trong thư mục dự án:

```dockerfile
FROM node:14-alpine
WORKDIR /app
```

Đơn giản phải không? Chỉ hai dòng:

- **`FROM node:14-alpine`**: Sử dụng image Node.js phiên bản 14 với base image Alpine Linux. Alpine là bản distro Linux cực kỳ nhẹ (~5MB), giúp image cuối cùng chỉ khoảng **35MB** thay vì hàng trăm MB.

- **`WORKDIR /app`**: Đặt thư mục làm việc mặc định là `/app`. Mọi lệnh chạy trong container sẽ thực thi từ thư mục này.

### Tại sao không dùng CMD hay ENTRYPOINT?

Chúng ta有意 **không** thêm `CMD` hay `ENTRYPOINT` trong Dockerfile này. Lý do:

- Không muốn giới hạn container chỉ chạy một lệnh cụ thể
- Muốn người dùng có toàn quyền quyết định lệnh nào sẽ chạy
- Dockerfile tối giản = image linh hoạt hơn

## Bước 2: Build image

```bash
docker build -t node-util .
```

Quá trình build sẽ:
1. Tải image `node:14-alpine` từ Docker Hub (nếu chưa có)
2. Đặt working directory là `/app`
3. Tạo image với tên `node-util`

Kết quả:

```
Successfully built abc123def456
Successfully tagged node-util:latest
```

Image này chỉ nặng khoảng **35MB** — rất nhỏ so với các image Node.js đầy đủ.

## Bước 3: Chạy Utility Container với Bind Mount

Đây là phần quan trọng nhất — sử dụng **bind mount** để chia sẻ thư mục giữa máy host và container:

```bash
docker run -it -v $(pwd):/app node-util init
```

Giải thích từng phần:

| Phần | Ý nghĩa |
|------|---------|
| `docker run` | Chạy container mới |
| `-it` | Chế độ tương tác (interactive + TTY) |
| `-v $(pwd):/app` | Bind mount: gắn thư mục hiện tại vào `/app` trong container |
| `node-util` | Tên image đã build |
| `init` | Lệnh cần thực thi (tương đương `npm init`) |

### Tại sao cần bind mount?

Khi chạy `npm init` bên trong container, kết quả (file `package.json`) sẽ được ghi vào thư mục `/app` bên trong container. Nếu **không có bind mount**, file đó sẽ **biến mất** khi container dừng lại.

Bind mount giải quyết vấn đề này bằng cách:
- Gắn thư mục hiện tại trên máy host (`$(pwd)`) vào `/app` trong container
- Mọi thay đổi trong `/app` bên trong container → **cũng thay đổi** trên máy host
- File `package.json` được tạo trực tiếp trên máy của bạn

## Bước 4: Kiểm tra kết quả

Sau khi hoàn tất `npm init`, bạn sẽ thấy file `package.json` xuất hiện trên máy host:

```json
{
  "name": "my-project",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "author": "",
  "license": "ISC"
}
```

Tuyệt vời! Bạn vừa tạo dự án Node.js **hoàn toàn bên trong container** mà không cần cài Node.js trên máy.

## Bước 5: Sử dụng cho npm install

Bây giờ bạn có thể cài đặt dependencies mà không cần npm trên máy host:

```bash
# Tạo file package.json
docker run -it -v $(pwd):/app node-util init

# Cài đặt dependencies
docker run -it -v $(pwd):/app node-util install
```

Thậm chí bạn có thể cài trực tiếp một package:

```bash
docker run -it -v $(pwd):/app node-util install express --save
```

## Tóm tắt

Với chỉ một Dockerfile hai dòng và utility container, bạn đã có thể:

- Tạo dự án Node.js mới (`npm init`)
- Cài đặt dependencies (`npm install`)
- Sử dụng bất kỳ lệnh npm nào

Mà **không cần cài đặt Node.js hay npm** trên máy host. Đây là sức mạnh thực sự của Utility Containers.

Trong bài tiếp theo, chúng ta sẽ tìm hiểu cách sử dụng **ENTRYPOINT** để tạo một utility container chuyên dụng hơn — chỉ chạy các lệnh npm mà không cần gõ `npm` mỗi lần.
