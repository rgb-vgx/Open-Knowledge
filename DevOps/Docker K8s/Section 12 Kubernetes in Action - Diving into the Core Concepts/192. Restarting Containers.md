# Tự Động Restart Containers: Khi Ứng Dụng Gặp Sự Cố

Một trong những tính năng tuyệt vời nhất của Kubernetes là **tự động restart containers** khi chúng gặp sự cố. Hãy cùng tìm hiểu cách nó hoạt động trong thực tế.

## Demo: Crash và Auto-restart

Giả sử ứng dụng Node.js của bạn có route `/error` gây crash:

```javascript
app.get('/error', () => {
  process.exit(1);  // Crash Node.js process
});
```

Khi bạn truy cập `/error`:

```
App crashed!
```

Nhưng sau vài giây, truy cập lại route gốc — ứng dụng hoạt động bình thường!

## Kiểm tra sự restart

```bash
kubectl get pods
```

Output:

```
NAME                        READY   STATUS    RESTARTS   AGE
first-app-6d4f5b8c9-abc12   1/1     Running   1          5m
```

Chú ý cột **RESTARTS** — giá trị đã tăng từ 0 lên 1. Kubernetes đã tự động restart container cho bạn.

## Crash lần nữa

Truy cập `/error` một lần nữa, rồi kiểm tra:

```bash
kubectl get pods
```

```
NAME                        READY   STATUS    RESTARTS   AGE
first-app-6d4f5b8c9-abc12   1/1     Running   2          7m
```

RESTARTS tăng lên 2. Và sau mỗi lần crash, thời gian chờ trước khi restart sẽ tăng dần (exponential backoff) để tránh infinite loops.

## Behavioral details

### Exponential Backoff

Kubernetes sử dụng **exponential backoff** khi restart:

- Lần 1: restart ngay lập tức
- Lần 2: chờ 10 giây
- Lần 3: chờ 20 giây
- Lần 4: chờ 40 giây
- ... và tiếp tục tăng đến max 5 phút

Mục đích: Nếu ứng dụng có vấn đề nghiêm trọng (không thể restart được), Kubernetes sẽ dần dần ngừng thử thay vì liên tục restart vô nghĩa.

### Dashboard View

Trong Minikube dashboard:

```
Pods → first-app-6d4f5b8c9-abc12
  Events:
    - Pulling image "nginx"
    - Created container
    - Started container
    - Killing container (due to crash)
    - Pulling image "nginx"
    - Created container (restart)
    - Started container (restart)
```

Events log cho thấy container đã được tạo lại sau mỗi lần crash.

## Tại sao điều này quan trọng?

1. **High availability** — ứng dụng tự phục hồi mà không cần intervention
2. **Reduced downtime** — dù có crash, ứng dụng nhanh chóng trở lại
3. **Less operational overhead** — không cần monitor và restart thủ công

## Tóm tắt

Kubernetes tự động restart containers khi chúng crash, với exponential backoff để tránh restart loops. Tính năng này là nền tảng cho high availability trong production.
