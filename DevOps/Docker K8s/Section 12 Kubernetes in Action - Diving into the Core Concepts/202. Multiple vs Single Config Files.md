# Nhiều Files Hay Một File: Cách Tổ Chức Configuration

Bạn có thể giữ Deployment và Service trong nhiều files riêng biệt, hoặc gộp lại thành một file. Mỗi cách có ưu điểm riêng.

## Cách 1: Nhiều files riêng biệt

```
project/
├── deployment.yaml
└── service.yaml
```

**Ưu điểm:**
- Rõ ràng — mỗi file cho một loại resource
- Dễ tìm khi cần thay đổi một loại cụ thể
- Phù hợp cho projects lớn

**Nhược điểm:**
- Nhiều files cần manage
- Khó thấy mối quan hệ giữa resources

## Cách 2: Gộp thành một file

```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend
spec:
  selector:
    app: second-app
  ports:
  - port: 80
    targetPort: 8080
  type: LoadBalancer
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: second-app-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: second-app
  template:
    metadata:
      labels:
        app: second-app
    spec:
      containers:
      - name: second-node
        image: your-dockerhub-username/kub-first-app
```

Lưu ý: Dùng **ba dấu gạch ngang `---`** để phân tách các resource definitions.

**Ưu điểm:**
- Dễ thấy mối quan hệ giữa resources
- Ít files hơn
- Apply một lần tạo tất cả resources

**Nhược điểm:**
- File lớn hơn, khó navigate hơn

## Best practices

1. **Đặt Service trước Deployment** trong file gộp
2. Resources được tạo **từ trên xuống dưới**
3. Service có selector sẽ tự động pickup Pods được tạo sau

## Apply multiple files

```bash
# Apply nhiều files riêng biệt
kubectl apply -f deployment.yaml -f service.yaml

# Apply một file gộp
kubectl apply -f master-deployment.yaml

# Apply tất cả files trong thư mục
kubectl apply -f ./k8s/
```

## Kết luận

Cả hai cách đều hoạt động tốt. Choose theo project size và preference. Projects nhỏ → gộp một file. Projects lớn → nhiều files riêng biệt.

---

**Tóm tắt:** Gộp resources thành một file bằng `---` separator. Đặt Service trước Deployment. Apply bằng `kubectl apply -f`. Cả hai cách đều hoạt động — chọn theo project size và team preference.
