# Cập Nhật & Xóa Resources: Dễ Dàng Với Declarative Approach

Với declarative approach, cập nhật và xóa resources trở nên cực kỳ đơn giản — chỉ cần thay đổi file và apply lại.

## Cập nhật Resources

### Thay đổi replicas

Thay đổi `replicas: 1` thành `replicas: 3` trong deployment.yaml:

```yaml
spec:
  replicas: 3  # Thay đổi từ 1
```

Apply lại:

```bash
kubectl apply -f deployment.yaml
```

Kubernetes tự động detect thay đổi và scale Pods.

### Thay đổi image

Thay đổi image trong template:

```yaml
spec:
  template:
    spec:
      containers:
      - name: second-node
        image: your-dockerhub-username/kub-first-app:2  # Thay đổi image
```

Apply lại:

```bash
kubectl apply -f deployment.yaml
```

Kubernetes thực hiện rolling update.

## Xóa Resources

### Xóa theo file

```bash
kubectl delete -f deployment.yaml -f service.yaml
```

Xóa tất cả resources được tạo từ các files này.

### Xóa theo tên (imperative)

```bash
kubectl delete deployment second-app-deployment
kubectl delete service backend
```

Dù bạn tạo resources bằng declarative approach, bạn vẫn có thể xóa chúng bằng imperative command.

### Xóa tất cả resources trong một file

```bash
kubectl delete -f master-deployment.yaml
```

Xóa tất cả resources (cả Deployment và Service) được define trong file đó.

## Ưu điểm của declarative updates

1. **Chỉ thay đổi những gì cần thiết** — không cần repeat cả command
2. **Dễ dàng hơn** — chỉ sửa file và apply lại
3. **Version control** — commit changes lên Git
4. **Ít lỗi hơn** — không cần gõ lại lệnh dài

## Kết luận

Cập nhật resources bằng declarative approach cực kỳ đơn giản: thay đổi file → apply lại. Kubernetes tự detect thay đổi và cập nhật. Xóa resources bằng `kubectl delete -f`.

---

**Tóm tắt:** Cập nhật: thay đổi file → `kubectl apply -f`. Xóa: `kubectl delete -f` hoặc `kubectl delete resource-name`. Declarative approach giúp updates đơn giản và ít lỗi hơn imperative.
