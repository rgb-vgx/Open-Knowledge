# Imperative vs Declarative: Hai Cách Tiếp Cận Kubernetes

Bạn đã thử imperative approach với các lệnh `kubectl create`, `kubectl expose`. Nhưng có một cách tiếp cận tốt hơn cho production: **declarative approach**.

## Imperative Approach (Mệnh lệnh)

Bạn chạy từng lệnh riêng biệt:

```bash
kubectl create deployment my-app --image=nginx
kubectl expose deployment my-app --port=80 --type=LoadBalancer
kubectl scale deployment my-app --replicas=3
```

**Ưu điểm:**
- Nhanh cho quick testing
- Không cần tạo files
- Dễ học cho người mới

**Nhược điểm:**
- Phải nhớ nhiều lệnh
- Khó maintain khi project lớn
- Không có version history
- Dễ mắc lỗi khi gõ lệnh

## Declarative Approach (Khẳng định)

Bạn viết cấu hình trong YAML files và apply:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: nginx
        image: nginx
```

```bash
kubectl apply -f deployment.yaml
```

**Ưu điểm:**
- Dễ maintain — tất cả cấu hình trong files
- Version control — commit lên Git
- Dễ share với team
- Ít lỗi hơn — chỉ cần thay đổi file và apply lại
- Kubernetes tự detect thay đổi và cập nhật

**Nhược điểm:**
- Cần học YAML syntax
- Ban đầu phức tạp hơn

## So sánh

| Tiêu chí | Imperative | Declarative |
|----------|-----------|-------------|
| Tốc độ ban đầu | Nhanh | Chậm hơn |
| Maintainability | Khó | Dễ |
| Version control | Không | Có (Git) |
| Sharing | Khó | Dễ |
| Error-prone | Cao | Thấp |
| Production-ready | Không | Có |

## Docker Compose analogy

Nếu bạn đã quen với Docker:
- **Imperative** = `docker run` nhiều lần (mỗi lần một lệnh)
- **Declarative** = `docker-compose.yml` + `docker-compose up` (tất cả trong một file)

Kubernetes declarative approach tương tự docker-compose — bạn viết cấu hình một lần, sau đó chỉ cần `apply` lại khi có thay đổi.

## Khuyến nghị

**Luôn sử dụng declarative approach** cho:
- Production deployments
- Team projects
- Bất kỳ project nào cần maintain dài hạn

Chỉ dùng imperative cho:
- Quick testing trên local
- One-off tasks

## Kết luận

Declarative approach là cách tiếp cận được khuyến nghị cho Kubernetes. Bạn viết cấu hình trong YAML files, sau đó dùng `kubectl apply` để Kubernetes thực thi. Dễ maintain, dễ share, và có version history.

---

**Tóm tắt:** Imperative chạy lệnh trực tiếp, declarative dùng YAML files + `kubectl apply`. Declarative approach được khuyến nghị cho production vì dễ maintain, có version control, và ít lỗi hơn.
