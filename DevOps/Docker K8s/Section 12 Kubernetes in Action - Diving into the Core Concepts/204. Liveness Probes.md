# Liveness Probes: Cách Kubernetes Kiểm Tra Sức Khỏe Containers

Kubernetes cần biết khi nào container gặp sự cố để restart. **Liveness Probes** là cách bạn nói với Kubernetes "hãy kiểm tra theo cách này".

## Tại sao cần Liveness Probes?

Mặc định, Kubernetes chỉ kiểm tra xem process trong container có đang chạy không. Nhưng đôi khi process vẫn chạy nhưng ứng dụng đã "treo" — không phản hồi nữa.

Liveness Probe cho phép bạn define **cách kiểm tra chính xác** — thường là gửi HTTP request đến health endpoint.

## Các loại Probes

### 1. HTTP GET Probe (Phổ biến nhất)

```yaml
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 3
```

Kubernetes gửi HTTP GET request đến `/healthz` trên port 8080. Nếu response status code >= 200 và < 400, container được coi là healthy.

### 2. TCP Socket Probe

```yaml
livenessProbe:
  tcpSocket:
    port: 8080
```

Kiểm tra xem port có open không.

### 3. Exec Command Probe

```yaml
livenessProbe:
  exec:
    command:
    - cat
    - /tmp/healthy
```

Chạy command trong container. Exit code 0 = healthy.

### 4. gRPC Probe

```yaml
livenessProbe:
  grpc:
    port: 8080
```

Sử dụng gRPC health checking protocol.

## Cấu hình chi tiết

```yaml
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 5    # Đợi 5s trước khi probe lần đầu
  periodSeconds: 3          # Probe mỗi 3 giây
  timeoutSeconds: 1         # Timeout sau 1 giây
  failureThreshold: 3       # Fail 3 lần liên tiếp = unhealthy
  successThreshold: 1       # 1 lần success = healthy
```

| Field | Mặc định | Ý nghĩa |
|-------|----------|---------|
| `initialDelaySeconds` | 0 | Đợi trước khi probe lần đầu |
| `periodSeconds` | 10 | Tần suất probe |
| `timeoutSeconds` | 1 | Timeout mỗi probe |
| `failureThreshold` | 3 | Số lần fail liên tiếp trước khi restart |

## Ví dụ thực tế

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: my-app:latest
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 5
          failureThreshold: 3
```

Khi container crash hoặc treo:
1. Liveness probe fail 3 lần liên tiếp
2. Kubernetes restart container
3. Container được thay thế bằng instance mới

## Startup Probes

Cho applications cần thời gian khởi động dài:

```yaml
startupProbe:
  httpGet:
    path: /healthz
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
```

Startup probe chạy trước liveness probe. Nếu startup probe fail, container bị restart. Khi startup probe success, liveness probe bắt đầu hoạt động.

## Kết luận

Liveness Probes giúp Kubernetes detect containers bị treo hoặc không healthy. HTTP GET probe là phổ biến nhất. Configure initialDelaySeconds, periodSeconds, và failureThreshold phù hợp với ứng dụng của bạn.

---

**Tóm tắt:** Liveness Probes kiểm tra health containers. HTTP GET probe phổ biến nhất. Configure initialDelaySeconds, periodSeconds, timeoutSeconds, failureThreshold. Startup probes cho applications khởi động chậm.
