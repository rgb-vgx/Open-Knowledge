# Kubernetes KHÔNG Quản Lý Infrastructure Của Bạn — Điều Quan Trọng Nhất Cần Hiểu

Một trong những nhầm lẫn phổ biến nhất về Kubernetes là suy nghĩ rằng nó sẽ tạo và quản lý toàn bộ hạ tầng cho bạn. Sự thật không phải vậy — và hiểu rõ ranh giới này là bước đầu tiên để làm việc hiệu quả với Kubernetes.

## Kubernetes làm gì và không làm gì?

### Kubernetes **làm** gì?

Kubernetes tập trung vào việc **orchestrate containers** — tức là quản lý vòng đời của các containers bên trong Pods:

- **Tạo và quản lý Pods** — đơn vị nhỏ nhất mà Kubernetes tương tác
- **Monitor health** của containers — kiểm tra liên tục xem chúng có đang chạy đúng cách không
- **Tự động restart** containers khi chúng gặp sự cố
- **Scale up/down** số lượng Pods khi cần thiết
- **Rolling updates** — cập nhật ứng dụng mà không downtime
- **Load balancing** — phân phối traffic giữa các Pods

Nói cách khác, Kubernetes chịu trách nhiệm đảm bảo **ứng dụng của bạn luôn chạy và có thể truy cập được**.

### Kubernetes **KHÔNG làm** gì?

Đây là phần quan trọng nhất:

- **KHÔNG tạo máy ảo** — Kubernetes không phải là công cụ tạo EC2 instances hay VMs
- **KHÔNG quản lý infrastructure** — nó không biết gì về network security groups, load balancers, hay file systems
- **KHÔNG cài đặt phần mềm** — nó không tự cài kubelet, API server, hay bất kỳ service nào trên nodes
- **KHÔNG phải cloud provider** — nó không phải AWS, GCP, hay Azure

## Điều này có ý nghĩa gì?

Khi sử dụng Kubernetes, bạn vẫn cần:

1. **Tạo machines trước** — سواء là VMs trên cloud hay physical servers trong data center
2. **Cài đặt Kubernetes components** — API server, scheduler, kubelet trên từng node
3. **Quản lý OS updates** — cập nhật hệ điều hành định kỳ
4. **Đảm bảo security** — cấu hình firewall, network policies
5. **Tạo additional resources** — load balancers, storage volumes nếu ứng dụng cần

## Giải pháp cho người không chuyên infrastructure

Nếu bạn không muốn quản lý infrastructure thủ công, có một số lựa chọn:

### Managed Kubernetes Services

Các cloud provider cung cấp dịch vụ managed Kubernetes:

- **AWS EKS** (Elastic Kubernetes Service)
- **Google GKE** (Google Kubernetes Engine)
- **Azure AKS** (Azure Kubernetes Service)

Các dịch vụ này sẽ tạo và quản lý control plane (master nodes) cho bạn, nhưng worker nodes vẫn cần được quản lý.

### Công cụ hỗ trợ

- **Kubermatic** — giúp tự động hóa việc tạo infrastructure cần thiết cho Kubernetes
- **kops** — Kubernetes Operations, giúp triển khai cluster production-ready

## Kết luận

Hiểu rõ ranh giới giữa Kubernetes và infrastructure là điều kiện tiên quyết để làm việc hiệu quả. Kubernetes là **quản lý container orchestration**, không phải quản lý machines. Bạn tạo machines, cài đặt Kubernetes components, rồi Kubernetes sẽ tận dụng chúng để quản lý containers của bạn.

---

**Tóm tắt:** Kubernetes quản lý containers thông qua Pods, nhưng KHÔNG tạo hay quản lý infrastructure. Bạn cần tạo machines và cài đặt Kubernetes components trước. Sử dụng managed services như EKS/GKE/AKS hoặc công cụ như Kubermatic để tự động hóa phần infrastructure.
