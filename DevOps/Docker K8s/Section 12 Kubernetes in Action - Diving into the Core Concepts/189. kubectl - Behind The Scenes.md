# Kubectl Behind The Scenes: Điều Gì Xảy Ra Đằng Sau Mỗi Lệnh?

Bạn đã chạy `kubectl create deployment` và thấy kết quả. Nhưng điều gì thực sự xảy ra bên trong cluster? Hiểu rõ quy trình này sẽ giúp bạn debug và làm việc hiệu quả hơn.

## Quy trình từ lệnh kubectl đến container đang chạy

### Bước 1: kubectl gửi yêu cầu đến API Server

Khi bạn chạy lệnh:

```bash
kubectl create deployment first-app --image=nginx
```

kubectl:
1. Tạo một **Deployment object** (JSON/YAML)
2. Gửi HTTP request đến **API Server** trên master node
3. API Server là "cánh cửa" duy nhất để tương tác với cluster

### Bước 2: API Server xử lý và lưu trữ

API Server:
1. Xác thực và validate Deployment object
2. Lưu object vào **etcd** (cluster's database)
3. Thông báo cho các controllers về object mới

### Bước 3: Deployment Controller hoạt động

Deployment Controller:
1. Nhận thông báo về Deployment mới
2. Đọc spec từ Deployment object (số replicas, image, etc.)
3. Tạo **ReplicaSet** — controller đảm bảo đúng số Pods đang chạy

### Bước 4: ReplicaSet Controller tạo Pods

ReplicaSet Controller:
1. So sánh số Pods hiện tại vs. số Pods mong muốn
2. Nếu thiếu → tạo Pod template mới
3. Gửi Pod object đến API Server

### Bước 5: Scheduler phân Pods vào Nodes

Scheduler:
1. Nhận Pods chưa được assign vào node nào
2. Phân tích resources của mỗi node (CPU, memory)
3. Chọn node phù hợp nhất
4. Gán Pod vào node đó (cập nhật Pod spec)

### Bước 6: Kubelet trên Node khởi động Container

Kubelet:
1. Nhận Pod đã được assign vào node của mình
2. Đọc container image từ Pod spec
3. Pull image (nếu chưa có)
4. Khởi động container
5. Monitor health của container

## Tại sao hiểu quy trình này quan trọng?

### Debug hiệu quả hơn

Khi gặp sự cố, bạn sẽ biết cần kiểm tra ở đâu:

```bash
# Pod không start? Kiểm tra events
kubectl describe pod <pod-name>

# Deployment không ready? Kiểm tra ReplicaSet
kubectl get rs

# Node có vấn đề? Kiểm tra node status
kubectl get nodes
kubectl describe node <node-name>
```

### Hiểu được "magic" thực sự là gì

Khi bạn thấy Kubernetes "tự động" làm điều gì đó, đó là nhờ:
- **Controllers** continuously reconcile desired state vs. current state
- **Scheduler** tự động phân Pods vào nodes
- **Kubelet** tự động khởi động containers

### Predict behavior better

Biết rằng Pods được scheduler dựa trên resources, bạn có thể:
- Set resource requests/limits cho containers
- Đảm bảo nodes có đủ resources
- Tránh situations where pods can't be scheduled

## Kết luận

Mỗi lệnh kubectl là một chuỗi các bước: kubectl → API Server → etcd → Controllers → Scheduler → Kubelet → Container. Hiểu quy trình này giúp bạn debug hiệu quả và làm việc với Kubernetes tự tin hơn.

---

**Tóm tắt:** kubectl gửi request đến API Server, lưu vào etcd. Deployment Controller tạo ReplicaSet, ReplicaSet tạo Pods. Scheduler phân Pods vào nodes, Kubelet khởi động containers. Hiểu quy trình này giúp debug hiệu quả.
