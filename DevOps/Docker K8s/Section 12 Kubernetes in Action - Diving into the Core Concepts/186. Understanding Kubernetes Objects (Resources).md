# Hiểu Về Kubernetes Objects: Đơn Vị Cơ Bản Của Kubernetes

Kubernetes hoạt động dựa trên một khái niệm cốt lõi: **Objects** (tài nguyên). Mỗi thao tác bạn thực hiện với Kubernetes đều thông qua việc tạo, sửa đổi, hoặc xóa các objects. Hãy cùng tìm hiểu cách chúng hoạt động.

## Kubernetes Objects là gì?

Kubernetes sử dụng hệ thống **objects** để quản lý mọi thứ. Mỗi object là một "bản thiết kế" mô tả trạng thái bạn muốn Kubernetes duy trì.

Ví dụ: Khi bạn muốn chạy 3 containers giống nhau, bạn tạo một **Deployment object** — Kubernetes sẽ đọc nó và tạo ra 3 Pods chứa containers đó.

## Các Object chính

### Pod — Đơn vị nhỏ nhất

Pod là đơn vị nhỏ nhất mà Kubernetes quản lý. Pod chứa một hoặc nhiều containers.

```
Pod
├── Container 1 (app chính)
├── Container 2 (sidecar — tùy chọn)
└── Shared Resources (volumes, network)
```

**Đặc điểm quan trọng của Pod:**

- **Mỗi Pod có một cluster-internal IP address** — nhưng IP này sẽ thay đổi khi Pod bị thay thế
- **Containers trong cùng Pod giao tiếp qua localhost** — giống như concept "task" trong AWS ECS
- **Pod là ephemeral (tạm thời)** — khi Pod bị xóa, mọi dữ liệu trong đó mất hoàn toàn
- **Thường chỉ có 1 container per Pod** — dù Kubernetes cho phép nhiều hơn

### Tại sao Pod ephemeral?

Đây là design decision có chủ đích. Containers cũng hoạt động tương tự — khi container bị xóa và chạy lại từ cùng image, dữ liệu cũ mất. Pod cũng vậy vì nó chỉ là "wrapper mỏng" xung quanh container.

Để persist data, bạn cần sử dụng **Persistent Volumes** — sẽ được cover trong các bài sau.

### Deployment — Controller manages Pods

Bạn **không nên** tạo Pods trực tiếp. Thay vào đó, hãy tạo **Deployment object**.

Deployment là **controller object** — nó:

1. **Định nghĩa trạng thái mong muốn** (desired state) — ví dụ: "tôi muốn 3 Pods đang chạy"
2. **Kubernetes thực thi** để đạt được trạng thái đó
3. **Tự động quản lý vòng đời** — tạo Pods, thay thế Pods hỏng, scale up/down

**Ưu điểm của Deployment:**

- Kubernetes tự động chọn worker node phù hợp (dựa trên CPU/memory)
- Tự động restart Pods khi containers crash
- Hỗ trợ **rolling updates** — cập nhật ứng dụng không downtime
- Hỗ trợ **rollbacks** — quay lại phiên bản trước nếu có vấn đề
- Hỗ trợ **autoscaling** — tự động thêm/bớt Pods dựa trên traffic

## Cách tạo Objects

Kubernetes hỗ trợ hai cách tạo objects:

### 1. Imperative Approach (Mệnh lệnh)

Bạn chạy lệnh trực tiếp trên terminal:

```bash
kubectl create deployment my-app --image=nginx
kubectl expose deployment my-app --port=80 --type=LoadBalancer
```

Ưu điểm: Nhanh, phù hợp cho quick testing.
Nhược điểm: Khó maintain, không có version history, dễ typo.

### 2. Declarative Approach (Khẳng định)

Bạn viết cấu hình trong YAML file và apply:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: nginx
        image: nginx
```

```bash
kubectl apply -f deployment.yaml
```

Ưu điểm: Dễ maintain, có version control, share được với team.
Nhược điểm: Cần học thêm YAML syntax.

## Kết luận

Kubernetes Objects là cách bạn giao tiếp với cluster. Pod là đơn vị nhỏ nhất chứa containers, Deployment là controller quản lý Pods. Luôn tạo Deployment thay vì Pods trực tiếp để tận dụng tự động hóa mà Kubernetes mang lại.

---

**Tóm tắt:** Kubernetes hoạt động qua Objects. Pod chứa containers nhưng là ephemeral. Deployment là controller quản lý Pods, hỗ trợ auto-restart, scaling, rolling updates. Hai cách tạo objects: imperative (lệnh trực tiếp) và declarative (YAML files).
