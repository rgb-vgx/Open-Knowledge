# Service Object: Cách Pods Trở Nên Có Thể Truy Cập Được

Pods chạy containers bên trong cluster, nhưng làm thế nào để thế giới bên ngoài (hoặc các Pods khác) có thể truy cập được chúng? Đó chính là lúc **Service** phát huy tác dụng.

## Vấn đề: Pods là ephemeral và có IP thay đổi

Mỗi Pod có một cluster-internal IP address. Tuy nhiên, có hai vấn đề lớn:

1. **IP thay đổi liên tục** — khi Pod bị thay thế (do crash, scaling, hoặc update), nó nhận IP mới
2. **Không thể truy cập từ bên ngoài cluster** — IP này chỉ dùng trong nội bộ cluster

Điều này khiến việc tìm và kết nối đến Pods trở nên cực kỳ khó khăn.

## Giải pháp: Service

**Service** groups các Pods lại với nhau và cung cấp một **địa chỉ IP tĩnh** (stable endpoint) không bao giờ thay đổi.

```
Thế giới bên ngoài
       ↓
   Service (IP tĩnh)
       ↓
┌──────────────────────────────┐
│         Cluster              │
│  ┌─────┐ ┌─────┐ ┌─────┐   │
│  │Pod 1│ │Pod 2│ │Pod 3│   │
│  └─────┘ └─────┘ └─────┘   │
└──────────────────────────────┘
```

### Service làm gì?

- **Cung cấp IP tĩnh** — endpoints không thay đổi dù Pods có bị thay thế
- **Load balancing** — phân phối traffic đều đến tất cả Pods trong Service
- **Expose ra bên ngoài** — cho phép truy cập từ ngoài cluster (tùy loại Service)

## Các loại Service

### 1. ClusterIP (Mặc định)

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: ClusterIP  # Mặc định, có thể bỏ qua
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080
```

- **Chỉ truy cập được từ bên trong cluster**
- Phù hợp cho internal services (database, cache, etc.)
- IP static được phân bổ trong range của cluster

### 2. NodePort

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: NodePort
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080
    nodePort: 30007  # Port trên mỗi node
```

- **Truy cập qua IP của bất kỳ node nào** kèm theo nodePort
- Port range: 30000-32767 (mặc định)
- Phù hợp cho development/testing

### 3. LoadBalancer

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: LoadBalancer
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080
```

- **Tạo external load balancer** (nếu cloud provider hỗ trợ)
- Phân phối traffic đều đến tất cả Pods
- Phù hợp cho production

> **Lưu ý với Minikube:** LoadBalancer type sẽ luôn hiển thị `EXTERNAL-IP: pending`. Dùng `minikube service <service-name>` để truy cập.

### 4. ExternalName

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: ExternalName
  externalName: my.database.example.com
```

- Map Service đến một DNS name bên ngoài
- Không có proxy, chỉ redirect DNS

## Ví dụ thực tế

Tạo Service cho Deployment:

```bash
# Cách imperative
kubectl expose deployment first-app --port=80 --type=LoadBalancer --target-port=8080

# Kiểm tra
kubectl get services
```

```
NAME         TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)        AGE
first-app    LoadBalancer   10.96.45.123    <pending>     80:31234/TCP   30s
kubernetes   ClusterIP      10.96.0.1       <none>        443/TCP        5m
```

Với Minikube:

```bash
minikube service first-app
```

Lệnh này sẽ mở trình duyệt với URL truy cập ứng dụng của bạn.

## Kết luận

Service giải quyết vấn đề Pods ephemeral bằng cách cung cấp endpoints tĩnh. ClusterIP cho nội bộ cluster, NodePort cho development, LoadBalancer cho production. Hiểu rõ các loại Service giúp bạn thiết kế networking phù hợp cho ứng dụng.

---

**Tóm tắt:** Service cung cấp IP tĩnh cho Pods, giải quyết vấn đề IP thay đổi. ClusterIP (internal only), NodePort (truy cập qua node), LoadBalancer (external LB). Minikube dùng `minikube service` để truy cập Service type LoadBalancer.
