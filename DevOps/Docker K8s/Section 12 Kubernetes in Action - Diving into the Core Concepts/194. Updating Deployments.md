# Cập Nhật Deployments: Rolling Updates Không Downtime

Khi code của bạn thay đổi, bạn cần cập nhật ứng dụng đang chạy. Kubernetes giúp bạn làm điều này mà **không gây downtime** nhờ cơ chế **rolling updates**.

## Quy trình cập nhật

### Bước 1: Thay đổi code

Sửa đổi source code của bạn. Ví dụ: thêm đoạn text mới vào trang chủ.

### Bước 2: Rebuild Docker Image

```bash
# Rebuild image với tag mới
docker build -t your-dockerhub-username/kub-first-app:2 .

# Push lên Docker Hub
docker push your-dockerhub-username/kub-first-app:2
```

> **Quan trọng:** Luôn dùng tags khác nhau cho mỗi version. Nếu dùng cùng tag "latest", Kubernetes sẽ không detect thay đổi.

### Bước 3: Cập nhật Deployment

```bash
kubectl set image deployment/first-app \
  kub-first-app=your-dockerhub-username/kub-first-app:2
```

Giải thích:
- `deployment/first-app`: Tên deployment cần update
- `kub-first-app=tên-image-mới`: Container name = image mới

### Bước 4: Theo dõi tiến trình

```bash
kubectl rollout status deployment/first-app
```

```
deployment "first-app" successfully rolled out
```

### Bước 5: Xác nhận

Truy cập ứng dụng trong trình duyệt — bạn sẽ thấy nội dung mới!

Kiểm tra Pods:

```bash
kubectl get pods
```

```
NAME                        READY   STATUS    RESTARTS   AGE
first-app-6d4f5b8c9-new12   1/1     Running   0          30s
```

## Rolling Updates hoạt động như thế nào?

```
Trước update:  Pod v1, Pod v1, Pod v1
                    ↓
Giai đoạn 1:   Pod v1, Pod v1, Pod v2 (đang tạo)
                    ↓
Giai đoạn 2:   Pod v1, Pod v2, Pod v2 (đang terminate Pod v1)
                    ↓
Sau update:     Pod v2, Pod v2, Pod v2
```

Kubernetes:
1. Tạo Pod mới với image mới
2. Đợi Pod mới ready
3. Tắt Pod cũ
4. Lặp lại cho tất cả Pods

**Kết quả:** Ứng dụng luôn khả dụng trong suốt quá trình update.

## Lỗi khi update

Nếu image tag không tồn tại:

```bash
kubectl rollout status deployment/first-app
```

```
Waiting for deployment "first-app" rollout to finish: 1 out of 3 new replicas have been updated...
```

Pod mới không thể start vì image không tồn tại. Nhưng Pod cũ vẫn đang chạy — ứng dụng không bị downtime!

Để hủy update có vấn đề:

```bash
kubectl rollout undo deployment/first-app
```

## Kết luận

Rolling updates là cách Kubernetes cập nhật ứng dụng không downtime. Luôn dùng tags riêng cho mỗi version để Kubernetes detect thay đổi. Dùng `kubectl rollout status` để theo dõi và `kubectl rollout undo` nếu cần hủy.

---

**Tóm tắt:** Cập nhật bằng `kubectl set image deployment/name container=new-image:tag`. Luôn dùng tags riêng. Theo dõi bằng `kubectl rollout status`, hủy bằng `kubectl rollout undo`. Rolling updates đảm bảo không downtime.
