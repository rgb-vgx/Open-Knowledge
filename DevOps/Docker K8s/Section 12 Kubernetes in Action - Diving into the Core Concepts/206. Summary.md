# Tóm Tắt Module: Kubernetes Core Concepts

Chúc mừng bạn đã hoàn thành module đầu tiên về Kubernetes thực hành! Hãy cùng ôn lại những gì đã học.

## Những gì bạn đã học

### 1. Setup & Installation

- **kubectl** — công cụ giao tiếp với cluster (cài trên máy cục bộ)
- **Minikube** — tạo cluster cục bộ trong VM cho development
- Kiểm tra bằng `minikube status` và `minikube dashboard`

### 2. Kubernetes Architecture

- Kubernetes **KHÔNG quản lý infrastructure** — bạn tạo machines, Kubernetes quản lý containers
- **Master node** (Control Plane) — quản lý cluster
- **Worker nodes** — chạy containers
- **kubelet** — agent trên mỗi node

### 3. Core Objects

- **Pod** — đơn vị nhỏ nhất, chứa containers, là ephemeral
- **Deployment** — controller quản lý Pods (self-healing, rolling updates, scaling)
- **Service** — expose Pods, cung cấp IP tĩnh, load balancing

### 4. Working with Kubernetes

**Imperative approach:**

```bash
kubectl create deployment my-app --image=nginx
kubectl expose deployment my-app --port=80 --type=LoadBalancer
kubectl scale deployment my-app --replicas=3
kubectl set image deployment/my-app my-app=new-image:tag
kubectl rollout undo deployment/my-app
```

**Declarative approach:**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-app
        image: nginx
```

```bash
kubectl apply -f deployment.yaml
```

### 5. Labels & Selectors

- **Labels** — key-value pairs gắn metadata cho resources
- **Selectors** — chọn resources dựa trên labels
- Dùng `-l` flag để filter resources trong commands

### 6. Liveness Probes

- Kiểm tra health containers bằng HTTP GET, TCP socket, exec command, hoặc gRPC
- Configure: initialDelaySeconds, periodSeconds, timeoutSeconds, failureThreshold

### 7. Configuration Options

- imagePullPolicy, environment variables, resource requests/limits
- Command/args overrides, ports, volume mounts

## Tại sao declarative approach được khuyến nghị?

- Dễ maintain — tất cả cấu hình trong YAML files
- Version control — commit lên Git
- Ít lỗi hơn — chỉ cần thay đổi file và apply lại
- Kubernetes tự detect thay đổi và cập nhật

## Bước tiếp theo

Bạn đã có nền tảng vững chắc. Tiếp theo, chúng ta sẽ đi sâu vào:

- **Networking** — cách Pods giao tiếp với nhau và thế giới bên ngoài
- **Volumes** — persist data trong Kubernetes
- **ConfigMaps & Secrets** — quản lý cấu hình và sensitive data
- **Namespaces** — tổ chức resources
