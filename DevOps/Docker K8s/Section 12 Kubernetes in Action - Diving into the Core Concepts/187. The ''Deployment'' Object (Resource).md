# Deployment Object: Bộ Não Quản Lý Pods Trong Kubernetes

Nếu Pod là đơn vị chạy containers, thì Deployment là **bộ não** quản lý tất cả. Hiểu rõ Deployment là chìa khóa để làm việc hiệu quả với Kubernetes.

## Tại sao không tạo Pods trực tiếp?

Bạn hoàn toàn có thể tạo Pods bằng tay và chạy chúng trên worker nodes. Nhưng tại sao không nên làm vậy?

Vì khi đó bạn sẽ phải:

1. **Tự chọn node** — quyết định node nào đủ tài nguyên
2. **Tự monitor** — kiểm tra xem Pods có đang chạy không
3. **Tự restart** — nếu container crash, bạn phải tự khởi động lại
4. **Tự scale** — khi traffic tăng, tự thêm Pods thủ công
5. **Tự xử lý updates** — mỗi lần code thay đổi, phải redeploy thủ công

Deployment giải quyết tất cả những vấn đề này.

## Deployment hoạt động như thế nào?

Deployment là một **controller object** — nó continuously theo dõi trạng thái hiện tại và so sánh với trạng thái mong muốn (desired state).

```
Trạng thái mong muốn (Deployment spec)
    ↓
Kubernetes API Server
    ↓
Scheduler phân Pods vào nodes
    ↓
Kubelet trên each node khởi động containers
    ↓
Kubernetes monitor health của Pods
```

### Ví dụ cụ thể

Khi bạn tạo Deployment với `replicas: 3`:

1. Kubernetes tạo 3 Pods
2. Đặt chúng trên các worker nodes có đủ resources
3. Monitor health của từng Pod
4. Nếu một Pod crash → tự động tạo Pod thay thế
5. Nếu một node chết → tự động di chuyển Pods sang node khác

## Các tính năng quan trọng của Deployment

### 1. Self-healing (Tự phục hồi)

Khi container trong Pod gặp lỗi:

```bash
kubectl get pods
# NAME                        READY   STATUS    RESTARTS   AGE
# my-app-6d4f5b8c9-abc12     1/1     Running   0          5m
```

Nếu Pod crash, bạn sẽ thấy:

```bash
kubectl get pods
# NAME                        READY   STATUS    RESTARTS   AGE
# my-app-6d4f5b8c9-xyz34     1/1     Running   1          2m
# (RESTARTS tăng từ 0 lên 1)
```

Kubernetes tự động restart container mà không cần can thiệp.

### 2. Rolling Updates

Khi bạn cập nhật image của containers:

```bash
kubectl set image deployment/my-app my-app=my-app:v2
```

Kubernetes sẽ:
1. Tạo Pod mới với image mới
2. Đợi Pod mới ready
3. Tắt Pod cũ
4. Lặp lại cho tất cả Pods

**Kết quả:** Ứng dụng luôn khả dụng trong suốt quá trình update.

### 3. Rollbacks

Nếu update có vấn đề, bạn có thể quay lại phiên bản trước:

```bash
kubectl rollout undo deployment/my-app
```

Hoặc quay về revision cụ thể:

```bash
kubectl rollout history deployment/my-app
kubectl rollout undo deployment/my-app --to-revision=1
```

### 4. Scaling

Thay đổi số lượng Pods:

```bash
kubectl scale deployment/my-app --replicas=5
```

Hoặc autoscaling dựa trên CPU:

```bash
kubectl autoscale deployment/my-app --min=2 --max=10 --cpu-percent=80
```

## Quan hệ giữa Deployment và Pods

Một Deployment quản lý một **Pod template** — tức là tất cả Pods được tạo ra đều giống hệt nhau (cùng container image, cùng config).

Nếu bạn muốn chạy nhiều loại containers khác nhau, bạn cần **nhiều Deployments**.

```
Deployment A → Pod 1, Pod 2, Pod 3 (cùng image A)
Deployment B → Pod 4, Pod 5 (cùng image B)
```

## Kết luận

Deployment là object quan trọng nhất trong Kubernetes. Nó giúp bạn quản lý vòng đời của Pods một cách tự động — từ tạo, monitor, restart, scale, cho đến update và rollback. Luôn sử dụng Deployment thay vì tạo Pods trực tiếp.

---

**Tóm tắt:** Deployment là controller object quản lý Pods. Nó cung cấp self-healing, rolling updates, rollbacks, và scaling. Luôn tạo Deployment thay vì Pods trực tiếp để tận dụng tự động hóa.
