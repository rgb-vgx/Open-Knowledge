# Tạo Service Declaratively: Expose Pods Từ YAML File

Bạn đã biết cách expose deployment bằng imperative命令. Bây giờ chúng ta sẽ làm tương tự nhưng với declarative approach — viết service.yaml file.

## Tạo service.yaml

```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend
spec:
  selector:
    app: second-app
  ports:
  - protocol: TCP
    port: 80
    targetPort: 8080
  type: LoadBalancer
```

### Giải thích

#### apiVersion

```yaml
apiVersion: v1
```

Service thuộc **core group** nên chỉ cần `v1`, không cần prefix.

#### kind

```yaml
kind: Service
```

#### metadata.name

```yaml
metadata:
  name: backend
```

Tên Service (tùy bạn đặt).

#### spec.selector

```yaml
spec:
  selector:
    app: second-app
```

**Quan trọng:** Service selector chọn Pods, không phải Deployments. Tất cả Pods có label `app: second-app` sẽ thuộc về Service này.

#### spec.ports

```yaml
spec:
  ports:
  - protocol: TCP
    port: 80
    targetPort: 8080
```

- **protocol**: TCP (mặc định) hoặc UDP
- **port**: Port mà Service lắng nghe (externally)
- **targetPort**: Port mà container đang chạy (internally)

#### spec.type

```yaml
spec:
  type: LoadBalancer
```

Các loại: ClusterIP (mặc định), NodePort, LoadBalancer.

## Áp dụng Service

```bash
kubectl apply -f service.yaml
```

Kiểm tra:

```bash
kubectl get services
```

```
NAME         TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)        AGE
backend      LoadBalancer   10.96.45.123    <pending>     80:31234/TCP   30s
```

## Truy cập ứng dụng

Với Minikube:

```bash
minikube service backend
```

Trình duyệt mở với URL truy cập ứng dụng.

## So sánh imperative vs declarative

### Imperative

```bash
kubectl expose deployment first-app --port=80 --type=LoadBalancer --target-port=8080
```

### Declarative

```yaml
apiVersion: v1
kind: Service
metadata:
  name: backend
spec:
  selector:
    app: second-app
  ports:
  - port: 80
    targetPort: 8080
  type: LoadBalancer
```

```bash
kubectl apply -f service.yaml
```

Declarative approach dễ maintain hơn vì tất cả cấu hình nằm trong file.

## Kết luận

Tạo Service declaratively giúp bạn dễ maintain và share cấu hình. Selector xác định Pods nào thuộc về Service. Luôn dùng declarative approach cho production.

---

**Tóm tắt:** Service YAML gồm apiVersion (v1), kind (Service), metadata (tên), spec (selector, ports, type). Selector chọn Pods thuộc về Service. Dùng `kubectl apply -f` để tạo Service.
