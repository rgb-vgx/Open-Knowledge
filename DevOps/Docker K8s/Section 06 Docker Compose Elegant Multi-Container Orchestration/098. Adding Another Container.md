# Thêm Container Frontend Vào Docker Compose

Đến phần cuối cùng — container frontend chạy React SPA.

## Cấu Hình Frontend Service

```yaml
services:
  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    volumes:
      - ./frontend/src:/app/src
    stdin_open: true
    tty: true
    depends_on:
      - backend
```

### Giải thích từng phần

**`build: ./frontend`** — Build image từ Dockerfile trong thư mục `frontend`.

**`ports: ["3000:3000"]`** — Publish port 3000. Truy cập `http://localhost:3000` trên trình duyệt.

**`volumes`** — Bind mount thư mục `src` của frontend. Đây là tính năng hot reload — khi bạn sửa code React trên host, thay đổi sẽ tức thì trong container mà không cần restart.

**`stdin_open: true` và `tty: true`** — Hai tùy chọn này tương đương với `-it` trong `docker run`. Cần thiết cho React development server để chạy ở interactive mode. Dù bạn chạy detached mode (`-d`), React vẫn cần biết rằng nó có thể nhận input.

**`depends_on`** — Frontend phụ thuộc vào backend. Docker Compose sẽ khởi chạy backend trước, rồi mới đến frontend.

## Docker Compose Info Hoàn Chỉnh

```yaml
version: "3.8"

services:
  mongodb:
    image: "mongo"
    volumes:
      - data:/data/db
    environment:
      MONGO_INITDB_ROOT_USERNAME: max
      MONGO_INITDB_ROOT_PASSWORD: secret

  backend:
    build: ./backend
    ports:
      - "80:80"
    volumes:
      - logs:/app/logs
      - ./backend:/app
      - /app/node_modules
    env_file:
      - ./env/backend.env
    depends_on:
      - mongodb

  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    volumes:
      - ./frontend/src:/app/src
    stdin_open: true
    tty: true
    depends_on:
      - backend

volumes:
  data:
  logs:
```

## Khởi Chạy Toàn Bộ

```bash
docker compose up -d
```

Docker Compose sẽ:
1. Tạo network mặc định
2. Tạo named volumes `data` và `logs`
3. Pull image `mongo` từ Docker Hub
4. Build image backend từ Dockerfile
5. Build image frontend từ Dockerfile
6. Khởi chạy cả ba containers theo đúng thứ tự phụ thuộc

Truy cập `http://localhost:3000` — bạn sẽ thấy ứng dụng hoạt động hoàn chỉnh.

## Dọn Dẹp

```bash
docker compose down
```

Toàn bộ containers và network sẽ bị xóa, nhưng dữ liệu trong volumes vẫn được giữ lại. Khi chạy lại `docker compose up`, ứng dụng sẽ khởi động nhanh hơn nhiều vì images đã được build từ trước.

## Tại Sao Docker Compose Tuyệt Vời?

So sánh:

**Trước đây:** 10+ lệnh Docker riêng lẻ, copy-paste vào terminal
**Bây giờ:** 1 file cấu hình + 2 lệnh `up`/`down`

Docker Compose đặc biệt hữu ích khi:
- Ứng dụng gồm nhiều container
- Bạn cần thay đổi cấu hình thường xuyên
- Bạn muốn chia sẻ môi trường phát triển với đồng đội
- Bạn muốn tái sử dụng cấu hình giữa các môi trường

## Tóm Tắt

- Docker Compose xử lý cả ba container chỉ với một file cấu hình
- **`stdin_open`** và **`tty`** cho interactive mode
- **`depends_on`** đảm bảo thứ tự khởi chạy
- Docker Compose thông minh — chỉ rebuild images khi cần
- Dữ liệu volume vẫn tồn tại sau khi dừng services
