# Cấu Hình Chi Tiết File Docker Compose

Hãy đi sâu vào cấu hình cho từng service, bắt đầu với MongoDB.

## Cấu Hình MongoDB

Trong bài trước, chúng ta khởi chạy MongoDB bằng lệnh `docker run` khá dài với image `mongo`, network, volume named `data`, và các biến môi trường. Bây giờ, hãy chuyển tất cả sang Docker Compose.

```yaml
version: "3.8"

services:
  mongodb:
    image: "mongo"
    volumes:
      - data:/data/db
    environment:
      MONGO_INITDB_ROOT_USERNAME: max
      MONGO_INITDB_ROOT_PASSWORD: secret
```

### Giải thích từng phần

**`image: "mongo"`** — Chỉ định image Docker Hub cần sử dụng. Tương tự `docker run mongo`. Bạn có thể dùng:
- Tên image ngắn: `"mongo"`
- URL đầy đủ registry: `"docker.io/library/mongo"`
- Image tùy chỉnh của bạn: `"myrepo/my-image"`

**`volumes`** — Mount named volume `data` vào `/data/db` bên trong container. Cú pháp `data:/data/db` giống hệt `docker run -v data:/data/db`.

**`environment`** — Đặt biến môi trường. Có hai cách viết:

Cách 1 — Object (key-value):
```yaml
environment:
  MONGO_INITDB_ROOT_USERNAME: max
  MONGO_INITDB_ROOT_PASSWORD: secret
```

Cách 2 — List:
```yaml
environment:
  - MONGO_INITDB_ROOT_USERNAME=max
  - MONGO_INITDB_ROOT_PASSWORD=secret
```

### Sử Dụng File Environment

Nếu不想hardcode biến môi trường trực tiếp trong file compose, bạn có thể dùng `env_file`:

```yaml
services:
  mongodb:
    image: "mongo"
    env_file:
      - ./env/mongo.env
```

File `mongo.env`:
```
MONGO_INITDB_ROOT_USERNAME=max
MONGO_INITDB_ROOT_PASSWORD=secret
```

Điều này đặc biệt hữu ích khi bạn muốn loại bỏ secrets khỏi file cấu hình hoặc exclude file `.env` khỏi git repository.

## Named Volume — Khai Báo Level Top

Với Docker Compose, named volume cần được khai báo ở level top-level (cùng cấp với `services`):

```yaml
services:
  mongodb:
    image: "mongo"
    volumes:
      - data:/data/db

volumes:
  data:
```

Phần `volumes` ở level top — dù trông có vẻ kỳ lạ với giá trị rỗng — là cách Docker Compose biết rằng nó cần tạo named volume `data`. Nếu bạn dùng nhiều services dùng chung volume này, dữ liệu sẽ được share giữa các container.

Lưu ý: **Bind mount** và **anonymous volume** không cần khai báo ở level top.

## Mạng (Network)

Tin tốt: bạn **không cần** cấu hình network khi dùng Docker Compose. Khi bạn chạy `docker compose up`, Docker tự động tạo một network mặc định và thêm tất cả services vào đó. Tất cả container trong cùng một compose file đều có thể giao tiếp với nhau qua tên service.

Nếu muốn dùng network tùy chỉnh:

```yaml
services:
  mongodb:
    image: "mongo"
    networks:
      - goals-net

networks:
  goals-net:
```

Nhưng trong hầu hết trường hợp, network mặc định là đủ.

## Tổng Hợp MongoDB Config

```yaml
version: "3.8"

services:
  mongodb:
    image: "mongo"
    volumes:
      - data:/data/db
    environment:
      MONGO_INITDB_ROOT_USERNAME: max
      MONGO_INITDB_ROOT_PASSWORD: secret

volumes:
  data:
```

Vậy là xong cấu hình cho MongoDB. Đơn giản hơn rất nhiều so với lệnh `docker run` dài dòng đúng không?

## Tóm Tắt

- **`image`** — Chỉ định image cho container
- **`volumes`** — Mount volume (named volume cần khai báo ở level top)
- **`environment`** — Đặt biến môi trường (hoặc dùng `env_file`)
- **Network mặc định** — Docker Compose tự tạo, không cần cấu hình thêm

Trong bài tiếp theo, chúng ta sẽ tìm hiểu cách khởi chạy và dừng dịch vụ.
