# Quản Lý Nhiều Container Với Docker Compose

Đã đến lúc cấu hình service backend — phần Node.js API. Đây là phần thú vị vì chúng ta cần build image từ Dockerfile.

## Cấu Hình Backend Service

```yaml
version: "3.8"

services:
  mongodb:
    image: "mongo"
    volumes:
      - data:/data/db
    environment:
      MONGO_INITDB_ROOT_USERNAME: max
      MONGO_INITDB_ROOT_PASSWORD: secret

  backend:
    build: ./backend
    ports:
      - "80:80"
    volumes:
      - logs:/app/logs
      - ./backend:/app
      - /app/node_modules
    env_file:
      - ./env/backend.env
    depends_on:
      - mongodb

volumes:
  data:
  logs:
```

### Giải thích từng phần

**`build: ./backend`** — Thay vì chỉ định image có sẵn, chúng ta yêu cầu Docker Compose build image từ Dockerfile trong thư mục `backend`. Docker Compose sẽ:
1. Tìm file `Dockerfile` trong thư mục `backend`
2. Build image từ Dockerfile đó
3. Sử dụng image vừa build cho container backend

Cú pháp ngắn gọn này phù hợp khi Dockerfile của bạn tên là `Dockerfile`. Nếu tên khác, dùng dạng dài:

```yaml
backend:
  build:
    context: ./backend
    dockerfile: Dockerfile-dev
    args:
      NODE_VERSION: 18
```

**`ports: ["80:80"]`** — Publish port 80 từ container ra host. Tương tự `-p 80:80`.

**`volumes`** — Ba loại volume khác nhau:

1. **Named volume:** `logs:/app/logs` — Lưu log持久化. Cần khai báo `logs` ở level top-level.

2. **Bind mount:** `./backend:/app` — Share code từ host vào container. Ưu điểm lớn: sử dụng đường dẫn tương đối thay vì đường dẫn tuyệt đối dài ngoằng.

3. **Anonymous volume:** `/app/node_modules` — Ngăn bind mount ghi đè thư mục `node_modules`. Không cần khai báo ở level top.

**`env_file`** — Đọc biến môi trường từ file `./env/backend.env`. File này chứa:

```
MONGODB_USERNAME=max
MONGODB_PASSWORD=secret
```

**`depends_on`** — Khai báo phụ thuộc: backend chỉ khởi chạy SAU KHI mongodb đã sẵn sàng. Nếu không có `depends_on`, cả hai container có thể khởi chạy cùng lúc, và backend có thể fail vì chưa kết nối được MongoDB.

## Tên Service Trong Code

Điểm quan trọng: tên service (ví dụ `mongodb`, `backend`) chính là tên DNS mà bạn sử dụng trong code để kết nối giữa các container. Trong file `app.js` của backend, khi kết nối MongoDB, bạn dùng tên `mongodb` — chính là tên service trong compose file.

Docker Compose tạo tên container tự động theo mẫu `{project_name}_{service_name}_{index}`, ví dụ `docker-compose_backend_1`. Nhưng tên service vẫn hoạt động như DNS alias.

## Kiểm Tra Kết Quả

```bash
docker compose up -d
docker ps
```

Bạn sẽ thấy hai container đang chạy:
- `docker-compose_mongodb_1`
- `docker-compose_backend_1`

```bash
docker compose logs backend
```

Kiểm tra log của backend — bạn sẽ thấy thông báo kết nối MongoDB thành công.

## Tóm Tắt

- **`build`** — Build image từ Dockerfile thay vì dùng image có sẵn
- **`ports`** — Publish port từ container ra host
- **`volumes`** — Hỗ trợ named volume, bind mount, và anonymous volume
- **`env_file`** — Đọc biến môi trường từ file bên ngoài
- **`depends_on`** — Đảm bảo thứ tự khởi chạy giữa các services
- **Tên service = DNS name** trong mạng Docker Compose

Trong bài tiếp theo, chúng ta sẽ thêm frontend vào hệ thống.
