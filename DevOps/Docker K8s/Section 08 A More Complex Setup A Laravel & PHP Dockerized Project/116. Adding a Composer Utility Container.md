# Thêm Container Composer: Utility Container Quản Lý Package PHP

## Composer Là Gì?

Composer là công cụ quản lý dependency cho PHP, hoạt động tương tự NPM trong Node.js. Với Composer, bạn có thể:

- Cài đặt Laravel và các framework PHP khác
- Quản lý các package third-party
- Tự động autoload class

## Tại Sao Cần Container Riêng Cho Composer?

Bạn có thể cài Composer trên máy cục bộ, nhưng sử dụng Docker container sẽ:

1. **Đảm bảo phiên bản Composer đồng nhất** giữa các thành viên trong team
2. **Không cần cài Composer trên host machine**
3. **Tách biệt môi trường** — Composer chạy trong container riêng, không ảnh hưởng đến system

## Tạo Dockerfile Cho Composer

Tạo file `dockerfiles/composer.dockerfile`:

```dockerfile
FROM composer:latest

WORKDIR /var/www/html

ENTRYPOINT [ "composer", "--ignore-platform-reqs" ]
```

### Giải thích

- **`FROM composer:latest`** — Image chính thức của Composer từ Docker Hub
- **`WORKDIR /var/www/html`** — Thư mục làm việc, đồng nhất với PHP container
- **`ENTRYPOINT`** — Mỗi lệnh chạy trong container sẽ tự động thêm flag `--ignore-platform-reqs`. Flag này giúp Composer bỏ qua việc kiểm tra platform requirements, tránh lỗi khi một số extension chưa được cài đặt.

## Cấu Hình Docker Compose

```yaml
services:
  composer:
    build:
      context: ./dockerfiles
      dockerfile: composer.dockerfile
    volumes:
      - ./src:/var/www/html:delegated
```

## Sử Dụng Container Composer

Để chạy Composer trong container:

```bash
docker compose run --rm composer [command]
```

Ví dụ:
- `docker compose run --rm composer install` — Cài đặt dependencies từ `composer.json`
- `docker compose run --rm composer update` — Cập nhật dependencies

Tùy chọn `--rm` đảm bảo container sẽ bị xóa ngay sau khi thực thi xong, tránh tình trạng "dead containers" tích tụ.

## Thư Mục Cấu Trúc

```
project/
├── docker-compose.yaml
├── dockerfiles/
│   ├── php.dockerfile
│   └── composer.dockerfile
├── nginx/
│   └── nginx.conf
├── env/
│   └── mysql.env
└── src/
```

## Kết Luận

Container Composer là utility container — chỉ chạy khi cần và tự động xóa sau khi hoàn thành. Với bind mount `./src:/var/www/html`, mọi file được Composer tạo ra trong container sẽ ngay lập tức xuất hiện trên host machine trong thư mục `src/`. Đây là nguyên tắc hoạt động chung của tất cả utility containers trong thiết lập này.
