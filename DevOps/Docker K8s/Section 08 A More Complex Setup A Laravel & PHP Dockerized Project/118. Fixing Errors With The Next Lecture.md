# Khắc Phục Lỗi Permission Trên Linux

## Vấn Đề Gặp Phải

Khi sử dụng Docker trên Linux, bạn có thể gặp lỗi **permission denied** khi bind mount source code vào container. Đây là vấn đề phổ biến liên quan đến quyền truy cập file giữa host machine và container.

## Giải Pháp

### 1. Cập Nhật php.dockerfile

Thêm user `laravel` vào Dockerfile để đảm bảo quyền truy cập đồng nhất:

```dockerfile
FROM php:8.2.4-fpm-alpine

WORKDIR /var/www/html

COPY src .

RUN docker-php-ext-install pdo pdo_mysql

RUN addgroup -g 1000 laravel && adduser -G laravel -g laravel -s /bin/sh -D laravel

USER laravel
```

**Thay đổi quan trọng:**
- Tạo group `laravel` với GID 1000
- Tạo user `laravel` thuộc group `laravel`
- Sử dụng `USER laravel` để mọi lệnh chạy với quyền của user này
- **Bỏ qua** dòng `RUN chown` — thay vào đó dùng user riêng

### 2. Cập Nhật composer.dockerfile

Áp dụng tương tự cho Composer container:

```dockerfile
FROM composer:2.5.7

RUN addgroup -g 1000 laravel && adduser -G laravel -g laravel -s /bin/sh -D laravel

USER laravel

WORKDIR /var/www/html

ENTRYPOINT [ "composer", "--ignore-platform-reqs" ]
```

## Tại Sao Lại Xảy Ra Lỗi?

Trên Linux, mỗi user có một UID (User ID) riêng. Khi container tạo file với user root (UID 0), các container khác chạy với user khác sẽ không có quyền truy cập那些 file.

Bằng cách tạo user `laravel` với UID/GID đồng nhất (1000) trên tất cả container, chúng ta đảm bảo:

- Container Composer tạo file → thuộc user `laravel` (UID 1000)
- Container PHP đọc/ghi file → cũng chạy với user `laravel` (UID 1000)
- Không có xung đột quyền truy cập

## Kiểm Tra Lại

Sau khi cập nhật Dockerfile, rebuild image:

```bash
docker compose up -d --build
```

Chạy lại Composer để tạo Laravel project và kiểm tra không còn lỗi permission.

## Kết Luận

Vấn đề permission là một trong những lỗi phổ biến nhất khi làm việc với Docker trên Linux. Giải pháp nằm ở việc đồng nhất user/group giữa các container — đây là best practice mà bạn nên áp dụng cho mọi dự án Docker multi-container.
