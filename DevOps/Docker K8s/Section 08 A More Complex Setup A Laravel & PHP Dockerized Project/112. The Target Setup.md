# Kiến Trúc Mục Tiêu: 6 Container Cho Laravel Application

## Tại Sao Laravel & PHP Khác Với Node.js?

Một trong những điểm khác biệt lớn nhất giữa Laravel/PHP và Node.js nằm ở cách chúng xử lý web server:

- **Node.js**: Chính Node.js vừa là ngôn ngữ lập trình vừa là runtime server. Bạn viết code JavaScript và Node.js xử lý cả logic application lẫn server.
- **PHP/Laravel**: Bạn cần **tách biệt** — PHP chỉ là ngôn ngữ interpreter, bạn cần thêm một web server (Nginx) để xử lý request HTTP và chuyển tiếp cho PHP interpreter chạy.

Đây là lý do tại sao thiết lập Laravel trên máy cục bộ trở nên phức tạp — bạn phải cài đặt, cấu hình và phối hợp nhiều công cụ riêng biệt.

## Kiến Trúc Container Mục Tiêu

Dưới đây là kiến trúc hoàn chỉnh mà chúng ta sẽ xây dựng:

```
┌─────────────────────────────────────────────────┐
│                  Host Machine                     │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │           Source Code Folder (src/)          │ │
│  └──────────────────┬──────────────────────────┘ │
│                     │ (Bind Mount)                │
│  ┌──────────────────▼──────────────────────────┐ │
│  │           Docker Compose Network             │ │
│  │                                              │ │
│  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  │ │
│  │  │  Nginx   │──│   PHP    │──│  MySQL   │  │ │
│  │  │ (Server) │  │(FPM)     │  │ (Database)│  │ │
│  │  └──────────┘  └──────────┘  └──────────┘  │ │
│  │       │              │                       │ │
│  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  │ │
│  │  │ Composer │  │ Artisan  │  │   NPM    │  │ │
│  │  │(Utility) │  │(Utility) │  │(Utility) │  │ │
│  │  └──────────┘  └──────────┘  └──────────┘  │ │
│  └──────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

### 3 Application Containers

Đây là các container chạy liên tục khi ứng dụng hoạt động:

1. **Nginx (Server)** — Nhận request từ bên ngoài, chuyển tiếp các file PHP đến container PHP interpreter
2. **PHP (FPM)** — Thực thi code Laravel/PHP, trả về response
3. **MySQL** — Lưu trữ dữ liệu, giao tiếp với PHP container qua mạng Docker

### 3 Utility Containers

Đây là các container chạy khi cần thực hiện tác vụ cụ thể:

1. **Composer** — Quản lý package PHP (tương tự NPM). Dùng để cài đặt Laravel và các dependency
2. **Artisan** — Công cụ CLI của Laravel, dùng để chạy migrations, seed data, và nhiều tác vụ khác
3. **NPM** — Xử lý front-end assets (JavaScript, CSS)

## Điểm Quan Trọng

- Tất cả containers trong cùng một docker-compose file sẽ **tự động nằm trong cùng mạng** và có thể **tìm thấy nhau bằng tên service**. Ví dụ: PHP container có thể kết nối MySQL bằng tên `mysql`.
- **Source code** trên host machine sẽ được **bind mount** vào các container, giúp bạn chỉnh sửa code trực tiếp và thấy thay đổi ngay lập tức.
- Utility containers chỉ chạy khi cần, không chạy liên tục như application containers.

## Kết Luận

Kiến trúc này có vẻ phức tạp, nhưng đó chính là điểm mấu chốt của Docker — tách biệt từng phần thành các container riêng biệt, mỗi container đảm nhiệm một trách nhiệm cụ thể. Phương pháp này giúp dễ bảo trì, mở rộng và triển khai ứng dụng.
