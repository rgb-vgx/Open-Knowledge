# Docker Container vs Máy Ảo (VM): Cuộc Chiến Kiến Trúc Trong Kỷ Nguyên Cloud

Nếu bạn đã đọc phần trước, chúng ta đã thống nhất rằng: việc tạo ra môi trường đóng gói, nhất quán và có thể tái sử dụng là chìa khóa giải quyết lời nguyền *"It works on my machine"*.

Đến đây, nếu bạn là kỹ sư đã có kinh nghiệm với hạ tầng truyền thống, có thể bạn sẽ đặt câu hỏi: *"Đợi đã! Chẳng phải Machine ảo (VM) cũng làm được điều tương tự sao?"*.

Câu trả lời là: **Có.** Nhưng cách nó giải quyết giống như việc bạn **thuê nguyên một chiếc Boeing 747 chỉ để chở một thùng mì tôm**.

---

## Giải Phẫu "Căn Bệnh" Của Máy Ảo

VM hoạt động bằng phần mềm gọi là **Hypervisor** (VMware, Hyper-V) chạy trên Host OS. Hypervisor "cắt" phần cứng vật lý thành những cỗ máy nhỏ hơn.

**Vấn đề cốt tử:** Mỗi VM bắt buộc phải cài đặt một **Hệ điều hành khách (Guest OS)** độc lập.

Giả sử bạn có server vật lý cần chạy 3 backend services. Nếu dùng VM, bạn phải tạo 3 máy ảo. Mỗi máy ảo cài 1 bản Linux Ubuntu:

- Mỗi Guest OS "ngốn" khoảng 1-2GB RAM ngay cả khi chưa chạy dòng code nào
- Khởi động mất từ vài chục giây đến vài phút (phải boot hệ điều hành hoàn chỉnh)
- Lãng phí hàng chục GB dung lượng ổ cứng cho công cụ hệ thống thừa thãi

Đây gọi là **"Guest OS Tax" (Thuế hệ điều hành)** — sự lãng phí tài nguyên khủng khiếp khi scale-up hệ thống.

---

## Cú Lột Xác Của Docker: Kiến Trúc Không Guest OS

Docker loại bỏ hoàn toàn tầng Guest OS cồng kềnh. Thay vì ảo hóa *phần cứng*, Docker ảo hóa ở cấp độ *hệ điều hành*.

Nền tảng là **Docker Engine** — một service cực nhẹ chạy trên Host OS. Khi khởi chạy 3 container cho 3 backend services, **tất cả đều dùng chung Kernel của Host OS**.

Docker Engine sử dụng các cơ chế của Linux Kernel (`Namespaces` để cách ly tiến trình, `Cgroups` để giới hạn RAM/CPU) tạo ra ảo giác rằng mỗi app đang chạy trên máy riêng biệt.

**Kết quả mang tính hủy diệt:**

| Đặc điểm | Virtual Machine | Docker Container |
|---|---|---|
| Kích thước | Hàng GB | Vài chục đến vài trăm MB |
| Khởi động | Vài chục giây - vài phút | Vài mili-giây |
| Hiệu năng | Bị hao hụt qua Hypervisor | Gần native performance |
| Guest OS | Cần 1 Guest OS riêng | Không cần |

## Infrastructure as Code & Khả Năng Chia Sẻ

Một nhược điểm cực lớn của VM là tính thủ công. Để chia sẻ VM cho đồng nghiệp, bạn phải clone nguyên ổ cứng ảo `.vmdk` hoặc `.ova` nặng chục GB.

Với Docker, mọi thứ được định nghĩa qua dòng text nhẹ nhàng trong **`Dockerfile`**:

1. **Dockerfile:** Bản thiết kế mô tả cách xây dựng môi trường
2. **Image:** Kết quả của `docker build` — gói read-only đóng băng toàn bộ code, runtime và OS layer
3. **Container:** Thực thể sống được khởi tạo từ Image

### Code Snippet: Sức mạnh Alpine Linux

Thay vì cài cả cục Ubuntu 2GB, đây là cách Backend Go-lang được đóng gói với Alpine:

```dockerfile
FROM alpine:3.18
RUN apk --no-cache add ca-certificates
WORKDIR /app
COPY my-go-backend .
EXPOSE 8080
CMD ["./my-go-backend"]
```

Bạn chỉ cần gửi file `Dockerfile` (vài Kilobyte) hoặc push Image lên Registry (Docker Hub/AWS ECR). Bất kỳ ai pull về chạy cũng mất chưa tới 1 phút.

## Best Practices & Cạm Bẫy

### Cạm bẫy 1: Cầm nhầm Container thành Máy ảo (Anti-pattern)

**Sai lầm:** Cấu hình SSH daemon, chạy `systemd`, cài Cronjob, Database và App API vào chung **một** container. SSH vào container sửa code bằng `vim`.

**Best Practice:** Tính Bất biến (Immutability). Container chạy một process duy nhất. Nếu code lỗi, **tuyệt đối không sửa code bên trong container**. Sửa source, build Image mới, xóa Container cũ và chạy Container mới.

### Cạm bẫy 2: "Docker thay thế hoàn toàn Máy ảo"

Trong thực tế production, Container và VM **bổ trợ cho nhau**. Bạn không cắm Docker thẳng vào phần cứng vật lý (Bare-metal). Thay vào đó, thuê VM trên Cloud (AWS EC2, Google Compute Engine) để tạo lớp ranh giới bảo mật, sau đó cài Docker Engine lên các VM đó và chạy hàng chục Container bên trong.

### Cạm bẫy 2: Quản lý OS Layer bị "Phình To"

Đừng bao giờ dùng `FROM ubuntu:latest` nếu không thực sự cần. Tập thói quen sử dụng `alpine` hoặc `scratch` cho ngôn ngữ biên dịch. Kích thước image nhỏ = Pull nhanh = Deploy nhanh = Giảm rủi ro bảo mật.

## Tóm Tắt

Nếu **Máy ảo** là việc phân lô bán nền phần cứng vật lý thành các máy tính nhỏ hơn, thì **Docker Container** là việc ảo hóa cô lập trực tiếp các ứng dụng ở tầng phần mềm.

Lựa chọn Docker giúp tiết kiệm 90% tài nguyên dư thừa, tăng tốc độ triển khai gấp hàng trăm lần, và biến hệ thống thành các module lắp ghép (microservices) mượt mà nhất.
