# "Hello World" Kiểu DevOps: Khởi Chạy Container Đầu Tiên Của Bạn

Nếu bạn là Backend Engineer đã quen setup môi trường truyền thống (cài cắm Runtime, config biến môi trường, tải dependencies), bài viết hôm nay sẽ mang đến trải nghiệm mang tính "ma thuật". Chúng ta sẽ khởi chạy một web server hoàn chỉnh mà **không hề cài đặt ngôn ngữ lập trình lên máy chủ**. Đây chính là sức mạnh cốt lõi của Docker: "Zero-Install Environment".

---

## Tại Sao Phải Đóng Gói?

Lấy ví dụ thực tế: dummy backend service viết bằng **Node.js** sử dụng tính năng `top-level await` (gọi DB connection giả lập trước khi khởi động server).

Vấn đề: Cú pháp này **chỉ được hỗ trợ từ Node.js 14.3 trở lên**.

- **Cách truyền thống:** Tải đúng phiên bản 14.3+ về máy, chạy `npm install`, rồi gõ `node app.mjs`. Nếu máy đang dùng Node 12 cho dự án legacy, xung đột ngay lập tức.
- **Cách DevOps:** Khoanh vùng dự án bằng Docker, nhét mã nguồn và đúng phiên bản Node.js cần thiết vào container. Host OS vẫn sạch sẽ.

## Giải Phấu Dockerfile: Trái Tim Của Quá Trình Build

Để Docker biết cách tạo môi trường, chúng ta cần `Dockerfile` — file text thuần túy (không có đuôi mở rộng).

Hai khái niệm sinh tử trong Docker:

1. **Image (Ảnh tĩnh):** Gói read-only chứa toàn bộ OS layer, runtime, thư viện và code. Giống đĩa cài game ngày xưa. Tuân thủ **OCI Image Specification**.
2. **Container (Thực thể sống):** Process đang chạy được khởi tạo từ Image. Giống lúc bạn đang chơi game.

### Dockerfile chuẩn mực cho Node.js

```dockerfile
# 1. Base Image: Nền móng
FROM node:14.17-alpine

# 2. Workdir: Thư mục làm việc trong Container
WORKDIR /app

# 3. Copy file cấu hình thư viện trước (Best Practice Cache)
COPY package.json .

# 4. Cài Dependencies
RUN npm install

# 5. Copy toàn bộ source code
COPY . .

# 6. Khai báo cổng (Document purpose)
EXPOSE 3000

# 7. Lệnh chạy khi Container KHỞI CHẠY (không phải lúc Build)
CMD ["node", "app.mjs"]
```

## Build Image và Khởi Chạy Container

Mở Terminal tại thư mục chứa source code và Dockerfile. Đảm bảo Docker Engine đang hoạt động.

### Bước 1: Build Image

```bash
docker build -t my-first-node-app .
```

- `docker build`: Lệnh tạo Image
- `-t my-first-node-app`: Đặt tên cho Image (nếu không có `-t`, Docker sinh ra ID vô nghĩa như `7d9a1...`)
- `.` (Dấu chấm): Chỉ định Build Context — tìm Dockerfile ở thư mục hiện tại

### Bước 2: Run Container

```bash
docker run -p 3000:3000 my-first-node-app
```

**Under the hood của cờ `-p` (Port Binding):**

Network của Container bị cách ly hoàn toàn với bên ngoài. `EXPOSE 3000` trong Dockerfile chỉ mang tính tài liệu hóa. Để truy cập được, bạn phải dùng `-p <Host_Port>:<Container_Port>`.

- `3000` (trái): Cổng trên máy thật (localhost)
- `3000` (phải): Cổng app đang chạy bên trong Container

Terminal sẽ bị "treo" — chứng tỏ web server đang chạy trên port 3000. Mở trình duyệt truy cập `http://localhost:3000`, bạn sẽ thấy dòng chữ `"Hi there!"`.

**Bạn vừa chạy thành công app Node.js mà máy bạn không hề có Node.js!**

### Bước 3: Quản Lý và Dọn Dẹp

```bash
docker build -t my-first-node-app:1.0.0 .
docker run --name node-demo -p 3000:3000 my-first-node-app:1.0.0
docker stop node-demo
docker rm node-demo
```

`docker stop` không xóa container; nó chỉ dừng process. `docker rm` mới xóa container và writable layer.

### Dockerfile Instructions Cần Nắm Chắc

| Instruction | Vai trò | Lưu ý production |
|---|---|---|
| `FROM` | Chọn base image, mở đầu build stage | Pin version hoặc digest; tránh `latest` |
| `COPY` | Copy file local vào image | Ưu tiên dùng cho source/config |
| `ADD` | Copy như COPY + URL/tar | Chỉ dùng khi thật sự cần tính năng thêm |
| `CMD` | Default command khi container chạy | Bị override ở `docker run` hoặc K8s `command/args` |
| `ENTRYPOINT` | Command chính khó thay đổi | Nên dùng exec form `["binary", "arg"]` |
| `HEALTHCHECK` | Health check cấp Docker | Trong K8s dùng liveness/readiness/startup probe |

`CMD` và `ENTRYPOINT` thường đi cùng: `ENTRYPOINT` là binary chính, `CMD` là default arguments. Dùng exec form để nhận signal đúng.

Xem các Container đang chạy:

```bash
docker ps
```

Tắt server gọn gàng:

```bash
docker stop <container_name_hoặc_container_id>
```

## Best Practices & Cạm Bẫy

### 1. Dùng ID thay vì Tag (Lỗi người mới)

Tutorials đôi khi bảo bạn copy ID loằng ngoằng rồi chạy `docker run <ID>`. Trong CI/CD, không ai làm vậy. Luôn dùng `-t` để đặt tên (`repo/app-name:version`) khi build.

### 2. Thứ Tự COPY Sinh Tử (Layer Caching)

Tại sao tách `COPY package.json` rồi `RUN npm install`, sau đó mới `COPY . .`?

Docker build Image theo từng "Lớp" (Layer). Nếu layer không đổi, Docker dùng cache để build siêu nhanh. Source code thay đổi liên tục, nhưng `package.json` rất ít đổi. Nếu gom `COPY . .` trước lệnh `RUN`, mỗi lần sửa 1 dấu phẩy trong code, Docker phải hì hục tải lại toàn bộ thư viện từ đầu.

### 3. Tạo `.dockerignore`

Giống Git, Docker có file `.dockerignore`. Luôn thêm `node_modules`, `.git`, `.env` vào đó. Ngăn "rác" từ máy local lọt vào Container, vừa giảm dung lượng image, vừa tiềm ẩn rủi ro lộ thông tin bảo mật.

### 4. Không chạy root nếu không cần thiết

Thêm user không đặc quyền trong image và chạy bằng `USER`. Đây là bước nền để khi lên Kubernetes bạn bật `runAsNonRoot`, `allowPrivilegeEscalation: false` và Pod Security `restricted` dễ dàng hơn.

## Tóm Tắt

Chỉ với hai lệnh `docker build` và `docker run`, bạn đã hoàn tất vòng đời cơ bản nhất của một ứng dụng Containerized. Đẹp nhất là sau toàn bộ quá trình, Host OS vẫn nguyên vẹn — không tàn dư cài đặt, không rác thư viện.

Chạy web server đứng trơ trọi chỉ là bước dạo đầu. Trong thực tế, service cần lưu trữ data, gọi cấu hình bên ngoài hay nói chuyện với Database. Đó là lúc giải bài toán **Volumes** và **Networking** ở các phần tiếp theo.
