# So sánh Volumes vs Persistent Volumes: Khi nào dùng loại nào?

## Cả hai đều giúp Persist Dữ liệu

Điểm quan trọng nhất cần nhớ: **Cả regular volumes lẫn persistent volumes đều giúp bảo toàn dữ liệu.** Tên gọi "persistent" không có nghĩa chỉ PV mới persist được — cả hai đều giúp dữ liệu tồn tại qua các lần container restart.

## Regular Volumes: Đơn giản, gắn với Pod

Regular volumes được định nghĩa **trong cùng file YAML với pod** (trong pod template của Deployment):

```yaml
# Trong deployment.yaml
spec:
  template:
    spec:
      containers:
        - name: app
          volumeMounts:
            - name: data
              mountPath: /app/data
      volumes:
        - name: data
          emptyDir: {}
```

**Ưu điểm:**
- Đơn giản, dễ cấu hình
- Đủ dùng cho development và small apps
- Không cần quản lý riêng biệt

**Nhược điểm:**
- Volume definition gắn liền với pod → cần lặp lại trong mỗi deployment
- Pod-dependent — mất khi pod bị xóa (emptyDir)
- Khó quản lý tập trung khi có nhiều pods

## Persistent Volumes: Mạnh mẽ, Độc lập

Persistent Volumes được định nghĩa **riêng biệt**, sử dụng qua Persistent Volume Claims:

```yaml
# host-pv.yaml - Định nghĩa một lần
apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv
spec:
  capacity:
    storage: 5Gi
  accessModes:
    - ReadWriteOnce
  hostPath:
    path: /data
  storageClassName: standard
```

```yaml
# host-pvc.yaml - Pod sử dụng qua claim
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  volumeName: my-pv
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
  storageClassName: standard
```

**Ưu điểm:**
- Pod-independent và Node-independent
- Quản lý tập trung — define once, use everywhere
- Phân tách trách nhiệm: Admin quản lý PV, Dev dùng PVC
- Phù hợp production cluster

**Nhược điểm:**
- Phức tạp hơn
- Có thể overkill cho demo project

## Nên dùng loại nào?

| Tiêu chí | Regular Volume | Persistent Volume |
|---|---|---|
| Development/Testing | ✅ Phù hợp | Có thể overkill |
| Small project, 1 developer | ✅ Phù hợp | Có thể overkill |
| Production cluster | ⚠️ Hạn chế | ✅ Nên dùng |
| Nhiều developers teams | ⚠️ Khó quản lý | ✅ Phù hợp |
| Multi-node cluster | ⚠️ hostPath hạn chế | ✅ Cloud storage |
| Data quan trọng, không được mất | ⚠️ Pod-dependent | ✅ Đảm bảo persist |

> **Tóm tắt:** Không có loại nào tốt hơn — tùy vào project. Development cá nhân → regular volumes. Production team với nhiều pods/nodes → persistent volumes.
