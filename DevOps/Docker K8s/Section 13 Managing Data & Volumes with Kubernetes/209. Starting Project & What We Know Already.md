# Demo App: Xây dựng ứng dụng Note.js đơn giản trên Kubernetes

## Tổng quan ứng dụng

Để minh họa cách quản lý dữ liệu trong Kubernetes, chúng ta sẽ bắt đầu với một ứng dụng Node.js cực kỳ đơn giản — một API ghi chú (notes) cho phép người dùng lưu và đọc dữ liệu.

Ứng dụng gồm một file `app.js` duy nhất, trong đó:

- **Server** lắng nghe trên port `3000`
- **GET /story** — đọc dữ liệu từ file `story/text.txt` và trả về cho client
- **POST /story** — nhận JSON body chứa field `text`, kiểm tra rỗng, rồi append nội dung vào file `story/text.txt`

```javascript
// app.js - tóm tắt cấu trúc
const express = require('express');
const fs = require('fs');
const path = require('path');

const app = express();
const STORY_PATH = path.join(__dirname, 'story', 'text.txt');

app.get('/story', (req, res) => {
  // Đọc file và trả về nội dung
});

app.post('/story', (req, res) => {
  // Kiểm tra text không rỗng, append vào file
});

app.listen(3000);
```

## Chạy thử với Docker Compose

Để chạy ứng dụng này trước khi deploy lên Kubernetes, bạn có thể dùng Docker Compose với volume đã cấu hình sẵn:

```bash
docker-compose up -d --build
```

Sử dụng Postman hoặc curl để test:

```bash
# Gửi dữ liệu
curl -X POST http://localhost/story -H "Content-Type: application/json" -d '{"text": "Hello từ Docker!"}'

# Đọc dữ liệu
curl http://localhost/story
```

Vì đã cấu hình volume trong `docker-compose.yml`, dữ liệu sẽ tồn tại ngay cả khi container bị xóa:

```bash
# Dừng và xóa container
docker-compose down
docker container prune

# Khởi động lại — dữ liệu vẫn còn!
docker-compose up -d
```

## Chuyển sang Kubernetes

Đó là những gì bạn đã biết từ phần Docker. Bây giờ, câu hỏi đặt ra là: **làm thế nào để đạt được hiệu quả tương tự khi deploy lên Kubernetes cluster?** Khi mà bạn không trực tiếp chạy `docker run` hay `docker-compose up` nữa, mà để Kubernetes quản lý pods cho bạn?

Đó chính là nội dung mà chúng ta sẽ tìm hiểu tiếp theo.

> **Tóm tắt:** Dữ liệu trong container sẽ bị mất khi container bị xóa. Volumes giúp dữ liệu tồn tại qua các lần restart. Và trong Kubernetes, cách thức tạo và quản lý volumes sẽ khác hoàn toàn so với Docker local.
