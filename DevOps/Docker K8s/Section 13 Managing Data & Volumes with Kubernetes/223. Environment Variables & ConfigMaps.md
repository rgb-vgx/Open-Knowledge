# ConfigMaps trong Kubernetes: Quản lý Cấu hình Tập trung

## Vấn đề với Env trực tiếp

Khi set env variables trực tiếp trong container spec, bạn vẫn cần sửa deployment YAML mỗi khi thay đổi cấu hình. Và nếu nhiều pods cần cùng env variables, bạn phải lặp lại trong mỗi pod spec.

**ConfigMap** giải quyết vấn đề này bằng cách tạo một resource riêng chứa key-value pairs, sau đó pods truy xuất values từ ConfigMap.

## Tạo ConfigMap

Tạo file `environment.yaml`:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: data-store-env
data:
  folder: "story"
```

```bash
kubectl apply -f environment.yaml

# Kiểm tra
kubectl get configmap
```

## Sử dụng ConfigMap trong Pod

Thay vì set value trực tiếp, dùng `valueFrom` với `configMapKeyRef`:

```yaml
containers:
  - name: story
    image: your-dockerhub/kub-data-demo:2
    env:
      - name: STORY_FOLDER
        valueFrom:
          configMapKeyRef:
            name: data-store-env    # Tên ConfigMap
            key: folder             # Key trong ConfigMap
    volumeMounts:
      - name: story-volume
        mountPath: /app/story
```

**Giải thích:**
- `name: STORY_FOLDER` — Tên env variable trong container
- `valueFrom.configMapKeyRef.name` — Tên ConfigMap chứa data
- `valueFrom.configMapKeyRef.key` — Key trong ConfigMap mà bạn muốn lấy value

## Cấu trúc hoàn chỉnh

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: story-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: story
  template:
    metadata:
      labels:
        app: story
    spec:
      containers:
        - name: story
          image: your-dockerhub/kub-data-demo:2
          env:
            - name: STORY_FOLDER
              valueFrom:
                configMapKeyRef:
                  name: data-store-env
                  key: folder
          volumeMounts:
            - name: story-volume
              mountPath: /app/story
      volumes:
        - name: story-volume
          persistentVolumeClaim:
            claimName: host-pvc
```

## Áp dụng

```bash
# Tạo ConfigMap trước
kubectl apply -f environment.yaml

# Áp dụng deployment
kubectl apply -f deployment.yaml

# Kiểm tra pods mới
kubectl get pods
```

## So sánh các cách set Env

| Cách | Ưu điểm | Nhược điểm |
|---|---|---|
| `value` trực tiếp | Đơn giản | Cần sửa YAML khi thay đổi |
| `configMapKeyRef` | Tập trung, tái sử dụng | Cần tạo ConfigMap riêng |
| `secretKeyRef` | An toàn cho sensitive data | Cần tạo Secret riêng |

## ConfigMap có thể chứa nhiều data

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  folder: "story"
  max-file-size: "10485760"
  allowed-types: "txt,json"
```

Mỗi key sẽ tương ứng một env variable riêng trong pod.

> **Tóm tắt:** ConfigMap tách biệt configuration khỏi application code. Pods truy xuất values từ ConfigMap qua `valueFrom.configMapKeyRef`. Giúp quản lý cấu hình tập trung, dễ thay đổi và tái sử dụng.
