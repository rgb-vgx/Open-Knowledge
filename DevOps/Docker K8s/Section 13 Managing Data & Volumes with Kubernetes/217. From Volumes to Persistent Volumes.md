# Từ Volumes đến Persistent Volumes: Giải pháp Lưu trữ Độc lập

## Vấn đề với Regular Volumes

Sau khi tìm hiểu `emptyDir` và `hostPath`, chúng ta thấy rõ hạn chế:

- **`emptyDir`** — Dữ liệu mất khi pod bị xóa
- **`hostPath`** — Chỉ hoạt động trên một node duy nhất

Trong production cluster với nhiều nodes, cả hai loại đều không đủ. Pods có thể chạy trên nhiều node khác nhau, và khi một pod bị replaced, dữ liệu trong volume có thể bị mất.

## Persistent Volumes: Giải pháp tách biệt Storage khỏi Pod

**Persistent Volume (PV)** là một resource độc lập trong cluster — **không gắn liền với bất kỳ pod hay node nào.** Nó được tạo và quản lý riêng biệt, tồn tại độc lập khỏi pod lifecycle.

### Cách hoạt động

```
┌─────────────────────────────────────────┐
│              Kubernetes Cluster          │
│                                         │
│  ┌──────────┐      ┌─────────────────┐  │
│  │   Pod A  │─────▶│                 │  │
│  └──────────┘      │  Persistent     │  │
│                    │  Volume (PV)    │  │
│  ┌──────────┐      │                 │  │
│  │   Pod B  │─────▶│  (cloud/NFS)    │  │
│  └──────────┘      └─────────────────┘  │
│                                         │
└─────────────────────────────────────────┘
```

Pods sử dụng **Persistent Volume Claims (PVC)** để "đặt hàng" dung lượng từ PV. Pods không cần biết PV được lưu ở đâu — chỉ cần claim đúng dung lượng cần thiết.

## Tại sao cần Persistent Volumes?

1. **Độc lập với Pod** — Dữ liệu tồn tại ngay cả khi pod bị xóa
2. **Độc lập với Node** — Dữ liệu lưu ở storage bên ngoài cluster (cloud storage, NFS...)
3. **Quản lý tập trung** — Định nghĩa volume một lần, sử dụng ở nhiều pods
4. **Kiểm soát dung lượng** — Admin có thể quản lý dung lượng có sẵn cho cluster

## Persistent Volume Types

Không phải mọi volume type đều phù hợp cho PV. `emptyDir` và `hostPath` (trên multi-node cluster) bị loại trừ. Các type phù hợp bao gồm:

- Cloud storage: `awsElasticBlockStore`, `azureDisk`, `gcePersistentDisk`
- Network storage: `nfs`, `cephfs`, `glusterfs`
- CSI drivers: linh hoạt nhất, hỗ trợ mọi loại storage

> **Tóm tắt:** Persistent Volumes tách biệt storage khỏi pod và node, đảm bảo dữ liệu không bị mất. Pods sử dụng Persistent Volume Claims để truy cập PV — tạo một lớp trừu tượng giữa application và infrastructure.
