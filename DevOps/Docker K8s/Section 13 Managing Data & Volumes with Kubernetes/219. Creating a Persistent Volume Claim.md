# Persistent Volume Claim: Cách Pods "đặt hàng" Lưu trữ

## Persistent Volume Claim là gì?

Sau khi tạo Persistent Volume (PV), pods không thể trực tiếp sử dụng nó. Pods cần tạo một **Persistent Volume Claim (PVC)** —类似于 đơn hàng yêu cầu dung lượng từ PV.

PVC định nghĩa: "Tôi cần X dung lượng, với Y quyền truy cập, từ class Z."

## Cấu hình PVC

Tạo file `host-pvc.yaml`:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: host-pvc
spec:
  volumeName: host-pv
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
  storageClassName: standard
```

## Giải thích từng phần

### volumeName — Chỉ định PV cụ thể

```yaml
volumeName: host-pv
```

Liên kết PVC với PV cụ thể. Trong thực tế, bạn có thể bỏ qua `volumeName` và Kubernetes sẽ tự tìm PV phù hợp dựa trên `accessModes`, `resources`, và `storageClassName`.

### accessModes

```yaml
accessModes:
  - ReadWriteOnce
```

Phải khớp với ít nhất một access mode mà PV hỗ trợ.

### resources.requests.storage

```yaml
resources:
  requests:
    storage: 1Gi
```

Yêu cầu dung lượng. Không được phép yêu cầu nhiều hơn capacity của PV.

### storageClassName

```yaml
storageClassName: standard
```

Phải khớp với `storageClassName` của PV.

## Liên kết PVC với Pod

Sau khi tạo PVC, pods sử dụng nó thông qua `persistentVolumeClaim` volume type:

```yaml
spec:
  containers:
    - name: story
      image: your-dockerhub/kub-data-demo:1
      volumeMounts:
        - name: story-volume
          mountPath: /app/story
  volumes:
    - name: story-volume
      persistentVolumeClaim:
        claimName: host-pvc
```

**Lưu ý:** `volumeMounts` vẫn giữ nguyên — chỉ thay đổi cách định nghĩa volume từ `hostPath` sang `persistentVolumeClaim`.

## Áp dụng và Kiểm tra

```bash
# Tạo PV trước
kubectl apply -f host-pv.yaml

# Tạo PVC
kubectl apply -f host-pvc.yaml

# Kiểm tra PV và PVC
kubectl get pv
kubectl get pvc

# Áp dụng deployment
kubectl apply -f deployment.yaml
```

Khi cả PV và PVC được tạo thành công:
- PV status chuyển sang `Bound`
- PVC status cũng chuyển sang `Bound`
- Pod có thể ghi/đọc dữ liệu qua volume

## Quy trình đầy đủ

```
Persistent Volume (PV)     Persistent Volume Claim (PVC)     Pod
┌──────────────────┐      ┌──────────────────────┐      ┌────────────┐
│ storage: 1Gi     │◀─────│ storage: 1Gi         │◀─────│ volumeMount│
│ hostPath: /data  │      │ volumeName: host-pv  │      │ /app/story │
│ RWO              │      │ RWO                  │      │            │
└──────────────────┘      └──────────────────────┘      └────────────┘
```

> **Tóm tắt:** PVC là cầu nối giữa Pod và PV. Pod yêu cầu dung lượng qua PVC, PVC tìm và gắn với PV phù hợp. Điều này giúp tách biệt application logic khỏi infrastructure.
