# emptyDir Volume trong Kubernetes: Tạo Volume Đơn giản nhất

## Vấn đề: Dữ liệu mất khi Container restart

Để minh họa rõ ràng vấn đề, hãy thêm một route lỗi vào ứng dụng demo:

```javascript
// Thêm vào app.js
app.get('/error', (req, res) => {
  process.exit(1); // Crash container
});
```

Sau khi rebuild image với tag mới, apply deployment lại. Khi gửi request tới `/error`, container sẽ crash và Kubernetes sẽ restart nó — nhưng **dữ liệu đã bị mất** vì chưa có volume nào.

## Giải pháp: Sử dụng emptyDir

`emptyDir` tạo một thư mục trống mới mỗi khi pod start, và giữ nó tồn tại cho đến khi pod bị xóa. Container có thể ghi dữ liệu vào thư mục này, và dữ liệu sẽ **sống sót qua các lần container restart.**

### Cấu hình Volume trong Pod Spec

Volume được định nghĩa ở **cùng cấp với containers** trong pod spec:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: story-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: story
  template:
    metadata:
      labels:
        app: story
    spec:
      containers:
        - name: story
          image: your-dockerhub/kub-data-demo:1
          volumeMounts:          # Mount volume vào container
            - name: story-volume
              mountPath: /app/story
      volumes:                   # Định nghĩa volume
        - name: story-volume
          emptyDir: {}
```

### Giải thích cấu trúc

1. **`volumes`** — Đặt ở cấp pod spec (cùng cấp với `containers`), liệt kê tất cả volumes của pod
2. **`volumeMounts`** — Đặt ở cấp container, chỉ rõ volume nào được mount vào path nào trong container
3. **`mountPath: /app/story`** — Path trong container where dữ liệu được ghi (tương ứng với working directory + thư mục `story` trong code)

### Kết quả

Sau khi apply:

```bash
kubectl apply -f deployment.yaml
```

- Gửi POST request → dữ liệu được ghi vào volume ✅
- Gửi request `/error` → container crash, restart → **dữ liệu vẫn còn!** ✅
- Gửi GET request → đọc được dữ liệu đã lưu ✅

## emptyDir hoạt động như thế nào?

- Pod start → tạo thư mục trống mới
- Container ghi dữ liệu vào thư mục qua `mountPath`
- Container restart → dữ liệu giữ nguyên (vì volume thuộc pod, không thuộc container)
- Pod bị xóa → thư mục bị xóa, dữ liệu mất

> **Tóm tắt:** `emptyDir` là loại volume đơn giản nhất, đủ dùng cho development. Nó giải quyết vấn đề container restart nhưng không giải quyết vấn đề pod replacement — dữ liệu vẫn mất khi pod bị xóa.
