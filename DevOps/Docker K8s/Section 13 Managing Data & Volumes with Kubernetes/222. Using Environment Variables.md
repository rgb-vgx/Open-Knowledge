# Environment Variables trong Kubernetes: Cấu hình Ứng dụng Linh hoạt

## Tại sao cần Environment Variables?

Trong ứng dụng demo, tên thư mục `story` bị hard-coded trong code. Nếu muốn thay đổi, phải sửa code và rebuild image. **Environment variables** giải quyết vấn đề này bằng cách externalize cấu hình.

## Cách sử dụng Env trong Kubernetes

### Cách 1: Định nghĩa trực tiếp trong Container Spec

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: story-deployment
spec:
  replicas: 1
  selector:
    matchLabels:
      app: story
  template:
    metadata:
      labels:
        app: story
    spec:
      containers:
        - name: story
          image: your-dockerhub/kub-data-demo:2
          env:
            - name: STORY_FOLDER
              value: "story"
          volumeMounts:
            - name: story-volume
              mountPath: /app/story
      volumes:
        - name: story-volume
          persistentVolumeClaim:
            claimName: host-pvc
```

Trong code, truy cập env variable:

```javascript
// Thay vì hard-coded "story"
const STORY_FOLDER = process.env.STORY_FOLDER || 'story';
const filePath = path.join(__dirname, STORY_FOLDER, 'text.txt');
```

### Cách 2: Sử dụng ConfigMap (Xem bài tiếp theo)

## Cấu trúc Env

```yaml
env:
  - name: KEY_NAME          # Tên biến
    value: "value_here"     # Giá trị
  - name: DATABASE_URL
    value: "mongodb://localhost:27017"
  - name: API_KEY
    value: "abc123"
```

Mỗi env variable gồm `name` và `value`. Pod sẽ có các biến môi trường này khi container start.

## Áp dụng và Kiểm tra

```bash
# Rebuild image với code mới (sử dụng env variable)
docker build -t your-dockerhub/kub-data-demo:2 .
docker push your-dockerhub/kub-data-demo:2

# Apply deployment
kubectl apply -f deployment.yaml

# Kiểm tra pods mới
kubectl get pods
```

Ứng dụng giờ sử dụng `STORY_FOLDER` env variable thay vì hard-coded. Nếu muốn thay đổi tên thư mục, chỉ cần sửa trong YAML — không cần rebuild image.

## Ưu điểm

- **Linh hoạt** — Thay đổi cấu hình mà không cần rebuild image
- **An toàn hơn** — Không hard-code sensitive values trong code
- **Tách biệt** — Code và configuration tách rời nhau
- **Khả năng tái sử dụng** — Cùng image, nhiều cấu hình khác nhau

> **Tóm tắt:** Environment variables giúp externalize cấu hình khỏi code. Trong Kubernetes, dùng `env` trong container spec để set biến môi trường. Cách tiếp theo sẽ dùng ConfigMap để quản lý env variables tập trung hơn.
