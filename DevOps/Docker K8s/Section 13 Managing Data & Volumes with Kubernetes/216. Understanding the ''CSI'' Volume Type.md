# CSI Volume Type: Giao diện Lưu trữ linh hoạt nhất trong Kubernetes

## CSI là gì?

**CSI** viết tắt của **Container Storage Interface** — đây là một giao diện tiêu chuẩn do Kubernetes team thiết kế để kết nối với mọi loại storage bên thứ ba mà không cần phải thêm built-in type riêng cho từng dịch vụ.

## Tại sao cần CSI?

Trước khi có CSI, Kubernetes cần thêm từng volume type riêng cho mỗi cloud provider: `awsElasticBlockStore`, `azureDisk`, `gcePersistentDisk`... Điều này gây ra vấn đề: nếu một dịch vụ storage mới ra mắt, Kubernetes cần cập nhật source code để hỗ trợ nó.

CSI giải quyết vấn đề này bằng cách **định nghĩa một giao diện chung.** Bất kỳ ai — cloud provider, công ty storage, hoặc developer — đều có thể viết driver tích hợp với giao diện này.

## Ví dụ thực tế: AWS EFS

Giả sử bạn muốn dùng Amazon EFS (Elastic File System) để lưu trữ dữ liệu. EFS là một NFS service trên AWS, nhưng không có built-in type nào cho AWS EFS trong Kubernetes.

Nhờ CSI, AWS đã viết một **CSI driver cho EFS.** Bạn chỉ cần:

1. Cài đặt AWS EFS CSI driver vào cluster
2. Sử dụng volume type `csi` trong pod spec
3. Chỉ đúng driver name và volume handle

```yaml
volumes:
  - name: efs-volume
    csi:
      driver: efs.csi.aws.com
      volumeHandle: fs-xxxxxxxx
```

## CSI drivers phổ biến

- **AWS EFS CSI Driver** — Amazon Elastic File System
- **AWS EBS CSI Driver** — Amazon Elastic Block Store
- **Azure Disk/File CSI Driver** — Microsoft Azure storage
- **GCP PD CSI Driver** — Google Persistent Disk
- **Ceph CSI Driver** — Ceph distributed storage
- **NFS CSI Driver** — Network File System

## Khi nào cần dùng CSI?

- Deploy lên cloud production và cần dùng dịch vụ storage của cloud provider
- Sử dụng storage system riêng trong data center (Ceph, GlusterFS...)
- Cần tích hợp với dịch vụ storage mới mà chưa có built-in type

Trong các bài tiếp theo, chúng ta sẽ chuyển sang **Persistent Volumes** — một concept cao hơn giúp tách biệt hoàn toàn storage khỏi pod và node lifecycle.
