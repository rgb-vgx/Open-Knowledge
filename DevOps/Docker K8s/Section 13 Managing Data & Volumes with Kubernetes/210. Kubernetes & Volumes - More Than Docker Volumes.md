# State trong Kubernetes: Tại sao Dữ liệu không thể bị Mất?

## Khái niệm "State" (Trạng thái)

Trước khi đi sâu vào Kubernetes volumes, cần hiểu rõ thuật ngữ **State** — có thể dịch là "trạng thái", nhưng thực chất là **dữ liệu được tạo và sử dụng bởi ứng dụng mà không được phép bị mất.**

State có hai loại chính:

1. **Dữ liệu do người dùng tạo (User-generated data):** như nội dung story trong ứng dụng demo, tài khoản người dùng, thông tin đơn hàng...
2. **Kết quả trung gian (Intermediate results):** dữ liệu tạm thời, cached results, hoặc các bảng tạm trong database — thường được lưu trong memory và sẽ bị xóa khi cần.

Loại dữ liệu đầu tiên thường được lưu trong database hoặc files — và đây là dữ liệu quan trọng nhất cần được bảo tồn. Loại thứ hai có thể chấp nhận bị mất.

## Tại sao volumes lại cần thiết?

Dù bạn đang dùng Docker local với Docker Compose, hay Kubernetes trên cluster, **volumes luôn là giải pháp để bảo toàn dữ liệu.** Container có thể bị stop, restart, hoặc remove — nhưng dữ liệu không được phép biến mất chỉ vì điều đó. Không có dữ liệu = không có giá trị cho ứng dụng.

## Docker vs Kubernetes: Volumes khác nhau như thế nào?

Với Docker local, bạn quen thuộc với lệnh `docker run -v` hoặc cấu hình volumes trong `docker-compose.yml`. Dữ liệu luôn nằm trên ổ cứng máy local.

Nhưng Kubernetes chạy containers trên **nhiều node machine trong cluster.** Bạn không trực tiếp chạy `docker run` — Kubernetes là người quản lý pods và containers. Vì vậy, bạn cần cấu hình Kubernetes để nó tự thêm volumes vào containers khi khởi chạy.

Điểm khác biệt cốt lõi:

| Docker Local | Kubernetes |
|---|---|
| Bạn trực tiếp quản lý container | Kubernetes quản lý pods & containers |
| Volume nằm trên máy local | Volume có thể nằm ở nhiều nơi: node disk, cloud storage, NFS... |
| Dữ liệu persist khi stop container | Volume lifetime gắn với pod lifecycle |
| Ít cần cấu hình storage linh hoạt | Cần hỗ trợ nhiều loại storage khác nhau |

Vì vậy, Kubernetes có hệ thống volumes mạnh mẽ và linh hoạt hơn Docker rất nhiều — và đó là những gì chúng ta sẽ khám phá ngay sau đây.
