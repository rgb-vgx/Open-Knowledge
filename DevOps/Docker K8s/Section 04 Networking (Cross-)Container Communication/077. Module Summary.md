# Tóm tắt Module: Container Communication & Networks

Module này đã giới thiệu 3 kịch bản giao tiếp chính trong Docker networking. Hãy cùng ôn lại những kiến thức quan trọng.

## 3 Loại Container Communication

### 1. Container → WWW
- **Tự động hoạt động:** Không cần cấu hình đặc biệt
- **Ví dụ:** Container gọi REST API bên thứ ba
- **Key takeaway:** Docker tự xử lý NAT và routing

### 2. Container → Host Machine
- **Giải pháp:** Sử dụng `host.docker.internal`
- **Ví dụ:** Container kết nối MongoDB cài trên host
- **Lưu ý:** Chỉ hoạt động trên Docker Desktop; trên Linux cần `--add-host`

### 3. Container → Container
- **Giải pháp tốt nhất:** Docker Networks
- **Ví dụ:** Container Node.js kết nối Container MongoDB
- **Ưu điểm:** Tên container = domain name, tự động DNS resolution

## Docker Network Drivers

| Driver | Use Case |
|--------|----------|
| **Bridge** | Default, multi-container trên cùng host |
| **Host** | Container dùng host networking |
| **Overlay** | Distributed app nhiều hosts |
| **None** | Maximum isolation |

## Best Practices

1. **Luôn dùng user-defined bridge network** thay vì default bridge
2. **Đặt tên containers rõ ràng** — chúng sẽ become domain names
3. **Không publish port** nếu chỉ cần container-to-container communication
4. **Sử dụng host.docker.internal** cho container-to-host communication

## Điểm quan trọng nhất

> **Container networking hoạt động tự động tại network layer** — Docker không thay đổi source code của bạn, chỉ xử lý request khi rời container.
