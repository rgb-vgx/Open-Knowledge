# Docker IP Resolution: Hiểu cách Docker xử lý tên và IP

Bạn đã thấy Docker tự động phân giải tên container thành IP. Nhưng làm thế nào? Docker không thay đổi source code của bạn — nó hoạt động ở layer network.

## Docker không sửa source code

Điều quan cần hiểu: **Docker không đọc hay thay đổi source code**. Khi bạn viết `mongodb://mongodb:27017`, Docker không tìm và thay thế `mongodb` thành IP trong file code.

## Docker hoạt động ở layer Network

Thay vào đó, Docker kiểm soát **environment network** mà ứng dụng chạy trong đó. Khi container gửi request ra ngoài:

1. **Request rời container:** Docker intercept request tại network layer
2. **Phân giải tên:** Docker DNS server phân giải tên thành IP正确
3. **Route request:** Docker gửi request đến destination正确

Quá trình này diễn ra hoàn toàn tự động tại network layer — application code không bị ảnh hưởng.

## Host.docker.internal hoạt động tương tự

Tương tự, `host.docker.internal` cũng được Docker xử lý tại network layer. Khi container gửi request đến domain này, Docker tự động phân giải thành IP của host machine.

## Browser request: Không bị ảnh hưởng

Nếu request đến từ browser (JavaScript code chạy trong browser), Docker không can thiệp vì request không khởi nguồn từ container. Docker chỉ xử lý request từ bên trong container.

## Kết luận

Docker IP resolution hoạt động hoàn toàn tại network layer — minh bạch, tự động, và không ảnh hưởng đến application code. Đây là lý do tại sao bạn có thể dùng tên container mà không cần lo về underlying networking details!
