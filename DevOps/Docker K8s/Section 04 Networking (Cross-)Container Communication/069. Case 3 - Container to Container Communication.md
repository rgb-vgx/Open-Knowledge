# Container giao tiếp với Container: Multi-Container Architecture

Đây là kịch bản quan trọng nhất trong Docker networking: **Container to Container Communication**. Hầu hết ứng dụng production đều gồm nhiều containers — một container cho app, một cho database, một cho cache, v.v.

## Tại sao Multi-Container là Best Practice?

Docker khuyến khích nguyên tắc **one container = one responsibility**. thay vì cài cả Node.js app và MongoDB trong một container, bạn nên:

- **Container 1:** Node.js API (chỉ chứa code app + dependencies)
- **Container 2:** MongoDB database (chỉ chứa database engine + data)

Cách này giúp dễ bảo trì, scale, và maintain hơn.

## Thách thức ban đầu

Khi chạy 2 containers riêng biệt, chúng không tự động biết nhau. Bạn cần tìm cách để container Node.js kết nối container MongoDB. Có 2 cách tiếp cận:

### Cách 1: Sử dụng IP Address thủ công

```bash
docker inspect mongodb | grep IPAddress
```

Sau đó hardcode IP này vào code Node.js. **Nhược điểm:** IP thay đổi mỗi lần restart container.

### Cách 2: Sử dụng Docker Networks (Recommended)

Tạo network riêng và đưa cả 2 containers vào cùng network. Khi đó, bạn có thể dùng **tên container** thay vì IP — Docker tự động phân giải tên thành IP正确.

Đây là giải pháp elegant và là best practice trong Docker networking!
