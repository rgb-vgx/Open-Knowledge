# Container giao tiếp với Host Machine: Bài toán kết nối local service

Bên cạnh việc gọi API bên ngoài, đôi khi ứng dụng trong container cần kết nối service chạy trực tiếp trên host machine — ví dụ MongoDB database cài trên máy local. Đây chính là kịch bản **Container to Host Machine Communication**.

## Khi nào cần Container → Host?

Trong thực tế, nhiều developers muốn test ứng dụng containerized với database chạy local trước khi container hóa hoàn toàn. Ví dụ: một Node.js API cần kết nối MongoDB đã cài trên host machine.

**Vấn đề:** Mặc định, container không thể truy cập `localhost` của host machine. Khi bạn chạy container, `localhost` trong container trỏ đến chính container đó, không phải host.

## Giải pháp: host.docker.internal

Docker cung cấp domain đặc biệt `host.docker.internal` để giải quyết vấn đề này. Domain này tự động phân giải thành IP address của host machine khi được gọi từ bên trong container.

```javascript
// Thay vì localhost
mongoose.connect('mongodb://localhost:27017/favorites');

// Sử dụng host.docker.internal
mongoose.connect('mongodb://host.docker.internal:27017/favorites');
```

**Lưu ý quan trọng:** `host.docker.internal` hoạt động trên Docker Desktop (Mac/Windows). Trên Linux, bạn cần thêm flag `--add-host=host.docker.internal:host-gateway` khi chạy container.

## Bước tiếp theo

Sau khi hiểu cách container kết nối host, chúng ta sẽ khám phá kịch bản phức tạp hơn: container giao tiếp với container khác — chủ đề chính của phần tiếp theo!
