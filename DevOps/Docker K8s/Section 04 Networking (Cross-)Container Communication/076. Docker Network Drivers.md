# Docker Network Drivers: Hiểu các loại mạng trong Docker

Docker Networks hỗ trợ nhiều network drivers khác nhau, mỗi loại phù hợp với use case riêng. Hiểu rõ các drivers giúp bạn chọn đúng giải pháp networking cho ứng dụng.

## Các Network Drivers chính

### 1. Bridge (Mặc định)

```bash
docker network create --driver bridge my-net
# Hoặc đơn giản (vì bridge là default)
docker network create my-net
```

**Đặc điểm:**
- Containers trong cùng network có thể tìm nhau bằng tên
- Isolation giữa các networks khác nhau
- Phù hợp cho most use cases

### 2. Host

```bash
docker run --network host nginx
```

**Đặc điểm:**
- Container chia sẻ network stack với host
- Không có isolation network
- Container sử dụng IP và ports của host trực tiếp
- Chỉ hoạt động trên Linux và Docker Desktop (opt-in)

### 3. Overlay

```bash
docker network create --driver overlay my-overlay
```

**Đặc điểm:**
- Kết nối containers trên nhiều Docker hosts khác nhau
- Chỉ hoạt động trong Swarm mode
- Dùng cho distributed applications

### 4. Macvlan

```bash
docker network create --driver macvlan my-macvlan
```

**Đặc điểm:**
- Container có MAC address riêng
- Xu hiện như device vật lý trên network
- Phù hợp cho legacy applications

### 5. None

```bash
docker run --network none nginx
```

**Đặc điểm:**
- Tắt hoàn toàn networking
- Container isolated 100%
- Dùng cho security-sensitive workloads

## Khi nào dùng driver nào?

| Use Case | Driver khuyến nghị |
|----------|-------------------|
| Multi-container app trên cùng host | Bridge (user-defined) |
| Container cần host networking | Host |
| Distributed app nhiều hosts | Overlay |
| Legacy app cần MAC address | Macvlan |
| Container cần maximum isolation | None |

## Bridge: Tại sao là default?

Bridge driver cung cấp sự cân bằng tốt nhất giữa isolation và connectivity. Với user-defined bridge, containers có thể:
- Tìm nhau bằng tên (DNS resolution)
- Isolated với networks khác
- Communication dễ dàng trong cùng network

Đây là lý do bridge là default và phù hợp cho hầu hết scenarios!
