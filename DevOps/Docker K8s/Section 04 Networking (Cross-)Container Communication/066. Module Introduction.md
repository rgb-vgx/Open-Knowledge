# Giới thiệu Module: Mạng và Giao tiếp Cross-Container trong Docker

Bạn đã biết cách tạo images, chạy containers và quản lý dữ liệu với volumes. Giờ là lúc bước vào một chủ đề quan trọng không kém: **Docker Networking** — cách các containers giao tiếp với thế giới bên ngoài và với nhau.

## Tại sao Networking lại quan trọng?

Hầu hết các ứng dụng thực tế đều không tồn tại đơn lẻ. Một Node.js API cần kết nối database, một Python service cần gọi REST API của bên thứ ba, hay một microservice cần talk với service khác. Tất cả đều đòi hỏi networking.

Trong module này, chúng ta sẽ khám phá 3 kịch bản giao tiếp chính:

1. **Container → WWW**: Container gọi API bên ngoài (ví dụ: REST API của bên thứ ba)
2. **Container → Host Machine**: Container kết nối service chạy trên host (ví dụ: MongoDB cài trực tiếp trên máy)
3. **Container → Container**: Hai hoặc nhiều containers giao tiếp với nhau trong cùng mạng

## Cảm nhận trước khi bắt đầu

Bạn sẽ học cách Docker xử lý networking một cách tự động — từ việc gán IP, phân giải tên, đến tạo networks riêng biệt cho group containers. Đặc biệt, bạn sẽ hiểu tại sao `host.docker.internal` là domain đặc biệt giúp container truy cập host, và tại sao user-defined bridge network là best practice thay vì default bridge.
