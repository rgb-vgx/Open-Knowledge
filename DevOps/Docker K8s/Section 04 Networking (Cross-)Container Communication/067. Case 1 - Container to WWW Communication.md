# Container giao tiếp với WWW: Kịch bản phổ biến nhất trong Docker

Khi ứng dụng trong container cần gọi API bên ngoài — ví dụ Star Wars API (swapi.dev) — đó chính là kịch bản **Container to WWW Communication**. Đây là hình thức giao tiếp cơ bản và quan trọng nhất mà bạn sẽ gặp thường xuyên.

## Ví dụ thực tế: Node.js gọi Star Wars API

Giả sử bạn có một Node.js application sử dụng Axios để gửi HTTP GET request đến `swapi.dev/api/films`. Ứng dụng này sẽ trả về dữ liệu phim và nhân vật Star Wars.

**Điều quan trọng:** Khi bạn đưa ứng dụng vào container, request HTTP từ bên trong container ra ngoài thế giới web **hoạt động ngay lập tức** — không cần cấu hình đặc biệt nào.

```bash
docker run -p 3000:3000 favorites-node
```

Container có thể gửi request đến bất kỳ web API nào bên ngoài mà không gặp trở ngại. Đây là ưu điểm lớn của Docker networking — bạn không cần lo lắng về cấu hình mạng phức tạp cho kịch bản này.

## Tại sao điều này hoạt động?

Docker sử dụng network driver `bridge` (mặc định) để kết nối container với internet. Khi container gửi request ra ngoài, Docker tự động xử lý NAT (Network Address Translation) và routing qua interface `docker0` trên host machine.

**Tóm tắt:** Container có thể truy cập WWW ngay lập tức — đây là behave mặc định của Docker networking. Bạn chỉ cần đảm bảo container có kết nối internet và mọi thứ sẽ hoạt động!
