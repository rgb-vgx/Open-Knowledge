# Bứt Phá Khỏi Các Pre-built Images: Tư Duy Đóng Gói Ứng Dụng (Custom Images)

Ở bài trước, chúng ta đã chạy thử Image `node` từ Docker Hub và chui vào bên trong nó thông qua cờ `-it`. Chạy được một shell tương tác thì rất thú vị để vọc vạch, nhưng ở môi trường thực tế — nơi chúng ta xử lý hàng nghìn request, định tuyến dữ liệu, hay thiết lập các pipeline kết nối tới Database — việc chỉ mở một cái shell là hoàn toàn vô nghĩa.

Mục tiêu tối thượng của chúng ta là **chạy mã nguồn (code) của chính mình**.

Dù bạn đang viết một service backend tốc độ cao bằng Go, một ứng dụng Python xử lý AI, hay một Web Server bằng Node.js, luồng tư duy kiến trúc luôn tuân theo một quy tắc duy nhất: **Lấy một Base Image (Image nền tảng) chính thức, và "đắp" code của mình lên trên cùng để tạo ra một Custom Image mới.**

## 1. Giải Phẫu Dự Án Mẫu: Từ Local Lên Container

Để thực hành việc Dockerize (đóng gói vào Docker), chúng ta sẽ sử dụng một dummy project viết bằng **Node.js**. Đừng lo lắng nếu bạn không rành về Node, bởi vì kiến trúc hệ thống của mọi ngôn ngữ backend đều chia sẻ chung một DNA.

Hãy xem qua cấu trúc của dự án mẫu này:

* **`server.js`**: Trái tim của ứng dụng. Đây là file khởi chạy một HTTP Web Server lắng nghe ở cổng (port) 80. Nó xử lý một route `GET /` để trả về giao diện HTML, và một route `POST /store-goal` để nhận dữ liệu từ người dùng, lưu vào biến nhớ tạm, sau đó redirect. (Nó đóng vai trò chính xác như hàm `main()` trong file `main.go` của bạn).
* **Thư mục `public/**`: Chứa file `styles.css` để định dạng giao diện tĩnh.
* **`package.json`**: File cực kỳ quan trọng dùng để khai báo metadata và các dependencies (thư viện bên thứ ba) mà ứng dụng cần. Ở dự án này, ta cần framework `express` và thư viện `body-parser`. Tương tự như cách chúng ta khai báo và quản lý các package trong file `go.mod` vậy.

## 2. Nỗi Đau Của Môi Trường Non-Docker (Cách Làm Truyền Thống)

Giả sử bạn vừa clone code này về máy Kubuntu của mình và muốn chạy nó **không dùng Docker**. Quy trình sẽ diễn ra như sau:

1. Mở trình duyệt, truy cập `nodejs.org`, tải file cài đặt Node.js về máy vật lý.
2. Mở terminal tại thư mục code, gõ lệnh `npm install`. Công cụ NPM (Node Package Manager) sẽ đọc file `package.json`, kết nối mạng tải về hàng đống các thư viện con và nhét tất cả vào một thư mục khổng lồ tên là `node_modules`. (Hành động này tương đương với `go mod download`).
3. Cuối cùng, gõ lệnh `node server.js` để chạy server.

**Vấn đề ở đây là gì?**
Cách làm này vấy bẩn trực tiếp lên hệ điều hành Host của bạn. Nếu sau này bạn chạy một project khác yêu cầu phiên bản Node.js cũ hơn, sự xung đột môi trường sẽ lập tức xảy ra. Hơn nữa, khi đưa code này lên production, bạn lại phải lặp lại y hệt 3 bước cài đặt thủ công kia lên máy chủ Linux.

## 3. Tư Duy DevOps: Dọn Dẹp Và Chuẩn Bị Dockerize

Thay vì cài đặt mọi thứ cục bộ, chúng ta sẽ bắt Docker làm tất cả công việc dơ bẩn này bên trong một không gian cô lập.

Nhưng trước tiên, bạn cần phải có một môi trường làm việc thực sự "sạch". Hãy làm theo các bước sau trong Terminal của bạn:

1. Dừng ứng dụng đang chạy cục bộ (nếu có) bằng `Ctrl + C`.
2. **Xóa ngay thư mục `node_modules**` (nếu bạn đã lỡ chạy `npm install` trước đó).
3. **Xóa luôn file `package-lock.json**` (file lock phiên bản thư viện local).

Lúc này, thư mục project của bạn chỉ còn lại thuần túy **Mã nguồn (Source Code)** gốc: `server.js`, `package.json`, và thư mục `public/`. Không có bất kỳ file binary hay dependency rác nào bị dính vào.

*(Lưu ý: Nếu bạn có file `.gitignore`, hãy giữ nó lại, nó dùng cho Git chứ không ảnh hưởng đến Docker).*
