# Thực Chiến Docker: Kéo (Pull), Khởi Chạy (Run) Và Khám Phá Bí Mật Của Tiến Trình (PID 1)

Ở bài trước, chúng ta đã nắm được lý thuyết cốt lõi: **Image** là bản thiết kế tĩnh, còn **Container** là thực thể đang chạy. Giờ là lúc mở Terminal lên và thực hành. Trong phần này, chúng ta sẽ làm quen với Docker Hub, cách khởi chạy một pre-built Image, và quan trọng nhất là "giải phẫu" vòng đời của một Container — một trong những khái niệm khiến nhiều người mới bối rối nhất.

---

## 1. Nguồn Gốc Của Image: Docker Hub Là Gì?

Để chạy được một Container, bạn phải có Image. Vậy lấy Image ở đâu?
Về cơ bản có 2 cách: Tự đóng gói thông qua `Dockerfile` (như ví dụ về ứng dụng Go backend ở bài đầu tiên), hoặc sử dụng các Image đã được dựng sẵn (Pre-built Images).

**Docker Hub** (`hub.docker.com`) chính là "siêu thị" Image lớn nhất thế giới, tương tự như GitHub dành cho mã nguồn, hay NPM/Go Module dành cho các thư viện. Các tổ chức lớn (như Node.js, MongoDB, Nginx, Redis) đều duy trì các **Official Images** (Image chính thức) tại đây. Khi cần dựng một database hay một môi trường runtime, bạn chỉ cần lên đây tìm kiếm và kéo về sử dụng ngay thay vì phải tự build từ đầu.

---

## 2. Cạm Bẫy Đầu Tiên: Tại Sao Container Vừa Chạy Đã Tắt?

Hãy thử ngay một ví dụ thực tế. Mở Terminal trên máy của bạn và gõ lệnh sau:

```bash
docker run node

```

**Chuyện gì xảy ra "under the hood" (dưới nền)?**

1. Docker Engine tìm image `node` ở local. Không thấy.
2. Nó tự động kết nối lên Docker Hub, tải (pull) phiên bản `node:latest` về máy.
3. Nó khởi tạo một Container từ Image này và chạy nó.
4. Xong! Bạn sẽ thấy dấu nhắc lệnh terminal trở lại bình thường, như thể chưa có chuyện gì xảy ra.

Hãy kiểm tra lại bằng lệnh xem toàn bộ các containers:

```bash
docker ps -a

```

Bạn sẽ thấy container `node` vừa được tạo ra, nhưng ở cột **Status**, trạng thái của nó là `Exited (0)`. Nó đã tắt ngay lập tức! Tại sao?

### Deep Dive: Nguyên lý Tiến trình (PID 1) trong Docker

Đây là kiến thức sống còn dành cho System Engineer: **Một Docker Container chỉ sống chừng nào Tiến trình chính (Process ID 1 - PID 1) bên trong nó còn hoạt động.**

Mặc định, lệnh chạy (CMD) được định nghĩa sẵn bên trong Image `node` là khởi chạy Node REPL (môi trường gõ lệnh tương tác của Node.js). Tuy nhiên, lệnh `docker run node` của chúng ta chạy ở chế độ cô lập (background/detached), không được gắn với luồng nhập/xuất chuẩn (STDIN/STDOUT) của terminal trên máy chủ (Host).

Do không nhận được bất kỳ luồng đầu vào (input) nào, tiến trình Node REPL bên trong lập tức báo EOF (End of File) và kết thúc. Kéo theo đó, PID 1 chết, và Docker Engine ngay lập tức ra lệnh dọn dẹp, tắt luôn Container đó.

## 3. Giao Tiếp Tương Tác Với Cờ `-it`

Để giữ cho Container "sống" và cho phép chúng ta tương tác trực tiếp với tiến trình Node.js bên trong, ta cần nối luồng terminal của máy Host vào Container bằng cách thêm cờ `-it` (viết tắt của `--interactive` và `--tty`):

```bash
docker run -it node

```

Lúc này, Docker sẽ cấp phát một terminal ảo (TTY) và mở luồng tương tác (Interactive). Bạn sẽ thấy dấu nhắc lệnh chuyển sang `> `, nghĩa là bạn đã thực sự chui vào bên trong môi trường Node.js của Container! Tại đây, bạn có thể gõ các lệnh JavaScript (như `1 + 1`).

Khi bạn muốn thoát, nhấn `Ctrl + C` hai lần. Lúc này tiến trình REPL kết thúc, và theo quy luật PID 1, Container cũng sẽ tự động chuyển về trạng thái `Exited`.

## 4. Bằng Chứng Thép Về Tính Cô Lập (Isolation)

Điểm ăn tiền nhất của Docker là gì? Đó là **bảo vệ sự sạch sẽ cho hệ điều hành Host của bạn**. Chúng ta hãy làm một bài test nhỏ:

Nếu bạn gõ lệnh kiểm tra version ngay trên máy tính cá nhân của bạn (bên ngoài Container):

```bash
node -v
# Output giả định: v14.7.0 (hoặc báo command not found nếu bạn chưa cài Node)

```

Bây giờ, hãy yêu cầu Docker chạy lệnh đó bên trong Container:

```bash
docker run -it node node -v
# Output từ Container: v20.x.x (Phiên bản mới nhất trên Docker Hub)

```

**Điều này chứng minh:**

1. Tiến trình đang chạy sử dụng **100% môi trường và thư viện được đóng gói sẵn trong Image**.
2. Bạn **KHÔNG CẦN** cài đặt Node.js, Python, hay bất kỳ runtime nào trên hệ điều hành vật lý (Ubuntu/macOS) của mình để chạy ứng dụng đó. Không còn những rắc rối kiểu xung đột phiên bản Node.js giữa Dự án A và Dự án B nữa!

## 5. Khởi Tạo Vô Hạn Thực Thể

Cuối cùng, hãy nhớ lại định lý ở bài trước: Từ một Image, bạn có thể tạo ra vô số Containers.
Chỉ cần bạn mở nhiều tab terminal và liên tục gõ lệnh `docker run -it node`, Docker sẽ tạo ra hàng loạt các Containers độc lập, chạy song song cùng một thời điểm.

Gõ lại `docker ps -a`, bạn sẽ thấy danh sách các Containers sinh ra từ cùng Image `node`. Mỗi Container sở hữu một ID riêng, bộ nhớ riêng và hoàn toàn không biết đến sự tồn tại của nhau (trừ khi bạn cấu hình Network cho chúng giao tiếp - phần này chúng ta sẽ học ở block Foundation tiếp theo).

### Tổng Kết

* **Docker Hub** là kho tàng Pre-built Images, giúp tiết kiệm thời gian thiết lập môi trường.
* **Vòng đời Container** gắn liền chặt chẽ với tiến trình chính (PID 1). Tiến trình chết, Container chết.
* Sử dụng cờ **`-it`** khi cần giữ Container sống để tương tác qua Terminal.
* Tính **Cô lập (Isolation)** là vũ khí mạnh nhất giúp loại bỏ hoàn toàn câu nói *"Nó chạy bình thường trên máy tôi mà!"*.
