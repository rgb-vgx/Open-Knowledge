# Gắn Lại Vào Container Đang Chạy: Docker Attach

Nếu bạn đã khởi chạy container ở chế độ detached (chạy ngầm) và muốn theo dõi output trực tiếp, bạn có thể "gắn lại" (attach) vào container đó mà không cần khởi động lại.

---

## Khi Nào Cần Docker Attach?

Giả sử bạn chạy container với cờ `-d`:

```bash
docker run -d --name my-app -p 3000:80 my-image:v1
```

Container đang chạy, nhưng bạn không thấy output trên terminal. Đột nhiên bạn muốn xem log real-time. Thay vì停下container rồi chạy lại, bạn chỉ cần attach vào:

```bash
docker attach my-app
```

Terminal sẽ hiển thị output từ container ngay lập tức.

---

## Docker Attach vs Docker Exec

Nhiều người nhầm lẫn giữa hai lệnh này. Sự khác biệt cốt lõi:

| | `docker attach` | `docker exec` |
|--|----------------|---------------|
| **Mục đích** | Gắn vào tiến trình **đang chạy** (PID 1) | Chạy **tiến trình mới** bên trong container |
| **Số shell** | Chỉ có 1 shell duy nhất | Có thể mở nhiều shell mới |
| **Ảnh hưởng** | Nếu thoát, container có thể dừng | Không ảnh hưởng container đang chạy |

```bash
# Attach vào PID 1 của container
docker attach my-app

# Tạo shell mới bên trong container (không ảnh hưởng PID 1)
docker exec -it my-app /bin/bash
```

---

## Mẹo Hữu Ích

- Nếu bạn chỉ muốn **xem log**, dùng `docker logs -f` thay vì `docker attach` — an toàn hơn vì không ảnh hưởng PID 1.
- Nếu bạn muốn **thao tác bên trong container** (xem file, chạy lệnh debug), dùng `docker exec -it`.
- `docker attach` chỉ nên dùng khi bạn thực sự muốn gắn vào tiến trình chính của container.

---

## Tổng Kết

- `docker attach` gắn terminal vào tiến trình chính (PID 1) của container đang chạy.
- `docker exec` tạo tiến trình mới — linh hoạt hơn và an toàn hơn cho debugging.
- Ưu tiên `docker logs -f` khi chỉ cần xem log.
