# Dừng & Khởi Động Lại Containers: Hiểu Rõ Vòng Đời Container

Trong bài trước, chúng ta đã thấy các lệnh `docker stop` và `docker start` cơ bản. Hôm nay, chúng ta sẽ đi sâu hơn để hiểu rõ cách thức hoạt động của chúng, cũng như sự khác biệt giữa các chế độ chạy khác nhau.

---

## 1. Docker Có Rất Nhiều Lệnh — Nhưng Chỉ Cần Nhớ Mấy Cốt Lõi

Khi bạn chạy `docker --help`, bạn sẽ thấy một danh sách dài các lệnh có sẵn. Tin vui là phần lớn trong số đó bạn sẽ hiếm khi cần đến. Tập trung vào các lệnh cốt lõi là đủ cho hầu hết các tình huống.

---

## 2. Container Đã Stop ≠ Container Mới

Một điểm quan trọng cần phân biệt:

- **`docker run`**: Tạo ra một container **mới** từ image, rồi start nó.
- **`docker start`**: Khởi động lại một container **đã tồn tại** (nhưng đang ở trạng thái stopped).

```bash
# Tạo container mới và chạy nó
docker run -d --name my-app -p 3000:80 my-image:v1

# Dừng container
docker stop my-app

# Khởi động lại container CŨ (không tạo mới)
docker start my-app
```

**Khi nào dùng `docker start` thay vì `docker run`?**
- Khi code và image không thay đổi.
- Khi bạn muốn giữ nguyên cấu hình của container cũ.
- Khi bạn muốn tiết kiệm thời gian (không cần tạo container mới).

---

## 3. Sự Khác Biệt Giữa `docker run` và `docker start`

| Lệnh | Hành động | Terminal |
|-------|-----------|----------|
| `docker run -d` | Tạo mới + Start | Detached (chạy ngầm) |
| `docker run` | Tạo mới + Start | Attached (bị chặn) |
| `docker start` | Chỉ start container cũ | Detached (mặc định) |

Lưu ý: `docker start` mặc định chạy ở chế độ **detached** — terminal không bị chặn và bạn có thể tiếp tục nhập lệnh khác. Điều này khác với `docker run` (mặc định là attached mode).

---

## 4. Kiểm Tra Trạng Thái

```bash
# Xem containers đang chạy
docker ps

# Xem tất cả containers (bao gồm stopped)
docker ps -a
```

Sau khi chạy `docker start`, bạn sẽ thấy container xuất hiện trong danh sách `docker ps` với trạng thái "Up". Bạn có thể truy cập ứng dụng qua localhost ở port đã cấu hình.

---

## 5. Tổng Kết

- `docker run` tạo container mới và chạy nó.
- `docker start` khởi động lại container đã dừng.
- Luôn kiểm tra `docker ps -a` để xem danh sách containers.
- Nếu code và image không đổi, hãy dùng `docker start` thay vì tạo container mới.
- `docker start` mặc định chạy detached, khác với `docker run` mặc định là attached.

Đây là nền tảng để hiểu về các chế độ attached và detached mà chúng ta sẽ tìm hiểu chi tiết ở bài tiếp theo.
