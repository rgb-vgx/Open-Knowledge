# Tổng Kết Lần Đầu: Bức Tranh Toàn Cảnh Về Image Và Container

Qua các bài học trước, chúng ta đã đi qua khá nhiều kiến thức nền tảng về Docker Images và Containers. Hôm nay, chúng ta sẽ dừng lại một nhịp để tổng hợp lại tất cả, đảm bảo rằng mọi người đều hiểu rõ bức tranh toàn cảnh trước khi tiến sâu hơn.

---

## 1. Docker xoay quanh Code của chúng ta

Điểm mấu chốt nhất cần nhớ: Docker cuối cùng cũng chỉ xoay quanh **code ứng dụng** mà chúng ta đang xây dựng — dù đó là web application, backend API, hay bất kỳ service nào.

Chúng ta lấy code đó, cùng với toàn bộ **môi trường thực thi** cần thiết (runtime, thư viện, công cụ), và đóng gói chúng vào một **Docker Image**.

Image không chỉ chứa code. Nó chứa **mọi thứ** mà ứng dụng cần để chạy: hệ điều hành base, các thư viện hệ thống, runtime (Node.js, Python, Go...), biến môi trường, và cấu hình.

---

## 2. Dockerfile — Bản Thiết Kế

Để tạo ra một Image, chúng ta viết **Dockerfile** — một file chứa các chỉ thị (instructions) mô tả chi tiết từng bước một:

- **Base image** nào sẽ được sử dụng làm nền móng?
- **Code** và **dependencies** nào cần được copy vào?
- Có bước cài đặt nào cần thực hiện không (ví dụ: `npm install`, `go mod download`)?
- Port nào cần được mở để truy cập từ bên ngoài?

Dockerfile chính là bản thiết kế mà Docker Engine sẽ đọc để xây dựng Image.

---

## 3. Image — Khắc Bạc Của Ứng Dụng

Image là **khuôn mẫu (template)** — bản thiết kế tĩnh chứa code và môi trường. Từ một Image duy nhất, bạn có thể khởi chạy **nhiều Containers** khác nhau.

Điều quan trọng cần nhớ: **Container KHÔNG sao chép code từ Image**. Container chỉ sử dụng chung các layer Read-Only của Image, sau đó thêm một lớp Read-Write mỏng ở trên cùng. Nếu bạn có 1 Image và 2 Containers, code chỉ tồn tại **duy nhất một lần** trong Image — cả hai Containers đều tham chiếu đến nó. Đây chính là lý do Docker cực kỳ hiệu quả về tài nguyên.

---

## 4. Container — Phiên Bản Đang Chạy

Container chính là **ứng dụng đang chạy** dựa trên Image. Nó hoạt động độc lập, cô lập hoàn toàn với các Containers khác và với hệ điều hành host.

Container được cấp phát tài nguyên riêng (CPU, RAM, Network) và có một không gian file system Read-Write riêng. Tuy nhiên, layer Read-Write này **chỉ tồn tại trong vòng đời của Container** — khi Container bị xóa, toàn bộ dữ liệu ghi trong lớp này cũng sẽ biến mất.

---

## 5. Mối Quan Hệ Image-Container

```
┌─────────────────────────────┐
│     Docker Image            │
│  (Code + Runtime + Env)     │
│  Read-Only, Shared          │
└──────────┬──────────────────┘
           │
     ┌─────┴─────┐
     │           │
┌────▼────┐ ┌────▼────┐
│Container│ │Container│
│  (R/W)  │ │  (R/W)  │
│ PID 1   │ │ PID 1   │
│ Running │ │ Running │
└─────────┘ └─────────┘
```

- **Image** = Bản thiết kế tĩnh (Read-Only)
- **Container** = Phiên bản đang chạy (Read-Write Layer + Process)
- Từ 1 Image → nhiều Containers độc lập
- Code chỉ tồn tại 1 lần trong Image, được share bởi tất cả Containers

---

## Tóm Tắt

| Khái niệm | Vai trò | Đặc tính |
|-----------|---------|----------|
| **Dockerfile** | Bản thiết kế | Chứa chỉ thị build Image |
| **Image** | Khuôn mẫu đóng gói | Read-Only, Immutable |
| **Container** | Phiên bản đang chạy | Read-Write, Ephemeral, Isolated |

Đây là nền tảng cốt lõi mà mọi thứ khác trong Docker đều xây dựng lên trên đó. Hiểu rõ mối quan hệ giữa ba thành phần này sẽ giúp bạn tránh được rất nhiều lỗi và cạm bẫy trong thực tế.
