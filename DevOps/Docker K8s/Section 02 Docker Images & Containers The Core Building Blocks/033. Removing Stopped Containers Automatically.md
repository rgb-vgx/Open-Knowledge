# Tự Động Xóa Containers: Cờ `--rm` Thiết Yếu

Trong bài trước, chúng ta đã học cách xóa containers thủ công bằng `docker rm`. Nhưng có một cách thông minh hơn để giữ hệ thống sạch sẽ — đó là sử dụng cờ `--rm` khi chạy container.

---

## 1. Cờ `--rm` Là Gì?

Khi bạn chạy container với cờ `--rm`, Docker sẽ **tự động xóa container ngay sau khi nó dừng**. Bạn không cần phải nhớ `docker rm` thủ công.

```bash
docker run -d --rm --name my-app -p 3000:80 my-image:v1
```

Sau khi bạn dừng container (`docker stop my-app`), container sẽ tự động bị xóa và không còn xuất hiện trong danh sách `docker ps -a`.

---

## 2. Khi Nào Nên Dùng `--rm`?

Cờ `--rm` đặc biệt hữu ích trong các trường hợp sau:

- **Container chỉ dùng một lần:** Test, build temporary, chạy script.
- **Sau khi stop → rebuild image mới → chạy container mới:** Đây là workflow phổ biến khi bạn thường xuyên thay đổi code.
- **CI/CD Pipeline:** Container build/test xong là tự xóa, giữ sạch environment.

```bash
# Ví dụ: Container test tự xóa sau khi dừng
docker run --rm -it my-test-image
```

---

## 3. `--rm` vs `docker rm` Thủ Công

| | `--rm` (tự động) | `docker rm` (thủ công) |
|--|-------------------|----------------------|
| Thời điểm xóa | Ngay sau khi stopped | Khi bạn chạy lệnh |
| Rủi ro quên | Không có | Cao — dễ tích tụ rác |
| Phù hợp | Production, CI/CD | Phát triển tạm thời |

---

## 4. Lưu Ý

- Container với `--rm` **không thể restart** bằng `docker start` vì nó đã bị xóa ngay sau khi dừng.
- Nếu bạn cần restart container, đừng dùng `--rm`.
- `--rm` chỉ xóa container khi nó dừng — nếu container đang chạy, nó vẫn bình thường.

---

## Tổng Kết

- `--rm` tự động xóa container ngay sau khi dừng.
- Phù hợp cho container dùng một lần và workflow CI/CD.
- Giúp tránh tình trạng "rác thải Docker" — container stopped tích tụ nhiều mà bạn quên xóa.
- Không dùng `--rm` nếu bạn muốn restart container sau này.
