# Giới Thiệu Multi-Stage Builds: Docker Image Optimization

Multi-stage builds là tính năng mạnh mẽ của Docker giúp tạo images nhỏ hơn và secure hơn. Bài viết này giải thích cách hoạt động và lợi ích của multi-stage builds.

## Vấn Đề Với Single-Stage Builds

### Traditional Dockerfile
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build
EXPOSE 3000
CMD ["npm", "start"]
```

### Problems
1. **Image size lớn**: Chứa cả development dependencies
2. **Security risk**: Attack surface lớn hơn
3. **Slow deployments**: Time để pull image
4. **Wasted resources**: Chứa code không cần thiết

## Multi-Stage Builds

### Concept
Sử dụng nhiều FROM statements trong Dockerfile:
```dockerfile
# Stage 1: Build
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Stage 2: Production
FROM nginx:stable-alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### Cách Hoạt Động
1. **Stage 1 (builder)**: Build code với Node.js
2. **Stage 2 (production)**: Copy kết quả build, serve với Nginx
3. **Final image**: Chỉ chứa stage 2

## Lợi Ích

### 1. Image Size Nhỏ Hơn
- Development dependencies không được copy
- Chỉ chứa production code
- Ví dụ: 1.2GB → 23MB

### 2. Security Tốt Hơn
- Fewer packages = fewer vulnerabilities
- Không có build tools trong production
- Attack surface giảm đáng kể

### 3. Deployment Nhanh Hơn
- Image nhỏ → pull nhanh hơn
- Startup time ngắn hơn
- Network bandwidth tiết kiệm

### 4. Better Caching
- Docker cache từng stage riêng
- Chỉ rebuild stage thay đổi

## Docker Build Commands

### Build All Stages
```bash
docker build -t my-app .
```

### Build Specific Stage
```bash
docker build --target builder -t my-app-builder .
```

### Build với Different Dockerfile
```bash
docker build -f Dockerfile.prod -t my-app-prod .
```

## Best Practices

1. **Đặt tên cho stages**: Dễ maintain và reference
2. **Sử dụng .dockerignore**: Tránh copy unnecessary files
3. **Minimize layers**: Kết hợp RUN commands
4. **Use specific tags**: Tránh dùng `latest`

## Kết Luận

Multi-stage builds là essential technique cho production Docker images. Nó giúp tạo images nhỏ hơn, secure hơn, và efficient hơn. Đây là best practice mà mọi developer cần nắm vững.
