# Hiểu Rõ Multi-Stage Build Targets: Xây Dựng Tùy Chỉnh

Multi-stage builds cho phép bạn build đến một stage cụ thể, hữu ích cho testing và debugging. Bài viết này giải thích cách sử dụng `--target` flag.

## Docker Build Targets

### Build Tất Cả Stages
```bash
docker build -t my-app .
```

Docker sẽ build từ đầu đến cuối, tạo image từ stage cuối cùng.

### Build Đến Stage Cụ Thể
```bash
docker build --target builder -t my-app-builder .
```

Chỉ build đến stage tên "builder", dừng lại ở đó.

## Ví Dụ Thực Tế

### Dockerfile với Nhiều Stages
```dockerfile
# Stage 1: Test
FROM node:18-alpine AS test
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm test

# Stage 2: Build
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Stage 3: Production
FROM nginx:stable-alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### Các Lệnh Build

```bash
# Chỉ chạy tests
docker build --target test -t my-app-test .

# Chỉ build code
docker build --target builder -t my-app-builder .

# Full production build
docker build -t my-app .
```

## Use Cases

### 1. Testing
```bash
docker build --target test -t my-app-test .
docker run my-app-test npm test
```

### 2. Debugging
```bash
docker build --target builder -t my-app-debug .
docker run -it my-app-debug sh
```

### 3. CI/CD Pipeline
```yaml
# GitHub Actions
- name: Run tests
  run: docker build --target test -t my-app-test .

- name: Build production
  run: docker build -t my-app .
```

## BuildKit Features

### Cache Mounting
```dockerfile
RUN --mount=type=cache,target=/app/.npm npm install
```

### Secret Mounting
```dockerfile
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc npm install
```

## Best Practices

1. **Đặt tên rõ ràng cho stages**: Dễ hiểu và reference
2. **Test stage riêng**: Đảm bảo code hoạt động
3. **Cache optimization**: Sử dụng build cache
4. **Security**: Không expose secrets trong final image

## Kết Luận

Multi-stage build targets là powerful feature cho CI/CD pipelines. Bạn có thể test, debug, và build tùy thích mà không cần multiple Dockerfiles. Đây là practice tốt cho modern development workflow.
