# Quản Lý và Cập Nhật Container/Image: Quy Trình Production

Khi ứng dụng đã triển khai thành công, câu hỏi tiếp theo là: làm thế nào để cập nhật khi có thay đổi code? Trong bài viết này, chúng ta sẽ tìm hiểu quy trình update container và manage application trên EC2.

## Quy Trình Cập Nhật Code

Khi bạn thay đổi code, quy trình cập nhật lên production server bao gồm các bước sau:

### Bước 1: Rebuild Image
```bash
docker build -t goals-node .
```

Image mới sẽ chứa code đã cập nhật.

### Bước 2: Tag Image
```bash
docker tag goals-node yourusername/goals-node
```

### Bước 3: Push Image Lên Docker Hub
```bash
docker push yourusername/goals-node
```

Docker push rất efficient - chỉ push các layer thực sự thay đổi.

### Bước 4: Pull Image Trên Server
```bash
docker pull yourusername/goals-node
```

**Lưu ý quan trọng**: `docker run` không tự động pull image mới. Nếu image đã có local, Docker sẽ dùng image cũ. Bạn phải pull thủ công để đảm bảo dùng phiên bản mới nhất.

### Bước 5: Dừng Container Cũ
```bash
docker stop goals-app
docker rm goals-app
```

### Bước 6: Chạy Container Mới
```bash
docker run -d -p 80:80 --name goals-app yourusername/goals-node
```

## Verify Cập Nhật

Mở trình duyệt, truy cập lại public IP. Bạn sẽ thấy phiên bản mới nhất của ứng dụng.

## Quản Lý Container Hàng Ngày

### Xem Logs
```bash
docker logs goals-app
```

### Xem Container Đang Chạy
```bash
docker ps
```

### Restart Container
```bash
docker restart goals-app
```

### Xem Chi Tiết Container
```bash
docker inspect goals-app
```

## Tự Động hóa Quy Trình

Trong thực tế, bạn sẽ muốn tự động hóa quy trình này với CI/CD pipeline:
1. Code push trigger build
2. Auto build image
3. Auto push lên Docker Hub
4. Auto deploy lên server

Công cụ phổ biến: GitHub Actions, GitLab CI, Jenkins.

## Kết Luận

Quản lý và cập nhật container trên production server đòi hỏi quy trình có kỷ luật. Điểm quan trọng nhất là luôn pull image mới trước khi chạy container. Với practice tốt, bạn có thể deploy updates một cách nhanh chóng và an toàn.
