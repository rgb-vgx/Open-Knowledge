# Sử Dụng EFS Volumes Với ECS: Persist Data Trong Containers

Vấn đề lớn nhất khi chạy database trong container: data bị mất khi container restart. AWS EFS (Elastic File System) giải quyết vấn đề này bằng cách cung cấp persistent storage cho containers.

## Vấn Đề: Data Loss Khi Container Restart

Khi ECS update service:
1. Task mới được tạo
2. Task cũ bị terminate
3. Tất cả data trong container mất
4. Database phải rebuild từ đầu

## Giải Pháp: EFS Volumes

### EFS Là Gì?
- Elastic File System của AWS
- Network file system (NFS)
- Persistent storage survive container restart
- Shared across multiple containers

### Cách EFS Hoạt Động
1. Container ghi data vào mount point
2. EFS lưu data trên network storage
3. Khi container restart, mount lại EFS
4. Data vẫn nguyên vẹn

## Setup EFS Với ECS

### Bước 1: Tạo EFS File System
```
EFS Console → Create File System
- Name: db-storage
- VPC: Chọn VPC của ECS
- Customize: Thêm subnets
- Security Group: Tạo mới cho EFS
```

### Bước 2: Tạo Security Group Cho EFS
```
EC2 → Security Groups → Create
- Name: efs-sg
- Inbound: NFS (port 2049) từ ECS security group
```

### Bước 3: Update Task Definition
```
Task Definition → Create new revision
- Volumes: Thêm volume tên "data"
- Type: EFS
- File system: Chọn EFS vừa tạo
```

### Bước 4: Mount Volume Vào Container
```
Container Definitions → mongodb
- Storage and Logging
- Mount Points: data → /data/db
```

### Bước 5: Update Service
```
ECS → Service → Update
- Force new deployment
- Platform version: 1.4 (hỗ trợ EFS)
```

## Verify

1. Thêm goal qua POST request
2. Update service (force new deployment)
3. Kiểm tra goals vẫn còn

## Lưu Ý

1. **Platform version**: Chọn 1.4 cho EFS support
2. **Security Group**: Phải cho phép NFS traffic
3. **Mount point**: Phải đúng path cho database
4. **Cost**: EFS tính phí theo storage sử dụng

## Kết Luận

EFS volumes giải quyết data persistence problem cho containers trên ECS. Mặc dù setup phức tạp hơn Docker volumes, nhưng đây là necessary cho production databases.
