# Development vs Production: Sự Khác Biệt Cần Hiểu

Khi sử dụng Docker cho cả development và production, nhiều developer thắc mắc: tại sao có sự khác biệt? Bài viết này giải thích rõ lý do và cách chúng vẫn đảm bảo tính reproducibility.

## Tại Sao Có Sự Khác Biệt?

### React Application
- **Development**: `npm start` chạy development server với hot reloading
- **Production**: `npm run build` tạo static files, serve với Nginx

### Node.js Backend
- **Development**: `npm start` chạy nodemon với auto-reload
- **Production**: `node app.js` chạy trực tiếp

### MongoDB
- **Development**: Container trên localhost
- **Production**: MongoDB Atlas hoặc container khác

## Docker Container Differences

### Development Container
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
```

### Production Container
```dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

FROM nginx:stable-alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

## Tại Sao Vẫn Đảm Bảo Reproducibility?

### 1. Code Lock-In
- Code trong container là giống nhau
- Chỉ có cách chạy là khác
- Same source code, same build process

### 2. Environment Lock-In
- Runtime environment được define trong Dockerfile
- Node.js version giống nhau
- Dependencies versions giống nhau

### 3. Environment Variables
- Linh hoạt cấu hình theo environment
- Không thay đổi code
- Ví dụ: `REACT_APP_API_URL`

## Best Practices

### 1. Same Node.js Version
```dockerfile
# Cả hai đều dùng node:18-alpine
FROM node:18-alpine
```

### 2. Same Dependencies Versions
```json
// package.json versions cố định
{
  "dependencies": {
    "react": "^18.2.0"
  }
}
```

### 3. Environment-Specific Configuration
```javascript
// Code giống nhau
const apiUrl = process.env.REACT_APP_API_URL;
```

## Verification

### Test Development
```bash
docker-compose up
# Access localhost:3000
```

### Test Production
```bash
docker build -f Dockerfile.prod -t my-app-prod .
docker run -p 80:80 my-app-prod
# Access localhost:80
```

Cả hai environment đều chạy ứng dụng đúng cách.

## Kết Luận

Sự khác biệt giữa development và production là cần thiết nhưng không mâu thuẫn với triết lý của Docker. Code và environment vẫn được lock-in vào container, đảm bảo tính reproducibility. Đây chính là sức mạnh thực sự của Docker.
