# Kiến Trúc Hiện Tại: Hiểu Rõ Application Architecture

Sau khi deploy thành công multi-container application, chúng ta cần overview kiến trúc hiện tại để hiểu cách các components hoạt động cùng nhau.

## Kiến Trúc Hiện Tại

### Components

1. **AWS ECS Cluster**: Network environment cho containers
2. **Task Definition**: Blueprint cho containers
3. **Service**: Quản lý task execution
4. **Load Balancer**: Distribution traffic

### Containers Trong Task

1. **Node.js Backend Container**:
   - REST API cho goals management
   - Port 80
   - Kết nối với MongoDB

2. **MongoDB Container**:
   - Database cho application
   - Port 27017
   - Persistent storage với EFS

### Data Flow

```
User Request
    ↓
Load Balancer
    ↓
Node.js Backend (Container 1)
    ↓
MongoDB (Container 2)
    ↓
EFS Volume (Persistent Storage)
    ↓
Response
```

## Tại Sao Kiến Trúc Này?

### 1. Separation of Concerns
- Backend xử lý business logic
- MongoDB quản lý data persistence
- Load Balancer distribution traffic

### 2. Scalability
- Mỗi container có thể scale independently
- Load Balancer distribute requests

### 3. Maintainability
- Update backend mà không affect database
- Replace MongoDB service mà không restart backend

## Vấn Đề Cần Lưu Ý

### 1. Single Point of Failure
- Chỉ có 1 backend container
- Nếu backend crash, entire app down

### 2. Database Scalability
- MongoDB chạy trong container
- Không optimal cho production workloads

### 3. No Frontend Yet
- Hiện tại chỉ có backend API
- Cần thêm frontend trong tương lai

## Kết Luận

Kiến trúc hiện tại là starting point tốt. Nó demonstrate multi-container deployment trên ECS. Tuy nhiên, cần improve nhiều aspects cho production-ready application. Bài tiếp theo sẽ discuss alternatives cho database management.
