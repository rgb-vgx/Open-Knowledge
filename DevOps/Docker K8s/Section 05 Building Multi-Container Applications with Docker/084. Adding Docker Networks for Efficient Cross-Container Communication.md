# Docker Network: Giao Hiệu Cross-Container Communication

## Vấn Đề Hiện Tại

Khi publish port cho từng container riêng lẻ, containers giao tiếp qua `localhost` trên host machine. Điều này:
- Không tối ưu (traffic đi qua host machine)
- Không tự động (cần manage port từng container)
- Không scale được (không dùng được container DNS)

**Giải pháp:** Đặt tất cả containers vào cùng Docker network.

## Tạo Docker Network

```bash
# Liệt kê networks hiện có
docker network ls

# Tạo network mới
docker network create goals-net
```

## Chạy Containers Trong Network

### MongoDB

```bash
docker run -d \
  --name mongodb \
  --rm \
  --network goals-net \
  mongo
```

**Không cần publish port** — containers trong cùng network tự giao tiếp qua container name.

### Node.js Backend

```bash
docker run -d \
  --name goals-backend \
  --rm \
  --network goals-net \
  -p 80:80 \
  goals-node
```

**Vẫn publish port 80** vì frontend cần truy cập từ host machine (browser chạy trên host).

## Thay Đổi Code Backend

Thay `host.docker.internal` bằng tên container `mongodb`:

```javascript
// Trước
await mongoose.connect('mongodb://host.docker.internal:27017/goals');

// Sau
await mongoose.connect('mongodb://mongodb:27017/goals');
```

Docker DNS tự động resolve `mongodb` thành IP của MongoDB container.

## React Frontend: Trường Hợp Đặc Biệt

### Tại Sao Không Dùng Container Name?

React code chạy trong **browser**, không phải trong container:

```
Browser (localhost:3000)
    │
    ▼ React JavaScript executes HERE
    │ (browser không biết Docker network là gì)
    ▼
Backend API (localhost:80)
```

Vì vậy, React code vẫn phải gọi `localhost:80/goals` — browser cần address mà nó hiểu được.

### Kết Luận

- **Backend → MongoDB:** Dùng container name (cùng network)
- **Frontend → Backend:** Dùng `localhost` (browser cần host address)

## Docker Network Architecture

```
┌─────────────────────────────────────────┐
│            goals-net network            │
│                                         │
│  ┌──────────┐    ┌──────────────────┐  │
│  │ MongoDB  │◀──▶│  Node.js Backend │  │
│  │ (mongodb)│    │ (goals-backend)  │  │
│  │ port 27017│    │   port 80        │  │
│  └──────────┘    └────────┬─────────┘  │
│                           │             │
└───────────────────────────┼─────────────┘
                            │ -p 80:80
                            ▼
                    ┌──────────────┐
                    │   Browser    │
                    │ (localhost)  │
                    └──────────────┘
                            ▲
                            │ -p 3000:3000
                    ┌───────┴────────┐
                    │ React Frontend │
                    │ (goals-frontend)│
                    └────────────────┘
```

## Xác Nhận Containers Hoạt Động

```bash
# Kiểm tra containers
docker ps

# Xem network details
docker network inspect goals-net

# Test functionality qua browser
# localhost:3000 — React app
# localhost:80/goals — Backend API
```

## Tóm Tắt

Docker network cho phép containers giao tiếp trực tiếp qua container name, không cần publish port. Điều này tự động, hiệu quả và dễ scale. Tuy nhiên, React frontend là ngoại lệ — code chạy trong browser nên vẫn cần `localhost`.

Trong bài tiếp theo, chúng ta sẽ tìm hiểu cách fix lỗi authentication MongoDB và đảm bảo data persistence.
