# Xây Dựng Ứng Dụng Đa Container Với Docker: Giới Thiệu Module

## Bạn Sẽ Học Được Gì?

Trong các module trước, chúng ta đã tìm hiểu về networking và bắt đầu xây dựng ứng dụng sử dụng nhiều container. Bây giờ, đã đến lúc đi sâu hơn —我们将 xây dựng một ứng dụng multi-container thực tế, hoàn chỉnh với database, backend API và frontend SPA.

> **Mục tiêu module:** Combine các kỹ năng Docker đã học vào một dự án thực tế, bao gồm MongoDB, Node.js REST API và React single-page application.

## Tại Sao Multi-Container Application?

Hầu hết các ứng dụng production thực tế không chạy trong một container duy nhất. Thay vào đó, chúng được cấu thành từ nhiều service riêng biệt:

- **Database** — Lưu trữ dữ liệu (MongoDB, PostgreSQL, v.v.)
- **Backend API** — Xử lý logic business và giao tiếp với database
- **Frontend** — Giao diện người dùng, giao tiếp với backend qua API

Mỗi service chạy trong một container riêng, giúp:
- **Tách biệt trách nhiệm** — Mỗi container chỉ làm một việc
- **Scale independently** — Container nào cần resources nhiều hơn thì scale riêng
- **Linh hoạt triển khai** — Thay đổi một service mà không ảnh hưởng service khác

## Cấu Trúc Ứng Dụng Mục Tiêu

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│   React     │────▶│   Node.js    │────▶│   MongoDB   │
│   Frontend  │     │   Backend    │     │   Database  │
│   (port 3000)│     │   (port 80)  │     │  (port 27017)│
└─────────────┘     └──────────────┘     └─────────────┘
```

**Nguyên tắc hoạt động:**
1. Frontend (React) gửi request HTTP đến Backend
2. Backend (Node.js) xử lý logic và gọi MongoDB để lưu/lấy dữ liệu
3. Dữ liệu được lưu trong MongoDB và trả về cho người dùng qua chuỗi trên

## Thách Thức Trong Module Này

Khi chuyển từ một container sang nhiều container, bạn sẽ gặp phải:

- **Networking** — Containers cần giao tiếp với nhau
- **Data Persistence** — Dữ liệu phải tồn tại ngay cả khi container bị xóa
- **Live Reload** — Source code thay đổi cần được phản ánh tức thì khi develop
- **Port Publishing** — Quản lý ports giữa các container và host machine

## Tại Sao Nên Thử Tự Làm Trước?

Trước khi đi cùng bài viết, hãy thử dockerize ứng dụng này theo cách của bạn. Bạn đã có đủ kiến thức từ các module trước:
- Docker images và Dockerfiles
- Container running và port publishing
- Named volumes và bind mounts
- Docker networking cơ bản

Đây là cơ hội tuyệt vời để practice!

## Tóm Tắt

Module này sẽ hướng dẫn bạn dockerize toàn bộ một ứng dụng multi-service thực tế. Bạn sẽ combine tất cả kỹ năng Docker đã học — từ Dockerfiles đến networking, volumes, và bind mounts — để xây dựng một development environment hoàn chỉnh.

Trong bài tiếp theo, chúng ta sẽ tìm hiểu chi tiết về ứng dụng mục tiêu và cách setup project trước khi bắt đầu dockerize từng service.
