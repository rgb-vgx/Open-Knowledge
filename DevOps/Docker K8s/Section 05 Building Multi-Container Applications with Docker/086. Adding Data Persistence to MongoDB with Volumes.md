# Data Persistence Cho MongoDB: Named Volumes Trong Docker

## Vấn Đề: Dữ Liệu Mất Khi Container Restart

Khi停止 MongoDB container và chạy lại, toàn bộ dữ liệu goals bị mất. Nguyên nhân: dữ liệu được lưu trong writable layer của container — khi container bị xóa, writable layer cũng mất.

## Giải Pháp: Docker Named Volume

Named volume lưu trữ dữ liệu trên host machine, tách biệt với container lifecycle.

### Cú Pháp

```bash
docker run -d \
  --name mongodb \
  --rm \
  --network goals-net \
  -v data:/data/db \
  mongo
```

**Phân tích:**
- `-v data:/data/db` — Tạo named volume tên "data", mount vào `/data/db` trong container
- `data` — Tên volume (Docker tự quản lý vị trí trên host)
- `/data/db` — Đường dẫn MongoDB lưu trữ database files

### Named Volume vs Bind Mount

| | Named Volume | Bind Mount |
|---|--------------|------------|
| **Đường dẫn host** | Docker tự quản lý | Bạn chỉ định cụ thể |
| **Truy cập từ host** | Khó (qua Docker API) | Dễ (truy cập trực tiếp) |
| **Sử dụng khi** | Cần persist data | Cần share files giữa host/container |

## Thêm Authentication

```bash
docker run -d \
  --name mongodb \
  --rm \
  --network goals-net \
  -v data:/data/db \
  -e MONGO_INITDB_ROOT_USERNAME=max \
  -e MONGO_INITDB_ROOT_PASSWORD=secret \
  mongo
```

**Environment variables:**
- `MONGO_INITDB_ROOT_USERNAME` — Tạo user root với tên này
- `MONGO_INITDB_ROOT_PASSWORD` — Mật khẩu cho user root
- User được tạo trong database `admin` với role `root` (superuser)

## Xác Nhận Data Persistence

```bash
# Thêm goal qua frontend
# Kiểm tra trong MongoDB container
docker exec -it mongodb mongosh -u max -p secret --authenticationDatabase admin

# Trong mongosh
> use goals
> db.goals.find()

# Dừng container
docker stop mongodb

# Chạy lại container với cùng volume
docker run -d \
  --name mongodb \
  --rm \
  --network goals-net \
  -v data:/data/db \
  -e MONGO_INITDB_ROOT_USERNAME=max \
  -e MONGO_INITDB_ROOT_PASSWORD=secret \
  mongo

# Data vẫn còn!
```

## Cập Nhật Connection String Backend

Vì giờ MongoDB có authentication, cần cập nhật connection string:

```javascript
// app.js
const MONGODB_URI = `mongodb://${process.env.MONGODB_USERNAME}:${process.env.MONGODB_PASSWORD}@mongodb:27017/goals?authSource=admin`;
```

## Tóm Tắt

Named volume giải quyết vấn đề data persistence — dữ liệu tồn tại ngay cả khi container bị xóa và tạo lại. Kết hợp với environment variables cho authentication, MongoDB container giờ đã sẵn sàng cho production-like setup.

Trong bài tiếp theo, chúng ta sẽ áp dụng similar techniques cho Node.js backend — persist logs và thêm live source code updates.
