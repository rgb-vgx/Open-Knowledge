# Docker Compose: Công Cụ Quản Lý Ứng Dụng Đa Container

Khi ứng dụng phát triển và sử dụng nhiều container, việc quản lý bằng các lệnh `docker run` riêng lẻ sẽ trở nên phức tạp và dễ gây lỗi. Docker Compose ra đời để giải quyết bài toán này bằng cách cho phép bạn định nghĩa toàn bộ cấu hình container trong một file YAML duy nhất.

## Tại Sao Cần Docker Compose?

Hãy tưởng tượng bạn có một ứng dụng với:
- Frontend React
- Backend Node.js API
- PostgreSQL Database
- Redis Cache

Nếu chạy từng container riêng lẻ, bạn sẽ cần:
```bash
docker network create app-net
docker run -d --name db --network app-net -v pgdata:/var/lib/postgresql/data postgres
docker run -d --name redis --network app-net redis
docker run -d --name api --network app-net -e DB_HOST=db -e REDIS_HOST=redis myapi
docker run -d --name frontend --network app-net -p 3000:3000 myfrontend
```

Đây là những lệnh dài, dễ sai sót và không dễ tái sử dụng.

## Docker Compose Giải Quyết Thế Nào?

Docker Compose cho phép bạn đặt tất cả cấu hình vào file `docker-compose.yml`:

```yaml
services:
  db:
    image: postgres:15
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: secret

  redis:
    image: redis:alpine

  api:
    build: ./api
    ports:
      - "3000:3000"
    environment:
      DB_HOST: db
      REDIS_HOST: redis
    depends_on:
      - db
      - redis

  frontend:
    build: ./frontend
    ports:
      - "80:80"
    depends_on:
      - api

volumes:
  pgdata:
```

## Các Lệnh Docker Compose Cơ Bản

### Khởi Chạy Ứng Dụng

```bash
# Chạy tất cả services
docker compose up

# Chạy nền (detached mode)
docker compose up -d

# Build lại images trước khi chạy
docker compose up --build
```

### Quản Lý Services

```bash
# Xem các container đang chạy
docker compose ps

# Xem logs
docker compose logs
docker compose logs -f api  # Theo dõi logs real-time

# Dừng tất cả services
docker compose down

# Dừng và xóa volumes
docker compose down -v
```

### Xây Dựng và Quản Lý Images

```bash
# Build images
docker compose build

# Build lại một service cụ thể
docker compose build api

# Pull images mới nhất
docker compose pull
```

## Tính Năng Quan Trọng Của Docker Compose

### 1. Tự Động Networking

Docker Compose tự động tạo network và thêm tất cả services vào đó. Bạn có thể sử dụng service name làm hostname:

```yaml
# Container api có thể kết nối đến database bằng tên "db"
environment:
  DB_HOST: db
```

### 2. Quản Lý Dependencies

Sử dụng `depends_on` để đảm bảo thứ tự khởi động:

```yaml
services:
  api:
    depends_on:
      - db
      - redis
```

### 3. Persistent Storage với Volumes

```yaml
services:
  db:
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

### 4. Xây Dựng Từ Dockerfile

```yaml
services:
  api:
    build:
      context: ./api
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
```

## Best Practices

1. **Sử dụng `docker compose up -d`** cho các môi trường development
2. **Luôn define volumes riêng** cho dữ liệu quan trọng
3. **Sử dụng `depends_on`** nhưng không nên rely vào startup order hoàn toàn
4. **Tạo `.env` file** cho các biến môi trường nhạy cảm
5. **Sử dụng `docker compose down -v`** khi muốn reset hoàn toàn

## Ví Dụ Thực Tế: Full Stack Application

```yaml
services:
  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    depends_on:
      - api

  api:
    build: ./api
    ports:
      - "5000:5000"
    environment:
      DATABASE_URL: postgres://postgres:secret@db:5432/mydb
      REDIS_URL: redis://redis:6379
    depends_on:
      - db
      - redis

  db:
    image: postgres:15
    volumes:
      - postgres_data:/var/lib/postgresql/data
    environment:
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb

  redis:
    image: redis:alpine

volumes:
  postgres_data:
```

## Tóm Tắt

- Docker Compose định nghĩa multi-container apps trong một file YAML
- Chỉ cần một lệnh `docker compose up` để khởi chạy toàn bộ ứng dụng
- Tự động networking giúp services giao tiếp bằng tên
- Quản lý volumes, networks và dependencies tập trung
- Phù hợp cho cả development và production
