# Docker Images và Containers: Hai Khái Niệm Cốt Lõi Bạn Phải Hiểu

Trong thế giới Docker, có hai khái niệm quan trọng nhất mà mọi developer cần nắm vững: **Images** và **Containers**. Hiểu rõ mối quan hệ giữa chúng sẽ giúp bạn làm việc hiệu quả hơn và tránh được nhiều lỗi phổ biến.

## Container: Hộp Đậy Cô Lập Cho Ứng Dụng

Container là những hộp cô lập chứa code và môi trường cần thiết để chạy code đó. Điểm quan trọng nhất cần ghi nhớ là: **mỗi container thường chỉ tập trung vào một tác vụ duy nhất**.

Điều này có nghĩa là bạn không nên chạy web server, frontend và database trong cùng một container. Thay vào đó, mỗi thành phần nên nằm trong container riêng biệt.

**Ưu điểm chính của container:**
- Nhỏ gọn, nhẹ nhàng, dễ dàng chia sẻ và tái tạo
- Môi trường được khóa lại bên trong container
- Khả năng tái tạo cao trên các môi trường khác nhau

## Tính Chất Stateless Của Container

Container mang tính **stateless** (không trạng thái). Dữ liệu được ghi bên trong container sẽ bị mất khi container bị tắt, ngoại trừ khi sử dụng **volumes**.

Volumes cho phép bạn映射 certain folders trong container sang thư mục trên máy host, giúp dữ liệu tồn tại ngay cả khi container bị xóa.

## Image: Bản Vẽ Cho Container

**Image là bản blueprint cho container.** Image chứa code và môi trường được mô tả trong Dockerfile. Container chỉ là lớp mỏng bổ sung nằm trên image.

Một image có thể tạo ra nhiều container khác nhau. Đây chính là ý tưởng cốt lõi: image có thể chia sẻ và tái sử dụng.

**Đặc điểm quan trọng của image:**
- **Read-only**: Image chỉ đọc, không chạy và không ghi dữ liệu
- Khi container tạo dữ liệu, dữ liệu đó chỉ được ghi trong lớp read-write của container, không phải trong image
- Image sẽ không bao giờ thay đổi, giúp dễ dàng build và chia sẻ

## Hệ Thống Layers: Tối Ưu Quá Trình Build

Khi bạn tạo image bằng các hướng dẫn trong Dockerfile, Docker tạo ra các **layers** (lớp) khác nhau. Hệ thống này đảm bảo rằng nếu chỉ có một hướng dẫn thay đổi, không cần phải thực thi lại toàn bộ.

Các layers được cache và có thể tái sử dụng, giúp quá trình build image trở nên nhanh chóng và hiệu quả. Container chỉ là lớp bổ sung mỏng trên cùng của image, được tạo mới cho mỗi container chạy.

## Ví Dụ Thực Tế

```dockerfile
# FROM python:3.11-slim - Layer 1: Base image
# WORKDIR /app - Layer 2: Tạo thư mục làm việc
# COPY requirements.txt . - Layer 3: Copy file dependencies
# RUN pip install -r requirements.txt - Layer 4: Cài dependencies
# COPY . . - Layer 5: Copy source code
```

Mỗi dòng trong Dockerfile tạo ra một layer. Khi bạn thay đổi code, chỉ có layer cuối cùng cần rebuild, các layer trước đó vẫn được cache.

## Tóm Tắt

- Container là thực thể chạy, image là bản blueprint
- Container tập trung vào một tác vụ
- Image read-only, container có lớp read-write
- Hệ thống layers giúp tối ưu quá trình build
- Volumes giúp dữ liệu tồn tại qua các lần restart
