# Docker Deployment: Những Lưu Ý Quan Trọng Khi Triển Khai Ứng Dụng

Sau khi nắm vững các kiến thức Docker cơ bản, việc triển khai ứng dụng lên môi trường production là bước tiếp theo quan trọng. Bài viết này tổng hợp những lưu ý và best practices cần ghi nhớ khi deploy containerized applications.

## Lưu Ý Đầu Tiên: Không Sử Dụng Bind Mount Trong Production

Đây là lỗi phổ biến nhất mà developer mới mắc phải. Bind mount phù hợp cho development nhưng **hoàn toàn không phù hợp cho production**.

```bash
# SAI - Không nên dùng trong production
docker run -v /local/path:/container/path myapp

# ĐÚNG - Sử dụng volume hoặc COPY trong Dockerfile
docker run -v mydata:/app/data myapp
```

**Lý do:**
- Bind mount phụ thuộc vào cấu trúc thư mục trên host
- Không reproducible giữa các môi trường khác nhau
- Gây khó khăn trong việc quản lý và backup

Thay vào đó, hãy sử dụng **regular volume** hoặc **COPY instruction** trong Dockerfile để đảm bảo mọi thứ cần thiết đều nằm trong container.

## Multi-Host Deployment

Khi triển khai lên môi trường production, một máy chủ duy nhất có thể không đủ sức chứa tất cả container. Đây là lúc bạn cần xem xét:

### 1. Multiple Hosts

- Frontend, backend, database có thể cần chạy trên các server khác nhau
- Mỗi server có thể chạy nhiều container
- Cần có giải pháp orchestration để quản lý

### 2. Docker Compose cho Production

```yaml
services:
  api:
    image: myusername/myapi:1.0
    deploy:
      replicas: 3
      resources:
        limits:
          cpus: '0.5'
          memory: 512M
    networks:
      - frontend
      - backend

  db:
    image: postgres:15
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - backend

networks:
  frontend:
  backend:

volumes:
  pgdata:
```

## Multi-Stage Build: Tối Ưu Image Cho Production

Đây là tính năng quan trọng giúp giảm kích thước image đáng kể, đặc biệt quan trọng cho frontend applications.

```dockerfile
# Stage 1: Build
FROM node:16 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**Kết quả:** Image cuối cùng chỉ chứa output build, không chứa source code hay build tools.

## Trade-Off: Control vs Ease-of-Use

### Self-Managed Server (Full Control)

```bash
# Tự setup EC2 instance trên AWS
ssh into server
sudo apt-get install docker.io
docker run -d -p 80:80 myapp
```

**Ưu điểm:**
- Full control trên mọi aspect
- Linh hoạt trong cấu hình

**Nhược điểm:**
- Bạn chịu trách nhiệm về security
- Cần tự update tools và dependencies
- Phức tạp hơn trong monitoring

### Managed Service (Ease-of-Use)

Sử dụng các dịch vụ managed như:
- **AWS ECS/EKS**
- **Google Cloud Run/GKE**
- **Azure Container Instances**

**Ưu điểm:**
- Ít responsibility hơn
- Dễ sử dụng hơn
- Tích hợp sẵn monitoring, scaling

**Nhược điểm:**
- Ít control hơn
- Chi phí có thể cao hơn

## Best Practices Cho Production

### 1. Image Security

```dockerfile
# Sử dụng official base images
FROM node:16-alpine

# Chạy với non-root user
RUN addgroup -g 1001 -S appgroup
RUN adduser -S appuser -u 1001 -G appgroup
USER appuser

COPY --chown=appuser:appgroup . .
```

### 2. Health Checks

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD curl -f http://localhost/ || exit 1
```

### 3. Resource Limits

```yaml
services:
  api:
    deploy:
      resources:
        limits:
          cpus: '1.0'
          memory: 1G
        reservations:
          cpus: '0.5'
          memory: 512M
```

### 4. Logging

```bash
# Sử dụng logging driver
docker run --log-driver=json-file --log-opt max-size=10m myapp
```

## Quy Trình Deploy Tham Khảo

1. **Build image** với multi-stage build
2. **Test locally** với Docker Compose
3. **Push image** lên registry
4. **Deploy lên staging** trước khi production
5. **Monitor** và collect metrics
6. **Scale** khi cần thiết

## Tóm Tắt

- Không sử dụng bind mount trong production
- Multi-stage build giúp tối ưu kích thước image
- Cân nhắc giữa self-managed và managed service
- Luôn implement health checks và resource limits
- Sử dụng Docker Compose hoặc Kubernetes để quản lý multi-container apps
