# Docker Data, Volumes và Networking: Quản Lý Dữ Liệu và Mạng Trong Container

Khi làm việc với containers, quản lý dữ liệu và mạng là hai khái niệm quan trọng cần nắm vững. Container mặc định là cô lập và stateless, điều này tạo ra thách thức trong việc duy trì dữ liệu và giao tiếp giữa các container.

## Bài Toán Statelessness Của Container

Mặc dù container có thể đọc và ghi dữ liệu, tất cả dữ liệu đó sẽ bị mất khi container bị dừng hoặc xóa. Đây là lý do tại sao chúng ta cần đến **volumes** và **bind mounts**.

## Bind Mounts: Kết Nối Thư Mục Host-V Container

Bind mount cho phép bạn映射 một đường dẫn cụ thể trên máy host sang đường dẫn trong container.

```bash
docker run -v /path/on/host:/path/in/container myapp
```

**Trường hợp sử dụng phổ biến:**
- Mirror source code để container cập nhật thay đổi real-time
- Cấu hình mà bạn muốn thay đổi thường xuyên
- Chủ yếu hữu ích trong quá trình **phát triển**

**Lưu ý:** Không sử dụng bind mount trong môi trường production!

## Volumes: Lưu Trữ Dữ Liệu Vĩnh Viễn

Khác với bind mount, volume không cần bạn biết chính xác đường dẫn trên host. Docker tự động quản lý storage location.

```bash
# Tạo named volume
docker volume create my-data

# Sử dụng volume khi chạy container
docker run -v my-data:/app/data myapp
```

### Named Volumes vs Anonymous Volumes

- **Named volumes**: Có tên cụ thể, dễ quản lý và tái sử dụng. Phù hợp cho dữ liệu cần persist.
- **Anonymous volumes**: Không có tên, hữu ích để bảo vệ dữ liệu bị ghi đè bởi setup steps trong container.

## Networking: Giao Tiếp Giữa Các Container

Container mặc định cô lập nhưng vẫn có thể kết nối và gửi request cho nhau cũng như ra Internet.

### Phương Pháp 1: Sử Dụng IP Address

```bash
docker inspect <container_id> | grep IPAddress
```

**Hạn chế:** IP address có thể thay đổi, gây bất tiện và không ổn định.

### Phương Pháp 2: Docker Network (Khuyến Nghị)

Tạo Docker network và thêm tất cả container cần giao tiếp vào cùng network:

```bash
# Tạo network mới
docker network create my-network

# Chạy container với network
docker run --network my-network --name api myapi
docker run --network my-network --name db mydb
```

Sau đó, bạn có thể sử dụng **container name** làm địa chỉ:

```bash
# Container api có thể kết nối đến db bằng cách sử dụng tên "db"
# Docker sẽ tự động resolve IP address
```

**Ưu điểm:** Docker tự động resolve IP addresses, giúp việc giao tiếp giữa các container trở nên dễ dàng và ổn định.

## Ví Dụ Thực Tế

```bash
# Tạo network cho ứng dụng
docker network create app-network

# Chạy PostgreSQL với named volume
docker run -d --name postgres \
  --network app-network \
  -v pgdata:/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=secret \
  postgres:15

# Chạy Node.js API kết nối với PostgreSQL
docker run -d --name api \
  --network app-network \
  -p 3000:3000 \
  -e DB_HOST=postgres \
  myapi
```

## Best Practices

1. **Sử dụng named volumes** cho dữ liệu quan trọng
2. **Tạo custom network** thay vì sử dụng default bridge
3. **Sử dụng container name** thay vì IP address
4. **Không dùng bind mount** trong production
5. **Luôn backup volumes** định kỳ

## Tóm Tắt

- Container mặc định là stateless, dữ liệu bị mất khi container dừng
- Bind mount phù hợp cho development, không nên dùng trong production
- Named volumes giúp dữ liệu tồn tại vĩnh viễn
- Docker network giúp container giao tiếp bằng tên thay vì IP
- Luôn tạo custom network cho multi-container applications
