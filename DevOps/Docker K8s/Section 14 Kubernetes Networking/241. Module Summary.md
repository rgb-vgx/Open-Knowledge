# Tổng hợp: Kubernetes Networking Module

Chúc mừng! Bạn đã hoàn thành Module Networking. Hãy cùng ôn lại những kiến thức quan trọng.

## Tóm tắt các khái niệm chính

### 1. Pod-internal Communication

```
┌──────────────────────┐
│        Pod           │
│  ┌────────┐ ┌──────┐ │
│  │Container│ │Auth  │ │
│  │  A     │◀▶│API   │ │
│  └────────┘ └──────┘ │
│     localhost         │
└──────────────────────┘
```

- Container trong cùng Pod giao tiếp qua **localhost**
- Chia sẻ Network Namespace
- Cách đơn giản nhất

### 2. Kubernetes Services

| Loại | IP | Port | Use case |
|------|-----|------|----------|
| **ClusterIP** | Internal | Bất kỳ | Internal microservices |
| **NodePort** | Node IP | 30000-32767 | Development |
| **LoadBalancer** | External IP | Bất kỳ | Production |

### 3. Pod-to-Pod Communication

Ba cách tiếp cận:

| Cách | Mô tả | Khuyến nghị |
|------|-------|------------|
| IP Address | Hardcode IP service | Test nhanh |
| Env Variables | `AUTH_SERVICE_HOST` | Khi cần linh hoạt |
| **DNS Name** ✅ | `auth-service` | **Production** |

### 4. CoreDNS

```
<service-name>.<namespace>.svc.cluster.local
```

- Tự động tạo DNS cho mỗi Service
- CoreDNS là DNS server mặc định của Kubernetes
- Pods truy cập Services qua tên DNS

### 5. Reverse Proxy Pattern

```
Browser → Nginx (Frontend) → Backend Service
```

- Frontend không cần hardcode backend URL
- Nginx config xử lý routing
- Sử dụng DNS name cho backend

## Best Practices

1. **Sử dụng DNS name** thay vì IP address
2. **ClusterIP** cho internal services (Auth, Database)
3. **LoadBalancer** cho external services (Frontend, API)
4. **Multi-Container Pod** chỉ khi tightly coupled
5. **Environment Variables** cho linh hoạt
6. **Reverse Proxy** cho Frontend-Backend connection

## Bước tiếp theo

- Tìm hiểu **Ingress Controller** (Gateway API)
- Network Policies cho bảo mật
- Service Mesh (Istio, Linkerd)
