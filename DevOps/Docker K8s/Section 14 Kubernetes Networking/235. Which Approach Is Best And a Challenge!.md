# Chọn cách tiếp cận tốt nhất: So sánh và Thử thách

Sau khi tìm hiểu tất cả các phương pháp, hãy tổng kết và thực hành.

## Khi nào Multi-Container Pod?

Chỉ sử dụng khi Container **tightly coupled**:

```
✅ Sidecar pattern (logging container)
✅ Ambassador pattern (proxy container)
✅ Containers chia sẻ storage紧密
❌ Container độc lập, riêng biệt
❌ Container có thể scale riêng
```

## Tổng kết 3 cách Pod-to-Pod Communication

### 1. IP Address thủ công
```javascript
const AUTH_ADDRESS = '10.96.100.200';
```
- Phù hợp: Test nhanh, development
- Hạn chế: Hardcode, không maintain được

### 2. Environment Variables tự động
```javascript
const authHost = process.env.AUTH_SERVICE_HOST;
```
- Phù hợp: Khi cần linh hoạt
- Hạn chế: Tên phức tạp, order dependency

### 3. DNS Name (Khuyến nghị)
```javascript
const AUTH_ADDRESS = 'auth-service';
```
- **Phù hợp nhất cho mọi trường hợp**
- Dễ nhớ, ổn định, tự động


## Thử thách cho bạn!

Triển khai Tasks API trên Kubernetes:

1. **Tạo Deployment** cho Tasks API
2. **Tạo Service** (LoadBalancer) cho Tasks API
3. **Kết nối** Tasks API với Auth API qua DNS
4. **Test** với Postman

### Yêu cầu

```yaml
# tasks-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: tasks-deployment
# ... bạn điền tiếp
```

### Tips

- Auth API DNS: `auth-service`
- Tasks API listens on port 8000
- Cần environment variable `AUTH_ADDRESS`

Thử tự làm trước, solution ở bài tiếp theo!
