# Thấy Compaction Bằng Mắt Thường: Tạo Topic, Produce Lương, Đọc Lại Chỉ Còn Latest Value

Lý thuyết compaction nghe hay, nhưng chỉ khi tự tay produce 6 dòng lương rồi đọc lại từ đầu thấy còn 3-4 dòng mới tin. Bài này làm đúng demo trong transcript: tạo topic `employee-salary` với segment siêu nhỏ để compaction trigger trong vài giây.

---

## 1. Cơ Chế Demo: Ép Compaction Chạy Nhanh Bằng Segment Nhỏ

Production không có nút "compact ngay". Cách duy nhất để demo nhanh là tune 2 thứ:

- `segment.ms` rất nhỏ (ví dụ **5000ms**) → segment đóng liên tục, đủ điều kiện cho cleaner.
- `min.cleanable.dirty.ratio` rất thấp (ví dụ **0.001**) → chỉ cần 0.1% log bẩn là cleaner chạy.

> Cảnh báo Windows trong transcript: bug cũ **KAFKA-1194** làm log compaction crash trên Windows non-WSL2. Dùng **WSL2 / Linux / macOS** hoặc Conduktor trên WSL2 để làm bài này.

## 2. Config Và Lệnh Demo: Giữ Nguyên Kịch Bản Transcript

**Bước 1 — tạo topic compact:**

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --create --topic employee-salary \
  --partitions 1 --replication-factor 1 \
  --config cleanup.policy=compact \
  --config min.cleanable.dirty.ratio=0.001 \
  --config segment.ms=5000
```

Verify:

```bash
kafka-topics.sh --bootstrap-server localhost:9092 \
  --describe --topic employee-salary
# Configs: cleanup.policy=compact, min.cleanable.dirty.ratio=0.001, segment.ms=5000
```

**Bước 2 — mở consumer đọc cả key:**

```bash
kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic employee-salary --from-beginning \
  --property print.key=true --property key.separator=","
```

**Bước 3 — mở producer có key (key.separator là dấu phẩy):**

```bash
kafka-console-producer.sh --bootstrap-server localhost:9092 \
  --topic employee-salary \
  --property parse.key=true --property key.separator=","
```

**Bước 4 — gõ đúng kịch bản (key,value):**

```
Patrick,10000
Lucy,20000
Bob,20000
Patrick,25000
Lucy,30000
Patrick,30000
```

Lúc này consumer đang chạy sẽ thấy **đủ cả 6 dòng theo đúng thứ tự** — compaction chưa ảnh hưởng tới tail read.

**Bước 5 — chờ + mồi thêm để trigger compaction:**

Đợi vài chục giây cho segment đóng và cleaner chạy. Gõ thêm một dòng (như transcript gõ `Stephane,0`) để chắc chắn có segment mới. Sau đó **tắt consumer cũ, mở consumer mới với group mới đọc từ đầu:**

```bash
kafka-console-consumer.sh --bootstrap-server localhost:9092 \
  --topic employee-salary --from-beginning \
  --property print.key=true --property key.separator="," \
  --group compaction-demo-2
```

Kết quả mong đợi — chỉ còn latest value mỗi key:

```
Bob,20000
Lucy,30000
Patrick,30000
Stephane,0
```

Ba dòng cũ (Patrick 10000, Patrick 25000, Lucy 20000) đã bốc hơi. Muốn chắc chắn, xem log broker sẽ thấy dòng `Log cleaner` vừa gộp segments.

## 3. Trade-offs Và Cảnh Báo Production

| Setting demo | Demo được gì | Vì sao production không để vậy |
|---|---|---|
| `segment.ms=5000` | Compaction trong vài giây | Hàng nghìn segments nhỏ → broker ngập file handles, cleaner chạy liên tục tốn CPU |
| `min.cleanable.dirty.ratio=0.001` | Dọn ngay cả khi barely dirty | Dọn kém hiệu quả, ghi lại segments liên tục gây đeo disk |
| 1 partition, RF=1 | Dễ nhìn | Không fault-tolerance, không parallelism |

## Pitfalls / Best Practice

- **Pitfall: đọc bằng cùng consumer group cũ thì không thấy gì mới.** Phải `--from-beginning` với group mới (hoặc reset offset) mới thấy log sau compaction.
- **Pitfall: sốt ruột kết luận "compaction không chạy".** Nó là tiến trình nền, cần đợi segment đóng + `log.cleaner.backoff.ms` (15s). Đừng spam restart broker giữa chừng.
- **Best practice:** setting demo **chỉ ở môi trường học**. Production về lại `segment.ms` 7 ngày (hoặc 1 ngày nếu cần) và `dirty.ratio=0.5`, tune dần theo monitoring.

## Kết Luận

Tóm lại: **tail read thấy đủ lịch sử, head re-read chỉ còn latest key — đó là bằng chứng compaction đã chạy; muốn demo nhanh thì bóp `segment.ms` và `dirty.ratio`, xong phải trả về default.**

Compaction giữ latest value để tăng availability cho state. Nhưng còn trường hợp toàn bộ ISR chết thì availability đánh đổi bằng gì? Bài tiếp theo: **unclean leader election — setting nguy hiểm nhất Kafka**.
