So now let's talk
about Amazon managed service for Prometheus.
This time it's a serverless, Prometheus-compatible service.
So it's not exactly Prometheus, but it's compatible with it,
for monitoring container metrics.
It will automatically scale ingestion,
storage, and query operations,
and data will be replicated across three availability zones,
which makes it highly available.
It's the same open source Prometheus data model
and the same PromQL query language,
which is a query language used by Prometheus
to filter and aggregate metrics.
So by all means, it looks and works just like Prometheus.
It works with Amazon EKS
and self-managed Kubernetes cluster,
and the metrics can be stored up to three years.
By default, it's 150 days of retention period.
So the idea is that in this managed service for Prometheus,
you're going to ingest all these metrics
from all these different services,
for example, Amazon EKS, AWS Distro for OpenTelemetry,
a normal Kubernetes cluster,
a Prometheus server, or OpenTelemetry.
And then once it's all in there,
you can usually combine it with Grafana, for example,
in the Amazon managed Grafana version,
to query these metrics
and build dashboards upon Prometheus.
Alright, that's it.
I hope you liked it,
and I will see you in the next lecture.
