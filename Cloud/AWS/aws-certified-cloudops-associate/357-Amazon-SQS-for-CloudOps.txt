So here are some concepts
you may need to know slightly for the CloudOps exam.
So the first is Message Visibility Timeout,
which is after a message is being polled by a consumer,
it becomes invisible to other consumers during this timeout,
and ,by default, is 30 seconds.
There's Dead Letter Queue.
So if your consumer fails to process
the message several times
after the maximum receive threshold,
it goes straight into the Dead Letter Queue,
which is another SQS queue.
Message Retention Period,
so SQS will automatically delete messages from the queue
after that time.
It can be set from anywhere from one minute to 14 days.
The default is four days.
And the SQS Access Policy, which is a resource-based policy,
which you can help to define who can access your SQS queue,
which is similar to an S3 bucket policy.
Here is a pattern you need to know about as well for SQS,
which is the prioritization pattern.
So say you wanted to send messages with a higher priority
and some with a lower priority,
you need to use two SQS queues for that.
You cannot only have one
because this feature is not available within SQS
in one queue.
So how does that work?
Well, we have two SQS queues
and the high priority messages are going to be sent
into the high priority SQS queue,
which is just a normal SQS queue that we've defined
as being the one that will have the high priority messages,
and the other SQS queue will have the low priority messages.
So now you have two SQS queues
and your consumers can poll from both,
but you need to add some logic in your code
so that your consumers first poll messages
from the high priority queue and so they receive them first.
And then if there are no messages
in the high priority queue,
then you poll messages from the low priority queue
and you start processing those.
And that's a good way to have a priority aspect within SQS.
