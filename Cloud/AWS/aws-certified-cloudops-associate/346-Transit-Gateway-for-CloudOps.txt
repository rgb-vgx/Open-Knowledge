Each region will have several VPCs,
and the solution is to have one transit gateway per region.
And then once you have this, you can peer them together.
And once you do so, then you get inter-region communication
and connectivity between the VPCs of different regions.
This follows AWS best practices.
We can also reference security groups,
thanks to transit gateway.
What do I mean?

which contains a security group, which is database instance,
and you want to allow a web server from another VPC
with its own security group.

but they're not listen VPC, so you can't reference it
unless you are using a transit gateway.
So again, you use transit gateway-peering,
and then you can reference the security groups
