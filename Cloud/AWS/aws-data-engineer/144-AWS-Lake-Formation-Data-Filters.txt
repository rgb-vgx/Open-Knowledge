Instructor: Let's discuss data filters in lake formation,
which is another way of including security restrictions.
We can do column, row, or cell level security
using data filters when you're setting up lake formation.
In the console, this is what it looks like.
Over on the right here, you'll see
a little Create data filter screen here.
You can give that data filter a name, tell it what database
and table you're applying this filter to,
and then the key of this is down
where it says Column level access and Row filter expression.
So by choosing different things there,
you can achieve column, row, or even cell level security.
So these are applied when we're granting
the select permissions on a table,
that's when we get this option.
So let's say I want to have row level security,
I would do that by selecting Access to all columns
under Column level, but then implementing
a row filter expression to have
a row level security implemented on this data filter.
If I wanted column level security,
I would leave the row filter blank and have all rows.
But then I can say include columns
or exclude columns to provide column level security
under the Column level access.
And for cell level security, I can do both.
I could say include specific columns
or exclude specific columns,
and also apply a row filter expression as well.
If I'm selecting both columns and rows
that are allowed in my filter,
then I now have cell level security.
You can do this via the console as we're seeing here
to the right, or you can also do it
through the API through the CLI.
That's CreateDataCellsFilter
is the name of the API call for that.
