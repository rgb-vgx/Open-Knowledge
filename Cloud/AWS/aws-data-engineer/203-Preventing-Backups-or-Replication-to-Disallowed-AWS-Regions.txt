Instructor: Another compliance concern
you might have is keeping data out of geographical areas
where you're not allowed to have it.
So oftentimes, you'll have restrictions
on where data can live.
Different countries have different laws about
how PII is stored, and privacy laws, and stuff like that.
So sometimes you have to be careful about
what jurisdiction you're actually storing your data in.
And it's all too easy to mistakenly,
or accidentally send data someplace where it shouldn't be.
A very common cause of this is backups or replication
where maybe you're being very well intentioned
and backing your data up to a different region
for better resilience from failures in one region.
But if you're not careful, you might end up doing
that backup or that replication someplace
where that data is not allowed to reside.
So there are some ways of enforcing that.
There's this system called AWS Organizations,
which isn't something we've really talked about,
but it's out there
and it has something called Service Control Policies.
That's one way to enforce these sorts
of geographic restrictions.
The more common way would be to just use
IAM policies and S3 bucket policies
to make sure you're locking everything down
to the regions data is allowed to be in.
So you just have to give more thought to your IAM policies
and think about not only what operations am I permitting,
but where am I permitting these things to happen?
So you need to take care, especially when you're configuring
the permissions for backups and replication for RDS,
Aurora, Redshift, or any other database, or data store.
And also you wanna set up your monitors
and alarming with CloudTrail and CloudWatch.
So if something does mistakenly go to the wrong country,
at least you'll know about it quickly
and you can take care of the situation.
Just for a real example here, here's one IAM policy
and its purpose in life is to make sure
that we're not gonna do any RDS backups outside
of the us-east-1 and us-west-1 regions.
So if you kind of study this statement over here,
we're saying that we're going to only allow
CreateDBSnapshot and CopyDBSnapshot
to the us-west-1 and us-east-1 region.
So that's restricting those backups
to just those two regions, however, we're gonna allow
everything else to happen anywhere.
So the second part of this policy says
we're gonna allow any other action
that's not CreateDBSnapshot or CopyDBSnapshot anywhere.
So this is just making sure that we're not replicating data
someplace outside of those regions,
but we can still access that data from any place.
