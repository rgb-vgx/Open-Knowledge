Okay, so welcome to a long
and detailed lecture on VPC Endpoints.
So VPC Endpoints, as you know, allow you to connect
to AWS services using the private network
instead of going through the public internet.
This scale horizontally and are redundant.
So that means that as soon as you're using VPC Endpoints,
you don't need to have an internet gateway or a NAT instance
or NAT Gateway to access AWS services.
Everything goes through the private, internal network.
So how does that work?
We have our VPC and a private subnet.
In our private subnet, we have an EC2 instance.
And say, we're trying to access Amazon S3 or DynamoDB.
In which case, we can set up a VPC endpoint gateway.
So Gateway is only for S3 and DynamoDB.
And if we do so, then our EC2 instance
will be able to talk to S3
and it will be able to talk to DynamoDB.
And for all services, including S3 and DynamoDB,
you can create a VPC endpoint interface.
So for example, say we're trying to access CloudWatch,
then to access CloudWatch privately,
then you need to create a VPC endpoint interface,
which is an ENI.
So it has to live within one of your subnets.
And then your EC2 instance would connect
through that ENI to the CloudWatch service.
In case of issues with VPC endpoints,
you need to check the DNS setting for the resolution
in your VPC, or you check your route tables to make sure
that there is indeed a route from your EC2 instance
to the endpoints.
And it is now possible
to access your VPC endpoints across different regions.
Okay, so now, let's do a deep dive
onto the VPC endpoint gateway.
This only works for Amazon S3 and DynamoDB,
and you must create one gateway per VPC.
You must update route table entries to make it work.
And so that means that it will be applied
to all the instances that are inheriting that route table.
The gateway is defined at the VPC level.
And so for example, if we're getting a VPC endpoint gateway
into Amazon S3 and we have an EC2 instance

Now, as I said, the VPC endpoint gateway

direct connect, a transit gateway or VPC peering,
this cannot go through your VPC endpoint gateway.
Your VPC endpoint gateway is really only here

You cannot share VPC endpoint gateways

And then we have VPC Endpoint Interface,
and they're a little bit different from Endpoint Gateway
because here we provision an ENI,
so an elastic network interface,
and this ENI will have some private host name.
And the idea is that to do security,

So how do we get access to this ENI

For this, we need to use a private DNS.

will resolve not to the public IP of that service,

And for this to work, we need
to make sure two settings are enabled in our VPC,
