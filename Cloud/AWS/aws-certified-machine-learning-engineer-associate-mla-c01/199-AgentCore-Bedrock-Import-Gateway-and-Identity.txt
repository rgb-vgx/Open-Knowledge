So let's hit on a few more capabilities of Agent Core and one of them is the ability to import
Bedrock agents into Agent Core. Why would you want to do that? I mean Bedrock has its own
built-in mechanisms for deploying its agents at scale. Well maybe you want to take an existing
Bedrock agent and build on top of that and do something a little bit more extensive with it,
right? So in that case maybe it makes sense to import a Bedrock agent and then build on top of
that and deploy this more complicated system through Agent Core. You can do that. It's really
easy actually. All you have to do is say agent core import dash agent and it will take the agent
you specify in Bedrock and turn it into strands code. So it will turn it into a code base using
strands SDK or optionally lang chain and lang graph and it just throws it in whatever output
directory you specify. And from there you can develop on top of it. You can test it. You can
deploy it. It's just like any other Agent Core agent at that point. So it is possible to take
a Bedrock agent import that into Agent Core and extend it from there. Another feature in Agent
Core is the Agent Core gateway. What's that all about? So this is addressing the problem of using
external tools at scale. So odds are whatever agent framework you're using has the ability to
call tools on its own including external tools through MCP. Well gateway does that too but in a
more well scalable manner I suppose. So what it does under the hood is it makes everything look
like an MCP tool internally. So external APIs, lambda functions, other services, they're just
going to look like another MCP tool to the Agent Core gateway and it's going to keep track of all
those gateway endpoints that your application can then refer to from within your Agent Core code
that you're wrapping up. Those targets can consist of anything that exposes open API interfaces or
Smithy models which is some AWS thing or lambda functions of course as well. So again you know
Agent Core is all about better AWS management and integration. And once you have that set up your
agents can then access them through gateway endpoints within Agent Core and that also has
the convenient property of managing your authorization and credentials for you as part of
the deal. So you have this centralized place where all of your security and all of your credentials
for accessing these external services are kept safely and in the cloud for you. Also it offers
a semantic tool selection capability as well so it doesn't just handle connectivity it lets you
choose the right tool for the job as well that's built into the gateway too. Then we have Agent
Core identity which isn't quite what it sounds like. So this is different from OAuth identity for
actually logging into your agent itself and that's a whole different can of worms. So obviously you do
want to think about how do you authenticate for your agentic AI application probably going to be
using Cognito and Agent Core's integration with Cognito for that. So that's a different problem.
What we're talking about here is your identity of the application itself when it's connecting
to external services and tools. So that too is an identity like there's user identity but your agent
also has an identity. It's kind of an interesting trend that AI agents are sort of being treated
like people these days. So it's about your agent's identity or identities and how they access external
tools. And Agent Core identity lets you do this securely both to external tools and to AWS services
of course. It provides a central repository for all of your agent identities for talking to these
external services kind of like a Cognito user pool but it's not for people it's for agents.
It also offers secure credential storage so you can keep those credentials for talking to those
external tools safely. And it offers OAuth 2.0 support with built-in support for tools from
Google, GitHub, Slack, Salesforce, and Atlassian all built into Agent Core identity. And there's
a lot more depth to this it's actually a pretty complicated topic. Don't think you're going to
