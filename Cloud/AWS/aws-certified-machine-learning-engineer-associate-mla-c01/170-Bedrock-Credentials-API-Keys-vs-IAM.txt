So there's a couple of ways to use Amazon Bedrock through credentials.
You can have a Bedrock API key or you can use IAM and knowing when to use one over the
other is something you got to know.
So like every other AWS service, you can use IAM to control your credentials and access to it.
And this is the preferred path for anything you're doing in production.
So if you are using Bedrock in a production application, in a production AWS workload,
this is going to give you stronger security.
It's going to inherit everything that IAM gives you through AWS authorization, and it's
built around the principle of least privilege, which is the best practice for authentication in general.
However, there is also API keys for Amazon Bedrock, and this is basically a convenience for developers.
So if you've worked with OpenAI or Anthropic, you know it's just a matter of throwing an
API key into your environment variables and you're good to go.
So if you're just experimenting, Bedrock does have the same feature.
You can just throw a Bedrock API key into your environment variables and be good.
So it's a simple bearer token style to call Bedrock API.
So if you just want to be, for example, calling Anthropic foundation models through Bedrock,
you could use a Bedrock API key to do that from your developer workstation.
Now there are two kinds of Bedrock API keys.
There are short term keys, and these just inherit the permissions of whatever IAM principle generated it.
And these are set to expire.
At the most, they can last 12 hours.
So this can be useful for short term authentication tasks.
You can also have a long term key that sticks around pretty much indefinitely, and you should
only be using these for exploration or development.
Do not use this in production.
And by all means, be careful never to check those in, right?
So never hard code a credential in your source code.
Never check them into Git just like you would with any API key.
In the short term, that limits the blast radius a little bit because they expire after a while.
Long term keys are more dangerous and you need to take care of them just like you would
with your OpenAI or your Anthropic API keys or whatever else it might be.
