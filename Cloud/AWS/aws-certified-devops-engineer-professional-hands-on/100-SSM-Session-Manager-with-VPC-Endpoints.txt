So here is a quick lecture
to show you how you can access your EC2 instances
that are in private subnets
within the systems manager service.
So for example, say you wanted to connect
to your EC2 instances using Session Manager,
but they don't have internet access.
So the way to do it is to use VPC endpoints.
So the first VPC endpoint that's required
is for the SSM service itself
and we allow inbound 443 port from the security group.
The second interface endpoint that is necessary
is for the SSM session manager service.
So this is a different one
and this will allow the EC2 instance
to privately connect to the session manager service.
Again, we allow inbound 443,
and then on our EC2 instance
we must at least allow outbound 443 to these services.
In case we're using KMS encryption,
we must also create a VPC interface endpoint for KMS.
And if we're using CloudWatch logs
to put all the logs into CloudWatch
from the session on Session manager,
we must also create a VPC endpoint for that service.
Finally, if the logs are sent into Amazon S3,
then we can use a VPC Gateway endpoint for Amazon S3.
And if you're using a VPC endpoint gateway
you must update your route tables
in your VPC to make this work.
So, okay, as bottom line,
what I want you to remember is that
if you wanted to privately use the SSM service,
you must create the appropriate VPC endpoints
to allow your EC2 instance
to access your service privately.
Okay, that's it for this lecture.
I hope you liked it,
and I will see you in the next lecture.
