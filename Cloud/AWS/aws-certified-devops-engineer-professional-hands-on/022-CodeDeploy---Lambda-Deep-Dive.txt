So now let's do a deep dive
into the Lambda deployments for CodeDeploy.
So the idea is that you create a new Lambda version
and then you want to deploy it onto and alias.
So for this, right now,
the alias is pointing to version one,
but we wanted to point to version two.
So we're going to specify the new version information
in an appspec.yml file.
And then this file is going to be placed in an S3 bucket.
Then we going to invoke the CodeDeploy service
with this appspec.ylm file.
And then CodeDeploy
is automatically going to update the Lambda alias
to reference to the new version, version two.
And then automatically
traffic is going to be shifted from version one
to version two
and everything will be updated.
So as you can see in this example
the CodeDeploy agent is not required
we just need to create the new version ahead of time
and create this appspec.yml file.
Now, if you look at the content of it,
it is actually extremely simple.
We just specify the name
of the Lambda function to deploy,
which is required,
the name of the alias of the Lambda function,
as well as the current version
and the target version.
And then CodeDeploy will do its thing.
So when we deploy to Lambda in an automated fashion
we can use again, code pipeline.
So we push code into code commit.
CodeBuild is going to build the code,
deploy a new Lambda version
and then create this appspec.yml file we have just seen.
And then CodeDeploy is going to take
this appspec.yml file as an input artifact
and use it to shift traffic
onto the areas for your Lambda function
between the current version
and the target version.
So we have control
into how fast the traffic shifting happens for your alias.
So we have the Canary, Linear
or All At Once type of deployments.
So Linear we've seen.
So we can do, for example,
Lambda Linear 10% every three minutes.
So it goes from 10% to 20%
and so on every three minutes.
Or we can do Canary, for example,
10% for 10 minutes
and then shift all the traffic to V2,
or Lambda All At Once
to shift all traffic at once.
So we also have deployment hooks for Lambda
but they're very simple.
So the hooks are run as Lambda functions.
And we only have three hooks.
So we have three steps.
So we have before allowed traffic, allowed traffic,
and after allowed traffic.
And it turns out that before allowed traffic
and after allowed traffic
are the only place where you can run hooks
and they are Lambda function.
So for example, if we are using
before allow traffic,
we can invoke a Lambda function
named Validate Before Allow Traffic,
to make sure that we have
some health checks in place.
Or after allowed traffic,
to make sure that after deploying the new Lambda version
everything is working as expected.
And that's it.
So now you know a lot more about Lambda and CodeDeploy.
