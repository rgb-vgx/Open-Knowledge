So, let's have a look
at how we can perform logging for our ECS tasks
and send these logs into CloudWatch Logs.
So, when you have a container
and it generates logs on the outputs,
then this application log
can be directly sent to CloudWatch Logs.
For this, when we start our ECS task,
we need to turn on the awslogs log driver,
and this is done by sending the logConfiguration parameter
in your task definition.
So if we take this example,
we have a Fargate task from a Fargate task definition
and for the log configuration,
we have specified awslogs.
We've also specified the log group, the region,
and the stream prefix.
And when this is done,
well, the logs from the container
are going to be sent and streamed directly
into CloudWatch Logs.
Now, if you're using the Fargate launch type,
you need to make sure that the Fargate task execution role
has the required permissions, of course,
to deal with CloudWatch Logs.
And on top of it,
we have compatibility for awslogs, which is CloudWatch,
but also Splunk or AWS FireLens
if we want to have other log drivers.
If we use the EC2 launch type,
then we can use this kind of logging facility
to prevent the logs from taking up disk space
on our container instances.
And so, we can use a combination
of the CloudWatch Unified Agent
and the ECS Container Agent.
And when we do enable the awslog driver
for the ECS Container Agent,
then you need to set up an ecs.config file
and you need to enable logging,
thanks to the ECS_AVAILABLE_LOGGING_DRIVERS setting.
And then of course,
your container on your EC2 instances
must have the appropriate permissions
to send the logs into CloudWatch Logs.
Another option is to use something
called the sidecar container pattern.
So, the idea is that you have a second container
next to your main container
that is responsible for going onto your file system
and finding the logs
and sending these logs into a log storage.
So, the difference with this
is that your container's part of your ECS task
do not create logs as an output to the task itself,
but may create log files, many log files,
on the file system.
In that case, you would start a sidecar container
and the role of it would be to pick up these files
from the file system
and send them into CloudWatch Logs.
So, different use cases for different patterns.
And that's it.
I hope you liked it, and I will see you in the next lecture.
