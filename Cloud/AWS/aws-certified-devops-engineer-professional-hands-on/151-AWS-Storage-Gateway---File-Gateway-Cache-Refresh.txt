So let's do a deep dive
onto the File Gateway.
So the File Gateway, because it's backed by Amazon S3,
has a list of files that it can expose to the users.
And if your users write a file
directly into the File Gateway,
that file will be synced with your S3 bucket
and your File Gateway knows about this file.
But if a user uploads a file directly into an S3 bucket,
then the File Gateway
does not necessarily know about it right away.
And so you may have stale data on your File Gateway.
And so therefore, there is an API
called the RefreshCache API
which is going to refresh the list of file
that your File Gateway knows about.
So we can either do this on demand,
such as using the RefreshCache API,
or doing it periodically thanks to a Lambda function,
or even trigger it automatically from the S3 bucket
through a Lambda function, but that may be costly
if you have many files written to your S3 bucket.
The second method
is to use the Automated Cache Refresh feature
which has the File Gateway automatically stay up to date
with the S3 buckets.
So this will be automatic
and this will be done periodically.
And so this ensure that the users do not have stale data
on their file shares
and so you don't need to automatically or manually
invoke the RefreshCache API.
You still may want to use that API
if you want the cache refresh to happen right away
so that you know that a file
you've just uploaded into your Amazon S3 bucket
is available on your File Gateway.
So hopefully that makes sense.
I hope you liked it and I will see you in the next lecture.
